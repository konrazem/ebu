# 2. The decision object: local action vectors

## 2.1 Vector, not edge

For source `i` with permitted out-edges `out(i) = (e_1,…,e_m)`, the decision
object is the **vector of simultaneously requested transfers**

```
q_i = (q_{e_1}, …, q_{e_m}) ,     q_e ≥ 0 ,
```

every component a **finite source-side quantity for the current tick** (same
units as a stock; `world.QUANTITY_SEMANTICS`). The rest vector is `q_i = 0`.

## 2.2 Opportunity generation (N-1) — field- and identity-independent

Generated from **external demand and the common physical constraints only**,
reusing the already-settled Q-1 and Q-3 resolutions verbatim:

```
d_e(t) = 0   ⇒   c_e(t) = 0                                   (Q-1)
d_e(t) > 0   ⇒   c_e(t) = min( d_e(t) , [K_j − x_j]_+ / η_e )  (Q-1, Q-3)
```

**No positive automatic flux is required to create a candidate.** This is the
single substantive departure from `o14_v30.candidate_menu`, whose entries are
fractions of `M_sel·[f_e − θ_e]_+` and therefore vanish identically when
`μ ≡ 0`. Here `c_e` depends on `d_e`, `K_j`, `x_j`, `η_e` and nothing else —
no `μ`, no `f_e`, no `M_e`, no `θ_e`, no controller identity, no arm label.

**No menu fractions, no numerical threshold and no new scientific parameter is
introduced.** The candidate set is the *continuous* region of §2.4; any finite
menu or numerical solver is a separately declared implementation choice (§4.7).

## 2.3 Exact group field contribution (N-3)

With `A(q) = {i} ∪ { j : e=(i,j), q_e > 0 }` the **complete** affected factor
set and `z` the declared common baseline (Definition 6.2; `z = x` at `u = 0`):

```
F_G(q)  =  V_A(z) − V_A( T_G(z, q) )

T_G(z,q):   z_i  ↦  z_i − Σ_e q_e            (source loses the full sent amount)
            z_j  ↦  z_j + η_e q_e            (destination receives η_e q_e)
```

**Draft derivation d-1 (exact decomposition — where additivity holds and where it
fails).** By separability,

```
F_G(q) = [ v_i(z_i) − v_i( z_i − Σ_e q_e ) ]        ← ONE aggregate source term
         + Σ_e [ v_j(z_j) − v_j( z_j + η_e q_e ) ]  ← additive over destinations
```

The destination terms **are** exactly additive: distinct factors, disjoint under
the single-source-destination restriction. The source term is **one evaluation
at the aggregate** `Σ_e q_e` — not a sum of per-edge source terms. ∎

**Draft derivation d-2 (per-edge quotes are not additive, and summing them
overestimates).** For two out-edges of the same source with quantities `a,b ≥ 0`,
write `φ = v_i`. Sum of independent same-baseline per-edge source terms minus
the joint source term equals the mixed second difference

```
Δ² = φ(z) − φ(z−a) − φ(z−b) + φ(z−a−b) .
```

`φ` convex ⇒ `φ'` nondecreasing ⇒ `ψ(t) = φ(z−t) − φ(z−t−b)` has
`ψ'(t) = φ'(z−t−b) − φ'(z−t) ≤ 0`, so `ψ(0) ≥ ψ(a)`, i.e. `Δ² ≥ 0`. Hence

```
F_G(q)  ≤  Σ_e  ( per-edge same-baseline quote )        with equality iff Δ² = 0.
```

Summing independent same-baseline edge quotes therefore **overestimates** the
true joint field value — it flatters the action. `F_G` is evaluated directly
from the vector; per-edge summation is **not** used. ∎

**The error is decision-changing, not merely numerical.**
`ILLUSTRATIVE_FIXTURE_ONLY`, exhibited because d-2 would otherwise look
vacuous: take `α=β=χ=1`, `L=4`, `U=16`, `R=2`, `η=1`, source `z_i = 6`, two
destinations at `z_{j1} = 8`, `z_{j2} = 9`, and `q = (2,2)`.

| | value |
|---|---|
| naive sum of per-edge same-baseline quotes | **0** |
| true `F_G(q)` (d-1) | **−4** |
| gap = mixed second difference of `v_i` | **+4** |

Both destinations stay in band, and each edge *taken alone* leaves the source at
`4 = L_i`, so every per-edge quote is exactly `0`. Jointly the source is driven
to `2`, two units below `L_i`, and the true value is `−4`. **The naive figure
sits exactly on the accept boundary of any "accept iff value ≥ 0" rule while the
true value is strictly negative** — so per-edge summation would not merely
mis-price this vector, it would *accept* a vector that the exact functional
rejects. This is why `F_G` is computed from the vector and never assembled from
edge quotes.

## 2.4 Feasible local vector set

```
Q_i  =  { q ∈ ℝ^m_{≥0}  :  q_e ≤ c_e  ∀e ,   Σ_e q_e ≤ B_i }
```

with `B_i` the permitted aggregate export **quantity** of §3. `Q_i` is a
non-empty compact convex polytope containing `0`.

## 2.5 Field contribution vs total EBU — kept distinct

```
F_G(q)          exact field contribution        (this §)
ΔE_G(q) = F_G(q) − C_G(q)     total EBU after declared residual process burden
```

Under the declared candidate assumption `C_a ≡ 0` (design §11; §7.2 here),
`C_G ≡ 0` and `ΔE_G = F_G`. **They are not the same object and are not
conflated**: every decision law below is stated on `ΔE_G`, which reduces to
`F_G` only under that assumption.

# 3. Proposed common internal-transfer permission rule (N-2)

## 3.1 Layer, and universality

This rule belongs to the **prospective world / provider layer**, not to any
controller. **If adopted it applies identically to every arm** — C0–C4 and any
C5 — exactly as the hard-capacity clamp does. **P1C is unchanged**; this is a
*new prospective rule alongside it*, not an amendment, and adopting it does not
adopt a new budget law for P1C's own domain.

## 3.2 Exact symbolic law

Declared per node: an **internal-transfer provider floor** `P_i`.

```
aggregate export budget (QUANTITY, this tick)
    B_i  =  [ x_i − P_i ]_+                                        (3.1)

per-edge common physical cap (QUANTITY, source-side)
    c_e  =  min( d_e , [K_j − x_j]_+ / η_e )   and 0 where d_e = 0  (3.2)

admissible vectors
    Q_i  =  { q ≥ 0 : q_e ≤ c_e , Σ_e q_e ≤ B_i }                  (3.3)

joint hard-feasibility (re-checked on the accepted increment, all nodes)
    0  ≤  x_j + Σ_{e→j} η_e q_e^acc − Σ_{e: j→k} q_e^acc  ≤  K_j   (3.4)
```

If a rate form is ever wanted, `B_i/Δt`; the rule is stated in quantities and
the conversion is `world.tick_quantity_from_rate`.

**Units.** `P_i`, `x_i`, `B_i`, `c_e`, `d_e`, `q_e` are all **stock-unit
quantities**. `P_i` is *not* a rate.

## 3.3 What `P_i` means, and what it is not

**Physical meaning (proposed), grounded in a physical assumption rather than in
a wish to distinguish controllers.** `P_i` is the candidate world's **declared
non-mobilisable stock quantity** at node `i` — equivalently its **provider
floor**: resource counted in `x_i` that the declared transport mechanism cannot
move out.

**Units: `P_i` is a STOCK QUANTITY**, the same units as `x_i` and `B_i`. It is
**not** a dimensionless fraction. If a world ever wishes to declare a
*fraction*, it must declare a separate `φ_i ∈ [0,1]` together with an explicit
conversion to stock units (for example `P_i = φ_i·K_i`); no such fraction is
declared here and none is implied.

**Interpretations are provisional, not established facts.** A dead volume below
an outlet, a bound or adsorbed fraction, a minimum operating head — these are
*possible readings* a concrete declared world might intend. This study's world
is an **abstract conserved scalar** with no committed transport physics, so none
of these is asserted of it. What the packet does assert is the **role**: on any
such reading `P_i` is a property of the plant and its transport mechanism, fixed
when the world is declared, existing independently of any controller or
viability model.

Two consequences of that grounding. First, `P_i` constrains **export only** — it
does not prevent a node from *receiving*, nor does it assert anything about that
node's health. Second, `P_i = 0` is a perfectly admissible declaration, meaning
the transport mechanism can mobilise the whole stock; it is not a degenerate
case to be avoided.

**It is explicitly NOT any of these, and is not silently identified with them:**

| | |
|---|---|
| `R_eff` | P1C's *effective regenerative reserve* for a **provider/extraction** setting, gating the State-P regenerative branch. `P_i` is for **internal relocation** in a closed world and gates nothing of P1C's |
| `R_i` | the **homeostatic reserve coordinate** in `v_i`'s `χ[R−x]_+²` branch — a *viability* declaration, read by eligible controllers (C3 stage 1, C4 through the potential). `P_i` is a *permission* declaration and is read by no controller |
| `L_i` | the **lower homeostatic band edge**, which C3 uses as its own **voluntary** source floor. `P_i` is involuntary and common |

**The relation between `P_i`, `R_i` and `L_i` is left UNDECIDED and is an
author decision** (§8, decision 2). **Numerical equality with `R_i` or `L_i` may
be proposed only as an explicit, justified policy choice** — never by default
and never because it produces a convenient comparison. A justification would
have to argue that the non-mobilisable stock quantity *happens* to coincide with
the declared homeostatic reserve or band edge in the intended plant — a claim
about the world, not about the study. **A positive floor must never be chosen
merely to create a contrast between controllers.**

It matters analytically: whether `P_i ≤ L_i` or `P_i > L_i` determines whether
C3's voluntary floor or the common provider floor binds first, and therefore
whether C3 remains a distinct comparator (§6.3). **But that consequence must not
become the reason for the choice.** Admissible declarations include `P_i = 0`,
an independent coordinate, or — with explicit argument — numerical coincidence
with `R_i` or `L_i`. **No value is selected here.**

## 3.4 Guarantee mapping

**Draft derivation d-4 (substitution instance of Theorem 4.1).** Theorem 4.1 uses
`R_i^eff` only as a tick-constant appearing in the budget and in the
conclusion. Substituting the declared constant `P_i` and taking `u ≡ 0`:

| Thm 4.1 assumption | Satisfied here by |
|---|---|
| (A1) synchronous frozen-state proposals, one update | `plan_tick` computes every proposal from one frozen state; `apply_joint` applies one joint update |
| (A2) `Δt > 0` known | declared |
| (A3) floor fixed during the tick | `P_i` is a declared world constant |
| (A4) `Q_i` is the **aggregate** out-edge export, **no hidden withdrawal** | **required of the rule**: (3.3) bounds `Σ_e q_e`, and all outflow must be inside it |
| (A5) no clipping creates stock | no clipping is applied |
| (A6) incoming `I_i ≥ 0` | `η_e ∈ (0,1]`, `q ≥ 0` |
| (A7) `x_i ≥ P_i` | holds iff the source is at or above its floor |
| (A8) feasibility `x_i + Δt·u_i ≥ P_i` | **at `u = 0` this is identical to (A7)** |
| (A9) `0 ≤ Σ_e q_e ≤ B_i` | enforced by (3.3) |

**Conclusion (derived, not asserted):** `x_i^{n+1} ≥ P_i`. ∎

**Draft corollary d-4a.** At `u ≡ 0`, (A7) and (A8) coincide, so P1C's *State I*
("locally reserve-infeasible") has **no analogue here**: a node is either at or
above its floor, or below it. The three-state classification collapses to two.

**Draft derivation d-4b (induction across ticks).** Fix the floors. Assume at
tick `n`: `x_i(n) ≥ P_i` for every node; outgoing quantities bounded by the
**frozen pre-state** budget `Σ_out q ≤ [x_i(n) − P_i]_+`; incoming quantities
`≥ 0`; `u = 0`; no hidden withdrawal. Then by the one-step bound
`x_i(n+1) ≥ P_i` at **every node simultaneously** — each node's bound uses only
its own frozen budget, and incoming only helps, so no cross-node interaction is
needed. The hypothesis is thereby re-established, and induction gives

```
x_i(n) ≥ P_i   for every node i and every tick n ≥ 0 ,
```

**provided the floors are fixed throughout the claimed horizon.** If any `P_i`
changes at some tick, the induction restarts and `x_i ≥ P_i^{new}` must be
**explicitly revalidated** at that tick; it does not follow from the earlier
bound. ∎

**What d-4/d-4b do and do not support — corrected, without importing unrelated
blockers.**

| | |
|---|---|
| **supported** | the simultaneous multi-tick floor bound above, under its stated hypotheses. It needs **no** proportional allocation (under pipeline (i), `σ = 1`), so review **open problem (iv)** — joint invariance *under proportional allocation* plus a descent inequality — is **not** a blocker for it. The previous revision cited it as one; that citation is withdrawn |
| **not supported** | any statement about **delivered service**, about **recovery** of a node below its floor, about **potential descent** (`V` need not decrease), or about **general long-run homeostasis**. A floor bound is a lower bound on stock, nothing more |
| **not settled by §6.4** | §6.4's `q^long = 0` concerns **extraction** from a non-regenerating stock — resource leaving the accounted system. In a **closed conserved** world a node that exports can later receive, so §6.4 does **not** establish that sustained **internal circulation** is impossible. Whether it is possible here is a separate open question |
| **topology note** | the in-degree ≤ 1 restriction does **not** forbid directed cycles (a ring has in-degree 1 at every node), so circulation is not structurally excluded by it either. Each component contains at most one cycle |

**Destination constraints.** The rule adds **no homeostatic destination
constraint**. It adds only hard-capacity feasibility, already common (3.2), plus
the joint successor condition (3.4). Under the single-source-destination
restriction each destination's (3.4) row reduces to its own single incoming edge
unless that node also sends, which §5.4 treats.

## 3.5 A source beginning below its floor

If `x_i < P_i` then `B_i = [x_i − P_i]_+ = 0` and **no export is permitted**.

**This is containment, not restoration, and must not be described as
restoration.** Zero export **prevents further outgoing depletion** — that much
it does achieve — but it does not restore the floor. With `u = 0` and no
regeneration, a node below its floor and receiving nothing stays exactly where
it is. This is the direct analogue of P1C's own
statement for State R/I — *"zero export cannot prevent the next reserve
breach"* (`_source_budget`) — and it carries the same honesty requirement.

**Consequence, stated because it is a real design property:** a below-floor node
can only be restored by an **incoming** transfer, which requires (a) some other
node to be above its own floor, (b) a demand-generated opportunity on an edge
into it, and (c) some controller choosing to send. **Recovery is therefore a
network property, not a local one**, and no local permission rule can supply it.
Whether the study wants below-floor initial states at all is an author decision.

## 3.5a Band invariance for C3 / `C5a` — a separate, narrower invariant

**Draft derivation d-13.** Assume (a) every destination has in-degree ≤ 1;
(b) every source bounds its own export by `A_i = [x_i − L_i]_+` from the frozen
pre-state; (c) every source caps each out-edge by `[U_j − x_j]_+/η_e`;
(d) `u = 0`, no hidden withdrawal; (e) all nodes start in band,
`x_n(0) ∈ [L_n, U_n]`. Then at every node simultaneously:

*lower:* `x_n' ≥ x_n − Σ_out q_n ≥ x_n − [x_n − L_n]_+ = L_n`;
*upper:* by in-degree ≤ 1, `x_n' ≤ x_n + η_e q_e ≤ x_n + [U_n − x_n]_+ = U_n`.

So `x_n' ∈ [L_n, U_n]`, the hypothesis is re-established, and induction gives
band invariance for all ticks with bands fixed. ∎

This is exactly what C3's rule enforces by construction and what `C5a`'s stage-1
screen enforces via `Z_V` (d-6, d-5 with `α,β > 0`). **It is a narrow invariant
and must not be equated with** sustained positive service, recovery from outside
the band, potential descent, or general long-run homeostasis. In particular
d-13 says nothing about whether any service is delivered: `q = 0` satisfies it
trivially.

## 3.6 Pipeline position — specified operationally

**The defect being corrected.** A controller cannot optimize over
`Q_i = {q ≤ c, Σq ≤ B_i}` unless it can *evaluate membership* in `Q_i`.
Knowing the symbolic mapping `B_i = [x_i − P_i]_+` while lacking `P_i` is **not**
knowing the set. So either the feasible domain is represented to the controller,
or the controller operates through a **fully specified proposal-to-accepted**
mechanism and is optimizing something else. Both are set out below.

### 3.6.1 What is committed, and what is merely my own prior choice

| Restriction | Provenance | Binding? |
|---|---|---|
| design §28 forbids global `V`, distant unrelated state, global average health, future demand, future rollout, oracle feasibility, other controller outcomes, final score | **committed** | yes — and **a source-local aggregate export cap is on none of these lists** |
| design §9: the provider layer determines what may be served; use the authoritative resolver; implement proportional scaling if that is current authority | **committed** | yes — and it states **no visibility rule whatsoever** |
| committed event ordering: **event 2** classifies sources, **computes aggregate budgets**, and **reports feasibility**; **event 3** is the actor's proposal | **committed** | yes — budgets already exist *before* any proposal |
| "no arm sees the budget" | `ebu_candidate_controllers.OPPORTUNITY_INVARIANTS` item 7 — **my own prospective declaration** | **no** — a candidate choice, amendable by the author |

**Draft derivation d-8a (no event-order amendment is required).** Publishing the
aggregate cap to the controller places a *read* of an event-2 output at
event 3. Event 2 already precedes event 3 in the committed ordering and already
"reports" feasibility. Therefore the architecture below needs **no amendment to
the committed event ordering**; it needs exactly one amendment, to my own
`OPPORTUNITY_INVARIANTS` item 7. ∎

**Publishing a constraint is not moving allocation.** Authoritative allocation
stays at event 4. What changes is only that the proposal arriving at event 4 is
already inside the admissible set, so the resolver's scaling is a no-op
(`σ = 1`) rather than absent. **The resolver is retained** as the authoritative
final check, not bypassed.

### 3.6.2 The three architectures, fully specified

| | **(i) published cap** *(analysed preferentially)* | **(ii) resolver-after-selection** | **(iii) declared-floor** |
|---|---|---|---|
| **controller-visible** | `c_e`; own `x_i`; own and destination declared parameters; **the scalar cap `B_i`** | `c_e`; own `x_i`; own and destination parameters. **No cap** | as (i) **plus `P_i` itself** |
| **optimization domain** | `Q_i = {q ≥ 0 : q_e ≤ c_e, Σ_e q_e ≤ B_i}` | `Q_i^open = {q ≥ 0 : q_e ≤ c_e, Σ_e q_e ≤ x_i}` — **its own stock, not `B_i`** | `Q_i` (same as (i)) |
| **proposal** | `q^sel ∈ Q_i`, already admissible | `q^sel ∈ Q_i^open`, possibly inadmissible | `q^sel ∈ Q_i` |
| **accepted vector** | `q^acc = q^sel` (σ = 1; see d-8b) | `q^acc = σ q^sel`, `σ = min(1, B_i/Σ q^sel)` | `q^acc = q^sel` |
| **valuation timing** | on `q^sel = q^acc`: **the value used to select is the value of what executes** | the controller values `q^sel`; what executes is `σ q^sel`. **Different objects** | as (i) |
| **what it reveals** | one scalar bound. Since the arm knows `x_i`, `P_i = x_i − B_i` is inferable whenever `B_i > 0` — so this reveals the floor's *value*, though not its semantics | nothing | the floor and its semantics |
| **amendment required** | `OPPORTUNITY_INVARIANTS` item 7 only | none | item 7, and arguably more than is needed |

Option (iii) is listed only to be set aside: it grants strictly more than the
decision needs. Option (i) publishes **an adequate representation of the
feasible domain** — which is what the controller requires — and nothing about
what the floor *means*.

### 3.6.3 Under (ii) the controller is not optimizing what executes

`F_G` is non-linear, so `F_G(σ q) ≠ σ F_G(q)`, and a vector selected as
value-maximal in `Q_i^open` need not be value-maximal after scaling. **The
selection value and the accepted value are distinct objects and are not claimed
identical.**

**Draft derivation d-10 (uniform reduction cannot flip a nonnegative value).**
For the current convex potential and affine action map `F_G` is concave (d-3)
and `F_G(0) = 0`, so concavity at `σq + (1−σ)·0` gives

```
F_G(σ q)  ≥  σ F_G(q) + (1−σ) F_G(0)  =  σ F_G(q) ,      0 ≤ σ ≤ 1 .
```

Hence `F_G(q) ≥ 0 ⇒ F_G(σq) ≥ 0`: **uniform proportional reduction cannot turn
a nonnegative local field value negative.** Under `C_G ≡ 0` the same holds for
net EBU. ∎

So under (ii) a `C5a` selection that was value-nonnegative **stays**
value-nonnegative after scaling — the resolver cannot force `C5a` to violate its
own refusal rule. That bounds the damage; it does **not** make the selection
optimal for what executes, because maximality is not preserved.

**Scope of d-10, explicitly.** It does **not** extend automatically to: a
non-convex potential; a **non-uniform** transformation (per-edge scaling with
differing factors); the value of the **full multi-source event** (additional
simultaneous actions by other sources); or a **non-zero process burden** — with
a fixed activation cost `c₀`, `C_G(σq)` does not shrink with `σ`, so net EBU can
be driven negative by scaling even though `F_G` cannot.

### 3.6.4 Joint feasibility — does the selected vector actually execute unchanged?

**Draft derivation d-8b (joint feasibility under (i)).** Assume (a) every
destination has in-degree ≤ 1; (b) per-edge caps `c_e ≤ [K_j − x_j]_+/η_e`
computed from the **frozen** pre-state; (c) per-source caps `Σ_e q_e ≤ B_i`
from the frozen pre-state; (d) `u = 0`, no hidden withdrawal. Then for every
node `n`, with `x_n' = x_n + Σ_{e→n} η_e q_e − Σ_{e: n→k} q_e`:

*Lower bound.* Incoming is `≥ 0`, so
`x_n' ≥ x_n − Σ_out q_n ≥ x_n − [x_n − P_n]_+`, which equals `P_n ≥ 0` when
`x_n ≥ P_n`, and is `≥ x_n ≥ 0` when `B_n = 0`.

*Upper bound.* Outgoing only reduces `x_n`, and by in-degree ≤ 1 there is at
most one incoming edge, so `x_n' ≤ x_n + η_e q_e ≤ x_n + [K_n − x_n]_+ = K_n`.

Hence the joint successor satisfies `0 ≤ x_n' ≤ K_n` at every node
**simultaneously**, so the selected vector is jointly feasible and **executes
unchanged**. ∎

**Both hypotheses are load-bearing.** With in-degree ≥ 2 the upper-bound step
fails: two sources each respecting `[K_j − x_j]_+` can jointly exceed `K_j`.
That is exactly the contention case with no committed allocation rule, and it is
why the single-source restriction is present. And if caps were computed from a
*post-update* rather than the frozen state, (A1)'s synchronous semantics would be
lost.

### 3.6.5 Recommendation for the pipeline

**Recommended (not adopted): architecture (i) — the published-cap pipeline.**

```
demand  →  common opportunities (c_e)  →  common permitted feasible set (cap B_i)
        →  controller selection within it  →  final physical validation (resolver + joint check)
```

Reasons: it is the only option in which the controller optimizes the object that
actually executes (d-8b); it requires **no committed amendment** (d-8a); it
leaves authoritative allocation at event 4 untouched; and it publishes a scalar
bound rather than the floor's semantics.

**Required amendments, exhaustively:**

1. amend `OPPORTUNITY_INVARIANTS` item 7 from "no arm sees the budget" to "every
   arm sees the same aggregate cap";
2. supply `B_i` on the **common context**, so it reaches **every** arm — C0–C4
   included — identically. Any arm whose rule does not read it is unaffected;
   what matters is that none is privileged;
3. record that `P_i`'s *value* becomes inferable from `B_i` and `x_i`, and decide
   whether that is acceptable (it is uniform across arms, and `P_i` is a
   declared world constant, not a secret).

**Not amended:** the committed event ordering, design §9, design §28, P1C, and
the authority of the resolver at event 4.

# 4. The two lexicographic policies, analysed

## 4.1 Objectives

```
S(q)  =  Σ_e q_e^delivered  =  Σ_e η_e q_e         (destination-side)
       =  Σ_e q_e   at η = 1                        (equals total sent)
ΔE_G(q) = F_G(q) − C_G(q)   →  F_G(q) under C_a ≡ 0
```

`S` is **unweighted delivered service** for a homogeneous scalar resource. No
price, service weight or utility coefficient is introduced; each transfer is
bounded by its own external demand through `c_e ≤ d_e`.

**`S` is measured DESTINATION-SIDE.** At `η = 1` it coincides numerically with
total sent `Σ_e q_e`, which is why the two are used interchangeably below. That
interchange is **licensed only by a common `η` across the source's out-edges**
(see the scope box after d-11). Under heterogeneous `η_e` the two objectives
are different functions with different maximisers, and every conclusion drawn
from "maximising `S` fixes the total withdrawal" must be re-derived.

Rest is included explicitly: **`F_G(0) = 0` and `S(0) = 0`** under the declared
zero-action convention (Definition 6.13a: `q = 0` is a separate exact branch,
never reached by limit).

## 4.2 Existence and structure

**Draft derivation d-3.** `Q_i` is compact convex and non-empty. Each `v_k` is convex
and `C¹` (Definition 6.1) and `T_G` is affine in `q`, so `V_A ∘ T_G` is convex
and hence

```
F_G  is CONCAVE on Q_i ;      S  is LINEAR on Q_i .
```

Both are continuous, so by Weierstrass each attains a maximum on `Q_i`; the
argmax set of a continuous function on a compact set is non-empty and compact,
so the **second** lexicographic stage also attains. Additionally:

- `argmax F_G` is **convex** and compact (superlevel set of a concave function);
- `argmax S` is a **face** of the polytope.

So both orderings are well-posed continuous programs with attained maxima. ∎

*(Caveat, binding: under Definition 6.13a with a fixed activation cost `c₀>0`,
`ΔE_G` is **discontinuous at `0⁺`** and d-3's concavity argument fails on the
closed set. Concavity is therefore a consequence of the `C_a ≡ 0` assumption,
not of the functional alone — see §7.2.)*

## 4.3 Variant `C5a` — EBU-first

```
stage 1:  maximize  ΔE_G(q)   over  q ∈ Q_i
stage 2:  maximize  S(q)      over  argmax stage 1
stage 3:  declared deterministic tie rule (N-5)
```

| Aspect | Treatment |
|---|---|
| **positive** value | selected; the largest achievable value wins |
| **zero** value | selected **only if** no positive value is achievable — and then stage 2 chooses the **most service** among zero-value vectors. Rest is *not* privileged over a zero-value service vector; `S` breaks that tie in service's favour |
| **negative** value | **never selected.** `ΔE_G(0) = 0`, so any `q` with `ΔE_G(q) < 0` loses to rest at stage 1 |
| service vs rest tie | resolved by stage 2 **for** service: among equal-value vectors the largest `S` is taken, so rest is chosen only when it is uniquely value-maximal |
| no positive service feasible | `Q_i = {0}` (all `c_e = 0`, or `B_i = 0`) ⇒ rest, `ΔE_G = S = 0` |
| information | `z_i`, `z_j` and declared parameters of `i` and each affected `j`; `c_e`; `η_e`, `Δt`; `B_i` under option (i) |
| existence | d-3 |

**Why rest defeats every negative-value service action.** Rest is always
feasible and has value exactly `0`. A burden-increasing vector has value `< 0`,
so it is strictly dominated at the **first** lexicographic level, where service
is not yet consulted. Service can therefore never purchase a worsening of the
represented local state: `C5a` **will decline unlimited demand rather than add
any burden at all.** That is the mechanism's defining property — and its
defining weakness on the service axis.

## 4.4 Variant `C5b` — service-first

```
stage 1:  maximize  S(q)      over  q ∈ Q_i
stage 2:  maximize  ΔE_G(q)   over  argmax stage 1
stage 3:  declared deterministic tie rule (N-5)
```

| Aspect | Treatment |
|---|---|
| **positive** value | selected at stage 2, but only among already service-maximal vectors |
| **zero** value | likewise |
| **negative** value | **can be selected** — and will be, whenever *every* service-maximal vector adds burden. The field then chooses the **least** negative |
| service vs rest tie | rest is selected only when `S` is forced to `0` |
| no positive service feasible | `Q_i = {0}` ⇒ rest |
| information | as `C5a` |
| existence | d-3 (linear max then concave max over a face) |

**What the field does and does not decide here.** Among equally-servicing
vectors it selects the **least-burdensome allocation** — it shapes *how* the
same total is delivered. It does **not** decide how much immediate service to
sacrifice for future viability; it never sacrifices any. Negative field values
are accepted whenever service-maximality requires them.

**Draft derivation d-7 (dimension of the service-maximal set — corrected).**
At `η = 1` the feasible set is a box plus one aggregate bound:
`Q = {q ≥ 0 : q_e ≤ c_e, Σ_e q_e ≤ B}`, `S(q) = Σ_e q_e`, so
`max S = min(Σ_e c_e , B)`. Let `E⁺ = {e : c_e > 0}` and `m⁺ = |E⁺|`;
coordinates with `c_e = 0` are **fixed at 0** and are removed before counting
dimension. Then:

| case | `argmax S` | dimension |
|---|---|---|
| `B = 0` | `{0}` | **0** |
| `B ≥ Σ_e c_e` | `{q_e = c_e ∀e}` — caps fix the vector | **0** |
| `m⁺ = 0` | `{0}` | **0** |
| `m⁺ = 1`, `0 < B < c_{e*}` | `{q_{e*} = B}` — one usable edge | **0** |
| `m⁺ ≥ 2`, `0 < B < Σ_e c_e` | `{q ∈ Q : Σ_e q_e = B}` | **`m⁺ − 1`** |

Only the last row leaves the controller any allocation freedom. ∎

**Additional constraints that alter this.** For `C5a` the zero-set requirement
tightens both bounds: the per-edge cap becomes
`c_e' = min(c_e, [U_j − x_j]_+/η_e)` and the aggregate becomes
`min(B_i, A_i)` with `A_i = [x_i − L_i]_+`. The same table then applies to the
primed quantities. The joint successor condition adds nothing further under
d-8b's hypotheses.

## 4.4a Does `F_G` actually vary across the service-maximal set?

**This is the question that decides whether either variant has an operative
field criterion at all, and the previous revision did not ask it.**

**Draft derivation d-11 (the source term is constant; flatness of the
destinations decides).** On the service-maximal set the total export
`T = Σ_e q_e` is **fixed** (`T = max S`). By d-1 the source contribution is

```
v_i(z_i) − v_i(z_i − T)     — a function of T alone, hence CONSTANT on the set.
```

Therefore

```
F_G(q)  =  const(T)  +  Σ_e [ v_j(z_j) − v_j(z_j + η_e q_e) ] ,
```

and `F_G` varies across the service-maximal set **iff**
`Σ_e v_j(z_j + η_e q_e)` varies over it. In particular, if every reachable
destination state stays inside its own zero set — i.e.
`z_j + η_e q_e ∈ Z_{v_j}` for every feasible `q_e` on the set — then every
destination term is identically `0`, and

```
F_G is CONSTANT on the entire service-maximal set.
```

∎

> **Efficiency hypothesis of d-11 (scope, added in this revision).** The first
> step — "the total export `T = Σ_e q_e` is **fixed** on the service-maximal
> set" — is **not** a consequence of service-maximality alone. It follows from
> `S(q) = Σ_e η_e q_e` only when `η_e` is **COMMON across the source's
> out-edges**: with `η_e ≡ η`, `max S` fixes `η Σ_e q_e` and hence `Σ_e q_e`.
> The first study's `η = 1` satisfies this, so d-11 stands **in the declared
> lossless domain**.
>
> Under **heterogeneous `η_e`** it fails. Fixing `Σ_e η_e q_e` leaves `Σ_e q_e`
> free, so the source term `v_i(z_i) − v_i(z_i − Σ_e q_e)` **varies across the
> service-maximal set**. The field criterion can then be operative for a reason
> that has nothing to do with destination flatness — the valuation would
> discriminate by *how much was withdrawn to achieve the same delivered
> service*, i.e. it would price transport loss through the source term.
>
> **Consequence for this packet.** d-7 (face dimension), d-11 (constant source
> term), d-13 (band invariance) and all of §4A (the matched reference, the
> decision-influence cases, the `CERTIFIED_FLAT` certificate) are **scoped to
> common-`η` worlds**. None of them may be exported into a heterogeneous
> loss-aware study without re-derivation. This is a **scope statement about
> existing results**, not a new result and not a reason to prefer any `η`.

**Consequence, stated plainly.** When `F_G` is constant on that set, the
lexicographic second stage is **vacuous** and the allocation is chosen by the
**declared residual tie rule (N-5)**, not by the graded EBU valuation. Any
report attributing such an allocation to "the field" would be **false
attribution**. Concretely, with all destinations in band and
`z_j + η_e c_e' ≤ U_j` for every edge, this is exactly the situation.

**When the field criterion *is* operative:** only where some destination's `v_j`
is non-flat over its reachable interval on the set — i.e. some destination is
already outside its zero set, or would be driven outside it by some admissible
allocation. Because `c_e` is capped by `K_j` rather than `U_j`, a destination
**can** be pushed above `U_j`, so the criterion is not always vacuous. **How
often it is operative is a property of the declared demand process, the declared
bands and `P_i` — and it must be measured and reported, not assumed.**

**Draft derivation d-12 (from an all-in-band baseline the exact valuation
carries no graded information).** Suppose `V_A(z) = 0`. By d-6,
`F_G(q) ≥ 0 ⟺ F_G(q) = 0 ⟺ T_G(z,q) ∈ Z_V`. So on the admissible region
`F_G` takes only the value `0`, and off it `F_G < 0`. Stage 1 of `C5a` is then a
**binary feasibility screen** — "does this vector keep every affected factor in
its zero set?" — and carries **no graded ranking**. Combined with d-11, stage 2
of `C5b` is flat **only where the reachable destination successors also stay
inside their zero sets** — which does *not* follow from the baseline. ∎

**This is the honest core of the matter, and it is independent of the automatic
flux.** From an all-in-band baseline with `C_a = 0`, the exact finite EBU
valuation contributes no graded information to either variant: in `C5a` it
degenerates to a band-feasibility screen, and in `C5b` it is flat on the
service-maximal set **only when every reachable destination successor also
stays inside its zero set**. **The condition is about the successor allocations
in `M_i`, not about the baseline**: because `c_e` is capped by `K_j` rather than
`U_j`, an all-in-band baseline can still admit allocations that push a
destination above `U_j`, and then `F_G` is *not* flat. That is the same
underlying cause as the C4 zero-action finding — an all-in-band baseline leaves
the potential flat — reappearing in a mechanism that *does* respond to demand.
It is **not** a statement that exact-EBU selection is uninformative in general;
it is a statement about this baseline.

## 4.5 Deterministic residual ties (N-5)

After both stages a tied set may remain with positive dimension (e.g. symmetric
edges under `C5a` stage 2, or the interior of `C5b`'s face when `F_G` is flat on
it). A **declared deterministic rule** is required. Proposed for review:
*lexicographically greatest quantity vector when edges are ordered by
destination node id ascending.* It depends only on declared identifiers — no
`μ`, no `f_e`, no controller outcome, no future information, no arm label — and
it is a **preregistration slot, not a default**. It resolves ties; it must never
change either maximum.

## 4.6 Recommended ordering (not adopted) — corrected reasoning

The previous revision recommended `C5b` on the ground that it "isolates the
field's contribution at equal service". **By d-11 that ground is conditional and
often false**, so the reasoning is restated.

**Recommended: `C5b` (service-first), with an explicit operativity condition.**

Why, after the corrections:

1. **`C5a` is not discarded** — its equivalence to C3 was never established
   (§6.3). But by **d-12**, from an all-in-band baseline `C5a`'s EBU stage is a
   **binary band-feasibility screen** carrying no graded ranking, which is the
   same constraint C3 imposes by construction. So on the declared baseline
   `C5a` would be testing a screen, not a valuation.
2. **`C5b` at least *can* be operative on the declared baseline**, because its
   per-edge caps run to `K_j` rather than `U_j`, so a destination can be driven
   out of band and the destination terms need not be flat (d-11).
3. **But `C5b` is operative only on a subset of states**, and on the complement
   the residual tie rule selects. **This must be measured and reported**, not
   assumed: the study should record, per tick, whether `F_G` was non-constant on
   the service-maximal set. Without that instrumentation the comparison cannot
   distinguish an EBU effect from a tie-rule artifact.

**Limitations, restated.** `C5b` does not preserve homeostasis as a constraint:
it accepts negative field values whenever service-maximality requires them
(and, at a zero-potential baseline with a fixed activation cost, on every
action — d-14, **which does not extend to later states where `V_A(z) > 0` and
`F_G` may exceed `c₀`**). It answers *"among
equally-servicing allocations, does the graded valuation choose better than
proportional-to-cap or max-min-fair?"* — **and only on the states where the
valuation is non-constant.** It does not answer whether the field should trade
service for viability; that is `C5a`'s question and needs a baseline with
`V_A(z) > 0`.

**Neither ordering is claimed to achieve long-run homeostasis**, and d-13's band
invariance is not such a claim.

## 4.7 Continuous programs, not menus

Both variants are **continuous optimizations over the polytope `Q_i`** (§2.4).
Nothing here replaces them with a finite menu, a grid, a fraction ladder or an
iterative solver. Any such implementation is a **separately declared
approximation** requiring its own statement of what it computes and its error
relative to the exact program; that declaration is an author decision and is not
made here.

# 4A. Matched no-field reference and decision-influence reporting

The comparison question is not "does `C5b` deliver more service than C2?" — by
d-7 it usually delivers exactly the same at a shared state. It is: **when the
field had a choice, did it change the choice, and was the change a field effect
or a tie-rule artifact?** This section specifies the reference and the reporting
that answer it. All formulas assume the candidate `C_G ≡ 0` configuration; if
that changes, every `F_G` below becomes `ΔE_G = F_G − C_G` and the two must be
kept distinct (§2.5).

## 4A.1 The matched reference

At one frozen local state, over the **same** common feasible set `Q_i`:

```
M_i     =  argmax_{q ∈ Q_i} S(q)                    the service-maximal set
q_ref   =  T( M_i )                                  no-field reference
q_EBU   =  T( argmax_{q ∈ M_i} F_G(q) )              field selection
```

`T` is **the same declared, field-independent selection rule in both**. The only
difference between `q_ref` and `q_EBU` is the set `T` is applied to.

## 4A.2 `T` specified in full

**`T(A)` = the lexicographically greatest element of `A` when components are
ordered by destination node id ascending.**

Fully determined, and field-independent by construction: it reads the quantity
vector and the declared destination identifiers, and **nothing else** — no
`F_G`, no `μ`, no `f_e`, no weights, no controller identity, no outcome, no
future data. Ties: none remain. For a non-empty compact `A ⊆ ℝ^m` the
lexicographic maximum is unique — maximise the first component over `A`,
then the second over that subset, and so on; each stage is a maximisation of a
continuous function over a non-empty compact set, and after `m` stages exactly
one point survives. Existence and uniqueness therefore need no tie-break
convention.

*(Water-filling / max-min-fair is the other natural candidate for `T` and is
also admissible — it is the lexicographic maximum of the ascending-sorted
vector. Which `T` is declared is an author decision (§8.3; decision **D5**). What matters here is
that **the same `T` is used in both expressions** and that it satisfies §4A.3.)*

## 4A.3 Restriction consistency is a requirement on `T`, not a detail

**Requirement.** For all `A ⊆ B` with `T(B) ∈ A`:  `T(A) = T(B)`.

This is Sen's property α (contraction consistency / Chernoff). **Without it the
comparison is meaningless**: `q_EBU ≠ q_ref` could arise purely because `T` was
applied to a smaller set, with no field improvement whatsoever — a *set-dependent
tie artifact* masquerading as a field effect.

**Draft derivation d-15 (both proposed rules satisfy α).** Let `T` maximise a
fixed total preorder `≽` that is antisymmetric on the relevant sets (lexicographic
order on the vector, or on its ascending sort). If `T(B) ∈ A ⊆ B`, then `T(B) ≽ a`
for all `a ∈ B ⊇ A`, so `T(B)` is `≽`-greatest in `A`; by uniqueness of the
`≽`-maximum, `T(A) = T(B)`. ∎ Any `T` defined as the unique maximiser of a fixed
order satisfies α; a rule whose criterion depends on the *set* (an average, a
median, a proportional share of the set's total) generally does **not**, and is
inadmissible here.

## 4A.4 Changed choice ⟺ strictly positive field advantage

**Draft derivation d-16.** Assume exact optimisation and an α-consistent `T`.
Write `M_i* = argmax_{q ∈ M_i} F_G(q)`, so `q_EBU = T(M_i*)`.

*Nonnegativity.* `q_ref ∈ M_i` and `q_EBU` maximises `F_G` over `M_i`, hence

```
F_G(q_EBU) − F_G(q_ref)  ≥  0        always, by definition of the argmax.
```

*Equivalence.* Suppose `F_G(q_EBU) = F_G(q_ref)`. Then `q_ref ∈ M_i*`. Since
`M_i* ⊆ M_i` and `T(M_i) = q_ref ∈ M_i*`, α gives `T(M_i*) = T(M_i) = q_ref`,
i.e. `q_EBU = q_ref`. Contrapositive:

```
q_EBU ≠ q_ref   ⟹   F_G(q_EBU) > F_G(q_ref)   strictly.
```

Conversely a strict advantage forces `q_EBU ≠ q_ref`. ∎

**Consequence for reporting.** Under exact optimisation with an α-consistent
`T`, a changed vector with **zero** advantage is *impossible*. If one is ever
observed it is **evidence of a defect** — inexact optimisation, a
non-α-consistent `T`, or a tolerance artifact — and **must not be counted as an
EBU-value effect.**

**And a warning about what nonnegativity is worth.** `F_G(q_EBU) ≥ F_G(q_ref)`
holds *by the definition of an argmax*. It confirms the selection mechanism does
what it is defined to do; it is **not** independent evidence of an improved
realised event value, of sustained service, or of long-run homeostasis.

## 4A.5 Relationship to C2 — the reference is NOT C2

**C2 is preserved unchanged and is not silently redefined.** The question is
whether C2's existing accepted-vector rule already equals `q_ref`.

C2 proposes `q_e = c_e·min(1, x_i/Σ_{e'} c_{e'})` — it scales by its **own
stock**, since it does not read `B_i`.

| regime | `M_i` | C2's accepted vector | equals `q_ref`? |
|---|---|---|---|
| `Σ c ≤ B_i` | singleton `{c}` | `q = c` (since `Σc ≤ B_i ≤ x_i` forces the `min` to 1) | **yes** — trivially, both are the unique point |
| `Σ c > B_i`, `P_i > 0` | face `Σq = B_i` | `Σ q = min(Σc, x_i) > B_i` | **no** — C2's own proposal is **outside `Q_i`**; under architecture (i) it is not admissible, under (ii) the resolver rescales it |
| `Σ c > B_i`, `P_i = 0` (so `B_i = x_i`) | face `Σq = x_i` | `q_e = c_e·x_i/Σc`, service-maximal | **only if `T` is proportional-to-cap** — which the declared `T` is not |

**Conclusion.** C2's rule equals `q_ref` **only in the degenerate singleton
case**. It is therefore **not** the matched no-field reference, and must not be
reported as one.

`q_ref` is accordingly identified as a **separate candidate no-field ablation**:
*the same feasible set, the same service objective, the same selection rule `T`,
and no field term.* It is a **reference calculation**, not a registered arm.

**Any adaptation of C2 is explicit and is an author decision.** Restating C2's
scaling denominator from `x_i` to `B_i` would make it feasible under
architecture (i) and service-maximal, but it would still equal `q_ref` only if
`T` were proportional-to-cap. **No such adaptation is made here**, and C2's
declaration is untouched.

## 4A.6 A reference calculation is not a comparison arm

`q_ref` is computed at the **same frozen state** as `q_EBU`, from the **same**
feasible set. It answers "what would the no-field rule have chosen *here*?"

It does **not** supply the outcomes of an arm that actually ran `T`-selection
over a trajectory. Such an arm would select differently at some tick, reach a
different successor state, and from then on face a different feasible set and
different reachable demand. **Per-decision reference statistics must never be
aggregated into a claim about an alternative arm's long-run service or
viability.** If a `T`-selection arm is wanted, it must be registered and run as
an arm.

## 4A.7 Per-decision record

Recorded for **every** source-local decision, with no filtering:

| field | meaning |
|---|---|
| `multiple` | whether `\|M_i\| > 1` |
| `field_nonconstant` | whether `F_G` is non-constant on `M_i` |
| `q_ref`, `q_EBU` | the two selected vectors |
| `changed` | whether they differ |
| `advantage` | `F_G(q_EBU) − F_G(q_ref)` |
| `range` | the theoretical field range `max_{M_i} F_G − min_{M_i} F_G` |
| `status` | `EXACT`, `CERTIFIED_FLAT`, or `UNRESOLVED` |

## 4A.8 How the range is obtained — exactly, or declared unresolved

**No expensive or approximate optimisation is introduced silently**, and
**sampling cannot establish constancy over a continuous set** and is not used
for that purpose.

The structure permits exact answers:

- **`max_{M_i} F_G`** — `F_G` is concave (d-3) and `M_i` is a compact polytope,
  so this is a **concave maximisation** with an attained maximum.
- **`min_{M_i} F_G`** — minimising a **concave** function over a polytope
  attains at a **vertex**, so the exact minimum is `min` over the vertex set of
  `M_i`. For `M_i = {q : Σq = B, 0 ≤ q ≤ c}` the vertices are the points with at
  most one fractional coordinate and all others at `0` or `c_e`; the count is
  combinatorial in the out-degree `m⁺`, which bounds the cost honestly rather
  than hiding it.
- **`CERTIFIED_FLAT`** — a cheap **sufficient** certificate that needs no
  optimisation: if for every `e ∈ E⁺` the *entire reachable interval*
  `{ z_j + η_e q_e : 0 ≤ q_e ≤ min(c_e, B_i) }` lies inside `Z_{v_j}`, then every
  destination term vanishes identically on `M_i` and `F_G` is constant there
  (d-11). Note this is a condition on **reachable successors**, not on the
  baseline.
- **`UNRESOLVED`** — neither an exact result nor a sound certificate was
  obtained. Reported as its own category, **never** silently merged into
  "no effect".

**Numerical equality rules and tolerances are explicit preregistration
requirements.** Deciding whether `F_G(q_EBU) − F_G(q_ref)` counts as zero, and
whether `max − min` counts as zero, requires a declared comparison rule. **No
tolerance is invented here and none is defaulted.**

## 4A.9 Interpretation rules, per case

Each case informs a **different** claim. None is a blanket `INCONCLUSIVE`, and
**a zero changed-choice count is a result, not an inconclusive run.**

| # | Case | Necessarily | What it informs | What it does NOT inform |
|---|---|---|---|---|
| **(a)** | `\|M_i\| = 1` | `q_ref = q_EBU` | the **demand/feasibility structure**: at this state service alone determined the allocation | nothing about the field — it was offered **no** choice. Not evidence for or against EBU |
| **(b)** | `\|M_i\| > 1`, `F_G` constant on `M_i` | `q_ref = q_EBU` (by α) | that the field's valuation **does not discriminate** among service-maximal allocations here — a genuine negative finding about the valuation's resolution | it does not show the field is wrong, only indifferent |
| **(c)** | `F_G` non-constant, but `q_ref ∈ M_i*` | `q_EBU = q_ref` (by α), advantage `= 0` | that the **no-field rule was already field-optimal** here — an agreement, and an interesting one | it is **not** an absence of opportunity; the field did have a basis and concurred |
| **(d)** | `q_EBU ≠ q_ref` | advantage `> 0` strictly (d-16) | the field **changed the decision** with a strictly positive local advantage — the only case that evidences a field effect on selection | it does **not** establish improved realised event value, service or homeostasis |
| **(e)** | `UNRESOLVED` | — | nothing; counted separately | must never be folded into (a)–(d) |

**Reporting discipline.**

- report **counts with their denominators** — e.g. "(d) in 12 of 480 decisions;
  (a) 310; (b) 96; (c) 55; unresolved 7" — never a bare percentage;
- **no minimum activation threshold.** There is no rate below which the study
  "fails to activate"; a low (d)-count is itself the finding;
- **do not tune the world until the field acts**, and **do not discard inactive
  decisions after seeing outcomes**. The decision record is fixed by the
  protocol, not by the results;
- **do not sum local advantages across sources and call the total a realised
  global improvement.** Affected factor sets overlap (d-9), so the sum is not
  the realised group change; that residual is an audit quantity (§5.3).

# 5. Runtime locality and the three distinct values

## 5.1 Permitted evaluation

`C5` may evaluate **only** the affected factors reachable through its declared
local view: its own `z_i` and parameters, and `z_j` plus declared parameters for
each destination of an out-edge it is considering. It must **not** call the
researcher's global-potential evaluator (`ebu_test_settlement.potential`, which
takes the whole `WorldSpec`), and must not receive global state, future demand,
oracle output or any other arm's outcome.

## 5.2 Local-to-global identity, and required inputs

**Lemma 6.6** licenses the local computation exactly: because `V` is separable
and `T_G` changes only factors in `A`,

```
V_A(z) − V_A(T_G(z,q))  =  V(z) − V(T_G(z,q))       for the GLOBAL V,
```

every unaffected factor cancelling identically. The local number **is** the
exact global change for that action group — provided `A` is **complete** (source
plus every destination receiving positive quantity). An incomplete `A` breaks
the identity, so completeness is a correctness requirement, not a convention.

Required inputs, per evaluation: `z_i`; `(α,β,χ,L,U,R,K)_i`; for each considered
destination `j`, `z_j` and `(α,β,χ,L,U,R,K)_j`; `η_e`; `Δt`; `c_e`; and `B_i`
under option (i) only.

**Any expanded permission information must be handled identically across arms.**
If option (i) grants `B_i`, it is granted to C0–C4 as well, on the common
context — never through an arm-specific channel.

## 5.3 Three values that must not be conflated

| # | Value | Computed by / when | Uses |
|---|---|---|---|
| 1 | **local candidate value** `ΔE_G(q)` | the arm, from the frozen baseline over its own affected set, before permission resolution | selection only |
| 2 | **accepted quantities** `q^acc` | the common physical layer | what actually executes. `= q^sel` under option (i); `= σ q^sel` under option (ii) |
| 3 | **realised simultaneous-event field value** | the evaluator, **after** execution, over **all** sources' accepted actions | audit and reporting only |

**(1) ≠ (3) in general**, and the difference is not an error to be eliminated.
Other sources acting simultaneously change the realised event value. **A local
actor must not be given remote information merely to close that gap** — doing so
would breach the information boundary for every arm and destroy the comparison.
The difference is reported, not removed.

**Corrected statement of what pipeline (i) does and does not buy.** Under (i),
`q^acc = q^sel`, so value (1) is the exact value of the arm's **own** accepted
vector — the selection/acceptance gap closes. **It does not follow that (1)
equals (3).** Value (3) is the field value of the **full multi-source event**,
and equality of an arm's evaluated and accepted vector says nothing about the
contributions of other sources. Conflating the two would be exactly the error
d-9 guards against.

**C5 optimizes only its authorized local action variables** — the components of
its own `q_i` — over its own feasible set. It does not optimize, and is not
claimed to optimize, the realised group value.

**Cross-source interaction remains an audit quantity.** The residual
`(3) − Σ_sources (1)` is computed by the evaluator after execution, for
reporting. It is **not** a newly authorized per-action settlement, **not** a
wallet credit, and **not** an entitlement: per-action decomposition at `m ≥ 2`
remains blocked (E2 / O3), and nothing in this packet changes that.

**No claim of global maximization.** Neither variant maximizes realised group
EBU. Each maximizes a **local** candidate value over its **own** feasible set.

## 5.4 Simultaneous groups and non-additivity

**Draft derivation d-9.** *"One action per source" does not establish disjoint effects
or additive quotes, even under the single-source-destination restriction.* If the
topology contains a chain `i → k → m`, node `k` is simultaneously a destination
of `i`'s action and the source of its own. The factor `v_k` then appears in the
affected sets of **two different sources**, so

```
realised group value   ≠   Σ_sources ( local candidate value )
```

and the residual is again a mixed second difference of `v_k`, not zero. ∎

Consequences, all preserved rather than assumed away:

- **simultaneous groups remain representable at any size**; no permanent
  one-action-only restriction is imposed;
- **additivity is not guaranteed** and quotes are not summed — consistent with
  **E2 / O3**. Note the precise form: overlapping affected factors mean
  additivity **cannot be assumed**, not that the interaction is nonzero in every
  case. The worked instance in §2.3 has interaction `+4`; a vector whose shared
  factor stays inside a flat region of `v` has interaction exactly `0`. The
  claim is "not guaranteed", never "always different";
- **group field evaluation is kept separate from per-action attribution**,
  wallet entries and entitlement claims, all of which remain blocked;
- a topology in which no node both sends and receives within one tick would make
  source groups disjoint. That is a possible further candidate restriction and
  is **not adopted here.**

# 6. Is this a distinct comparison?

## 6.1 What is being compared

Under the proposed permission rule all arms share `Q_i` and the replayed demand.
The question is whether `C5`'s selection is a *different policy*, not merely a
different derivation of the same policy.

## 6.2 `C5b` versus C2 — same service, different shape; and a mismatch

**Service value.** Both attain `S = min(Σ_e c_e , B_i)`:

- if `Σ c ≤ B_i`: C2's rule `q_e = c_e·min(1, x_i/Σc)` gives `q = c` (since
  `Σc ≤ B_i = [x_i−P_i]_+ ≤ x_i` forces the `min` to 1), and `C5b`'s stage-1
  argmax is the same singleton ⇒ **identical vectors, `C5b` ≡ C2 exactly**;
- if `Σ c > B_i`: `C5b` selects on the face `Σq = B_i`; C2's *own rule* caps by
  `x_i`, not `B_i`.

**Mismatch identified, not silently repaired.** C2 scales by its **own stock**
`x_i` because it cannot see `B_i` (invariant 7). Under the proposed rule with
`P_i > 0`:

- **option (ii)**: the resolver scales C2's proposal to `Σ = B_i`; because C2's
  shape is proportional-to-cap the result lands **on** the service-maximal face,
  so **C2 does attain the same immediate service objective** — the matched
  comparator is intact;
- **option (i)**: C2's rule as written can propose outside `Q_i`. Making it
  attain `S`-maximality would require restating it with `B_i` in place of `x_i`
  — **a change to C2, which this packet does not make.** It is an author
  decision (§8, decision 4). C2 is neither weakened nor replaced here.

**What the EBU secondary criterion changes — and the scope of the claim.**

- **Scope, corrected.** The equal-service statement holds **at a common frozen
  state with a common feasible set**. It does **not** transfer across
  independently evolving trajectories: `C5b` and C2 generally select *different
  allocations* on the binding face, so their successor states differ, and from
  the next tick onward their feasible sets, their demands' reachability and
  their delivered service may all differ. **"`C5b` and C2 deliver the same
  service" is a per-tick statement at a shared state, never a trajectory
  statement.**
- **What changes at a shared state:** only the allocation **shape** on the
  binding face — and by **d-11** even that is chosen by the residual tie rule,
  not by EBU, whenever the destination terms are flat.
- **Uniqueness (d-7):** when `B_i = 0`, or `B_i ≥ Σ_e c_e`, or at most one edge
  has positive cap, the service-maximal vector is a **singleton**: the field has
  **no** allocation choice and `C5b` coincides with C2 at that state.

**C3 is not a service-maximal comparator, and should not be read as one.** C3
bounds its own export by `A_i = [x_i − L_i]_+`. **Whether that is tighter than
permission is conditional on `L_i` versus `P_i`:** `A_i ≤ B_i` holds iff
`L_i ≥ P_i`, and if `P_i > L_i` the provider floor is the tighter bound and C3's
own allowance is not binding. Under `L_i ≥ P_i`, when `A_i < B_i` C3
**deliberately delivers less** than either `C5b` or C2. That is C3's declared
purpose, not a deficiency, and the comparison must report it as a deliberate
withholding rather than a shortfall.

## 6.3 `C5a` versus C3 — probable equivalence on the declared initial condition

**Draft derivation d-5 (the actual zero set — corrected).**
`Z_{v_i} = { x : v_i(x) = 0 }` is the intersection of the **hard physical
domain** with only the **active** penalty constraints:

```
Z_{v_i} = [0, K_i]
          ∩ { x ≥ L_i  if α_i > 0 }
          ∩ { x ≤ U_i  if β_i > 0 }
          ∩ { x ≥ R_i  if χ_i > 0 }
```

**The previous claim "any zero weight makes it strictly larger" is withdrawn.**
Redundancy matters:

| weights | with `R ≤ L ≤ U ≤ K` | zero set |
|---|---|---|
| `α,β,χ > 0` | — | `[L, U]` |
| `α,β > 0`, **`χ = 0`** | `x ≥ R` was **implied by** `x ≥ L` | **still `[L, U]`** — no enlargement |
| `α = 0`, `β,χ > 0` | lower bound weakens to `R` | `[R, U]`, strictly larger iff `R < L` |
| `α = 0`, `β > 0`, `χ = 0` | no lower penalty at all | `[0, U]` |
| `β = 0`, `α > 0` | upper bound is only physical | `[L, K]`, strictly larger iff `U < K` |

So `Z_{v_i} = [L_i, U_i]` needs only **`α_i > 0` and `β_i > 0`** (given
`R_i ≤ L_i`); `χ_i` may be zero. Enlargement requires `α_i = 0` or `β_i = 0`,
and the physical boundaries `0` and `K_i` always bound the result. Weights are
unfilled parameters (slot S-P), so wherever they are not declared positive the
**actual** zero set above must be used. ∎

**Draft derivation d-6.** If `V_A(z) = 0` then `F_G(q) = −V_A(T_G(z,q)) ≤ 0`, so

```
F_G(q) ≥ 0  ⟺  F_G(q) = 0  ⟺  T_G(z,q) ∈ Z_V  (every affected factor in its zero set).
```

∎ So from a fully in-band baseline, `C5a`'s stage 1 admits **exactly** the
zero-set-preserving vectors, and stage 2 maximizes service among them.

**Draft derivation d-8 (agreement on set and total service — NOT equivalence).** Assume: in-band
baseline `V_A(z)=0`; `α,β,χ > 0`; `R ≤ L`; `C_a ≡ 0`; `u = 0`; and `P_i ≤ L_i`.
Then

- `C5a`'s admissible set is `{ q ∈ Q_i : z_i − Σq ≥ L_i , z_j + η q_e ≤ U_j ∀e }`;
- C3's stage-1 and stage-2 caps are inert (no reserve or lower-band deficits),
  so C3 allocates its stage-3 budget `A_i = [x_i − L_i]_+` under caps
  `min(d_e, c_e, [U_j − x_j]_+/η_e)` — i.e. over **the same set**;
- both exhaust the budget: C3's water-filling delivers
  `Σ q = min(A_i, Σ caps)`, which is the **maximum** attainable total, and
  `C5a` stage 2 maximizes exactly that total.

Hence `C5a` and C3 agree on the **admissible set** and on **total service**, and
differ only in the **shape** chosen on the tied face: C3 takes the max-min-fair
point, `C5a` takes whatever the declared residual tie rule (N-5) selects. ∎

**Report, corrected: agreement is NOT equivalence.**

**d-8 establishes exactly two things** under its hypotheses (in-band baseline,
`α,β > 0`, `R ≤ L`, `C_a ≡ 0`, `u = 0`, `P_i ≤ L_i`): `C5a` and C3 agree on the
**admissible set**, and on the **maximum immediate service** `min(A_i, Σ caps)`.

**It does not establish that they are the same controller.** Controller
equivalence requires the **selected vectors to match across the relevant
domain**, including permission handling, allocation, tie-breaking and rest. Here
they demonstrably need not match: C3 selects the **unique max-min-fair
(water-filling)** point of the service-maximal set, whereas `C5a` selects
whatever the declared residual tie rule (N-5) picks. Both are service-maximal;
they are generally **different points**. Different points mean different
successor states, hence different later feasible sets and later service — so the
difference is not confined to one tick.

**Therefore `C5a` is NOT discarded as a duplicate.** The previous revision's
"probable duplicate, not recommended" verdict is **withdrawn**: it asserted an
equivalence that was never established.

**But the converse warning is equally binding.** If the *only* difference
between `C5a` and C3 is the residual tie rule, then that difference must **not
be attributed to graded EBU valuation.** By **d-12**, from an all-in-band
baseline `C5a`'s stage 1 is a binary band-feasibility screen carrying no graded
ranking, and stage 2 is service-maximisation — so on that baseline the EBU
functional contributes *nothing* beyond the screen that C3 imposes by
construction, and any observed difference is a **tie-rule artifact**. Reporting
it as an EBU effect would be a false attribution.

**To establish equivalence or distinctness properly**, the author would have to
either (a) fix N-5 to water-filling, in which case `C5a` and C3 select
identically on this baseline and equivalence *would* be established there; or
(b) declare a different N-5 and report the resulting difference **as a tie-rule
difference**; or (c) move to a baseline with `V_A(z) > 0`, where `F_G` is
genuinely graded and the two policies can differ for a reason attributable to
the field. Options for a material distinction:

- a baseline with `V_A(z) > 0` — `C5a` then ranks **burden reduction** while C3
  ranks reserve-deficit-then-band-deficit lexicographically by water-filling;
  these can disagree on genuinely field-driven grounds;
- `P_i > L_i`, so the common provider floor binds before C3's voluntary floor
  and the admissible sets diverge;
- `α_i = 0` or `β_i = 0` for some node, so `Z_V` exceeds the band (d-5) and the
  sets diverge;
- `C_a ≢ 0`, which changes `C5a`'s stage-1 comparison but not C3's rule at all.

# 7. Scope and comparison integrity

## 7.1 Identical treatment across arms

All arms use **identical** opportunity-generation rules (§2.2), **identical**
initial conditions, and the **same replayed external demand** (one
`DemandSchedule`, generated once). Their later stocks and therefore their later
feasible quantities **will** differ, because their decisions differ — that is
the intended content of the comparison and not an asymmetry. Any information
added for permission (option (i)'s `B_i`) is added to the **common context** for
every arm.

## 7.2 `C_a ≡ 0` is a declared candidate assumption, and it is load-bearing

`C_a ≡ 0` is retained **only** as a clearly identified candidate assumption,
justified by the idealized scope design §11 states: additional physical
transformations should appear as their own atomic actions rather than hidden in
another action's generic penalty, and labour, monetary, transaction, transport
and generic "effort" terms are forbidden inside `C_a`.

**Why it is load-bearing — and for which policies.**
Definition 6.13a permits a fixed activation cost: `C_a(0) = 0`,
`C_a(q) = c₀ + C_cont(q)` for `q > 0`, `c₀ > 0`.

**Draft derivation d-14.** At an all-in-band baseline `V_A(z) = 0`, so
`F_G(q) ≤ 0` for every `q` (d-6). With strictly positive process burden for
every nonzero action, `ΔE_G(q) = F_G(q) − C_G(q) ≤ −c₀ < 0` for all `q ≠ 0`,
while `ΔE_G(0) = 0`. Hence:

- **`C5a`, and any policy that refuses negative net EBU, selects rest** —
  inactivity follows, the Finding-1 degeneracy reached through the cost term;
- **`C5b` does NOT follow.** Service-first maximises `S` at stage 1, where net
  EBU is not consulted, so it still selects a service-maximal vector and merely
  records `ΔE_G < 0`. **Inactivity is not automatic for service-first
  selection.** ∎

Additionally `ΔE_G` is **discontinuous at `0⁺`** (a downward jump of `c₀`), so
d-3's concavity argument no longer covers the closed set `Q_i`; it survives on
`{q ≠ 0}` only when `C_cont` is convex and anchored.

**Neither direction of manipulation is taken.** `C_a` is not removed to obtain
neutral quotes, and no burden is invented to distinguish controllers. Whether
`c₀ = 0` stands is an author decision (§8, decision 3).

## 7.3 Programme scope kept visible

This is a **first conservative-world** candidate: closed, lossless, `u = 0`, no
regeneration. It does **not** answer, and must not be read as answering, the
programme's **regeneration** or **exogenous-disturbance** questions. Those
remain separate scope with their own identity requirements — a regenerative
plant would need a new study identity, and a disturbance would need declared
conservation or boundary accounting and independence from controller and field.

| **published common feasible cap** | the aggregate `B_i = [x_i − P_i]_+`, computed in committed **event 2** and published to every arm **before** proposal in event 3. **No committed event-order amendment is required** (d-8a); only this packet's own `OPPORTUNITY_INVARIANTS` item 7 changes |
| **selection domain** | `Q_i = {q ≥ 0 : q_e ≤ c_e, Σ_e q_e ≤ B_i}` — the arm optimises **exactly what will execute** (architecture (i), §3.6.5) |
| **authoritative final validation** | a separate authoritative step **after** selection: (1) joint hard feasibility on the **joint successor** against the same frozen baseline; (2) aggregate conservation closure against an **explicitly declared** tolerance; (3) configuration/state provenance match. It **reports or refuses** a mismatch — it does **not** rescale the selected vector to invent a repair. EBU plays **no part** in it: **exact EBU evaluation is part of the controller's selection; it does not create physical permission** |
| **topology / frozen-state assumptions** | **in-degree `deg⁻(j) ≤ 1`** (configuration-level restriction) and **frozen-state caps** for the whole tick. These are exactly the hypotheses d-8b and d-13 rest on; **they are not generalised** to contested destinations, and exports are **not** financed from uncommitted incoming transfers |
| **execution guarantee** | under the two hypotheses above, the selected vector is jointly feasible and **executes unchanged** (d-8b) |
| **provider floor `P_i`** | see §8.0.1 |

### 8.0.1 The provider floor `P_i` — recommended value, for explicit approval

`P_i` is the **declared non-mobilisable stock quantity** at node `i`, in
**stock units** (not a fraction — a fraction would need a separate `φ_i ∈ [0,1]`
and an explicit conversion `P_i = φ_i·K_i`). It enters only through
`B_i = [x_i − P_i]_+`.

**It is semantically distinct from all three neighbouring quantities, and no
numerical coincidence is assumed:**

| quantity | what it is |
|---|---|
| `P_i` | **provider/permission floor** — stock that cannot be mobilised for export at all |
| `R_eff` | committed P1C **export floor** used by `robust_budget` — a *rate-layer* input's stock term, not this |
| `R_i` | **homeostatic reserve coordinate** in `v_i` — a *valuation* boundary, not a permission one |
| `L_i` | **lower band edge** — a valuation boundary; C3's `A_i = [x_i − L_i]_+` uses it |

> **Recommendation, stated explicitly for author approval and NOT silently
> adopted: `P_i = 0`.**
>
> **Ground:** this study's resource is an **abstract homogeneous scalar with no
> declared physical embodiment** (§A of the resource-model note). A positive
> non-mobilisable quantity is a **fact about a plant** — dead volume, bound
> fraction, minimum wetted level. This world declares no plant, so **no
> positive floor is derivable**, and inventing one would be authoring a
> physical fact to fill a slot. `P_i = 0` is the **simplest appropriate
> candidate**, not a default chosen for convenience.
>
> **Consequences of `P_i = 0`, stated so the choice is informed:** permission
> reduces to hard feasibility (`B_i = x_i`); C3 remains distinct from the
> service-maximisers through `A_i` alone; and since `A_i ≤ B_i` holds **iff
> `L_i ≥ P_i`**, at `P_i = 0` C3's withholding is **unconditional**.
>
> **What would justify `P_i > 0`:** a declared physical embodiment, with the
> floor read off it. **Choosing a positive floor to manufacture a contrast
> between controllers is not a valid ground** and is explicitly rejected.

## 8.1 The EBU candidate — `C5b`

**Identifier:** `C5b-demand-driven-exact-EBU-service-first`, a **new,
separately identified candidate arm**.

**Decision law**, in exactly three stages over `q ∈ Q_i` at the frozen state:

```
stage 1   M_i   =  argmax_{q ∈ Q_i}  S(q)          maximum feasible immediate service
stage 2   N_i   =  argmax_{q ∈ M_i}  F_G(q)        maximum exact local finite field value
stage 3   q     =  T(N_i)                          declared deterministic residual selection
```

with `F_G(q) = V_A(z) − V_A(T_G(z,q))` computed **from the vector**, never
assembled from per-edge quotes (d-1, d-2), and `S(q) = Σ_e η_e q_e` measured
destination-side (`= Σ_e q_e` at `η = 1`; the interchange is licensed only by a
**common `η`** — see the scope box after d-11).

**Process burden:** `C_a ≡ 0`, carried as a **declared candidate assumption for
this idealized scope**, *not* as a universal physical fact and *not* as a
finding that performing an action is costless (§7.2, d-14).

### 8.1.1 What this policy does NOT optimize — stated plainly

- **It does not sacrifice immediate service for future viability.** Service is
  lexicographically **first**: `C5b` will accept a **negative** `ΔE_G` whenever
  every service-maximal vector adds burden, choosing only the *least* negative.
  It is not a homeostasis-preserving policy and must not be described as one.
- **It does not maximize the complete simultaneous multi-source event's
  value.** `F_G` is the **source-local** value at a frozen baseline.
  Simultaneous quotes are **not additive** (d-2), so local maximisation carries
  no global optimality claim.
- **It does not optimize long-run anything.** Stages 1–2 are **same-tick**
  quantities. No sustained service, recovery, potential descent or long-run
  homeostasis follows.
- **The field criterion is often inoperative.** At fixed total export the source
  term is constant, so stage 2 discriminates only where some destination's
  burden is non-flat over the **reachable** allocations (d-11, d-12) — which is
  precisely why §8.4's reporting is not optional.

## 8.2 Comparator roles — four distinct objects

**These are not interchangeable, and C2 is not silently replaced.**

| role | object | purpose | status |
|---|---|---|---|
| **existing C2** | its own declared accepted-vector rule, scaling by its own `x_i` | an **existing arm**, unchanged | **definition untouched**. It equals `q_ref` **only** in the degenerate singleton case (§4A.5); where the budget binds it is either infeasible at `P_i > 0` or a different service-maximal point |
| **existing C3** | `A_i = [x_i − L_i]_+`, three-stage reserve-and-band-aware | an **existing arm**, unchanged | **not a service-maximal comparator** and must not be read as one (§7). Water-filling point of its own admissible set |
| **matched no-field reference** | `q_ref = T(M_i)` — same `Q_i`, same frozen state, same `T`, **stage 2 deleted** | isolates *field influence* from *tie-rule effect*: it differs from `q_EBU` **only** by which set `T` is applied to | a **same-state diagnostic calculation**, computed alongside every `C5b` decision. **Not an arm.** Not C2 |
| **other proposed arms** | `C5a` (zero-set / band-feasibility screen); `C4` | `C5a` tests a **binary** band-feasibility screen, not a graded valuation, on the in-band baseline (d-12); `C4` retained as a definition | **retained as definitions.** **Inclusion in the eventual arm set is a design decision, not an automatic consequence of retaining their code or analysis** |

### 8.2.1 Should the matched reference eventually become a real comparison arm?

> **Recommendation: yes — eventually, as a separately evolving arm, and NOT in
> place of the same-state diagnostic.** Both are needed; they answer different
> questions. **Not launched, registered or implemented by this packet.**

The reason is a genuine limitation of the diagnostic, and it must not be
papered over:

> **A same-state reference calculation cannot establish its own alternative
> long-run trajectory.** `q_ref` is evaluated at the **state `C5b` actually
> reached**. It answers "at this state, would deleting the field stage have
> changed this decision?" It does **not** answer "where would a no-field
> controller have ended up?", because a no-field controller would have visited
> a **different sequence of states** from the first tick at which the two
> diverged. Summing or counting same-state differences along `C5b`'s own
> trajectory is **not** a counterfactual trajectory.

So: keep the diagnostic (it is the only thing that separates a field effect
from a tie-rule artifact), and, **if a long-run claim about the field's
contribution is ever wanted**, run the reference as its own arm evolving under
its own decisions. **Which of the two a given claim rests on must be stated.**

## 8.3 The residual selection rule `T` — one concrete recommendation

> **Recommended `T`: the lexicographically greatest admissible vector, with
> coordinates ordered by destination identifier ascending.**

**Full deterministic statement** (no step is left to convention). Given a
non-empty compact admissible set `X ⊆ ℝ^m` and the source's out-edges
`e_1, …, e_m` ordered by destination id ascending:

```
X_0 = X
for k = 1 … m:
    q*_k = max { q_k : q ∈ X_{k−1} }
    X_k  = { q ∈ X_{k−1} : q_k = q*_k }
T(X) = the unique element of X_m
```

i.e. **greedily fill the lowest-id destination to its maximum, then the next,
and so on.**

- **All ties are resolved.** Each `max` is attained (`X_{k−1}` compact
  non-empty), each `X_k` is compact non-empty, and after `m` steps every
  coordinate is pinned, so `X_m` is a **singleton**. **No residual tie-break
  convention is needed, and none is left implicit.** This holds for both uses:
  `M_i` is a compact polytope, and `argmax_{M_i} F_G` is compact non-empty
  because `F_G` is concave and continuous.
- **Restriction consistency (Sen's α) holds** — required by §4A.4 and proved
  for any `T` that uniquely maximises a fixed order (**d-15**). This is what
  makes `q_EBU ≠ q_ref` interpretable: without it, a changed vector could arise
  purely from applying `T` to a smaller set.
- **Field-independent** — `T` never reads `F_G`, `μ`, or any potential weight.

### 8.3.1 Disclosed: this rule is identifier-dependent

**Relabelling the nodes can change the selected vector.** The rule is a
function of the **identifier order**, which is an artifact of how the world was
written down, not a physical property.

**It must therefore not be described as fair, neutral, label-invariant or
symmetric. It is none of those.** Its virtues are narrower and sufficient for
the purpose: it is **deterministic, declared in advance, field-independent and
α-consistent**. Because stage 3 acts **only** after service and field are both
exhausted, identifier dependence affects only decisions the two prior stages
left genuinely tied — which is exactly the population §8.4 counts and reports.

**No tie rule is adopted by this task.** An author who prefers a different `T`
need only keep the four properties above; note that **setting `T` to
water-filling would make `C5a` and C3 select identically on the in-band
baseline — establishing that equivalence rather than assuming it** (d-8, 0.5).

## 8.4 Decision-influence reporting — carried forward unchanged

The construction of §4A is **retained as an integral part of the design**, at
the same frozen state, over the same `Q_i`, with the same `T`:

```
M_i    = argmax_{q ∈ Q_i} S(q)
q_ref  = T(M_i)
q_EBU  = T(argmax_{q ∈ M_i} F_G(q))
```

The five outcomes stay **distinct**, because each supports a different claim:

| case | condition | what it shows |
|---|---|---|
| **(a)** | `\|M_i\| = 1` | the field had **no choice** — evidence for nothing either way |
| **(b)** | multiple choices, `F_G` **constant** on `M_i` | the valuation is **indifferent** here — a genuine **negative finding** about its resolution |
| **(c)** | `F_G` non-constant but `q_ref` already maximal | **agreement**, not absence of opportunity |
| **(d)** | `q_EBU ≠ q_ref` | a **genuinely changed choice**, necessarily with **strictly positive** local advantage (d-16) |
| **(e)** | range not certified | **unresolved** — its own category, never merged into "no effect" |

**Statuses stay explicit: exact / certified-flat / unresolved.** The range is
obtainable **exactly** (concave max attained; concave min attained at a
**vertex**), and a cheap **sufficient** flatness certificate needs no
optimisation. **No numerical tolerance is invented here** — the equality rule is
a preregistration item, deliberately NOT on the adoption sheet (§8.5.1).

**Interpretation limits, restated because they are easy to violate:**

- **A positive local field advantage is not evidence of improved long-run
  service or homeostasis.** It is the definitional gap between two maxima at
  one state.
- **Overlapping source-local advantages must not be summed and called realised
  global improvement.** `F_G` values at a frozen baseline are not additive
  across sources (d-2), and the realised multi-source event value is a
  different object.
- Counts are reported **with denominators**, with **no minimum activation
  threshold**, no post-hoc discarding, and **a zero changed-choice count is a
  result, not an inconclusive run**.

## 8.5 Author decision sheet — architecture adoption

**Eight decisions. All are architecture/comparison-design choices. None
selects a number.** Numerical preregistration is a **separate, later** stage
(§8.6). Settled first-study scope (§1) is **not** reopened, and **no
loss-aware question appears here** — none of them blocks this design.

---

**D1 — Publish the aggregate cap `B_i` to every arm (architecture (i)).**
*Recommendation:* **adopt.**
*Why it matters:* it makes the arm optimise **exactly what executes**, so the
selected value is the accepted value.
*If rejected:* arms optimise `Q_i^open` (bounded by own stock only); the
resolver may then bind, so selection value ≠ accepted value. d-10 bounds
sign-flips but **not** optimality.
*Adopting authorizes:* amending **this packet's own** `OPPORTUNITY_INVARIANTS`
item 7. **It does not** amend committed event ordering — event 2 already
computes budgets before event 3 (d-8a) — and does not adopt any budget law.

**D2 — Set the provider floor `P_i = 0`.**
*Recommendation:* **adopt** (§8.0.1).
*Why it matters:* `P_i` is the only permission parameter in the design; a
positive value is a claim about a **plant this world does not declare**.
*If rejected:* a positive `P_i` requires a stated physical reading; note
`A_i ≤ B_i` then holds **iff `L_i ≥ P_i`**, so C3's withholding stops being
unconditional.
*Adopting authorizes:* computing `B_i = x_i`. **It does not** establish that
no physical floor exists in any world, equate `P_i` with `R_eff`, `R_i` or
`L_i`, or license choosing a floor to separate controllers.

**D3 — Declare `C_a ≡ 0` for this idealized scope.**
*Recommendation:* **adopt as a declared candidate assumption.**
*Why it matters:* it is what makes both lexicographic maxima exist (d-3) and
keeps the study about the **field**, not about an activation parameter.
*If rejected:* a fixed `c₀ > 0` makes `C5a` and every negative-refusing policy
inactive **at a zero-potential baseline** (d-14 — which does **not** extend to
`V_A(z) > 0`); `C5b` still acts; concavity survives only off `0`.
*Adopting authorizes:* omitting a process-burden term from these fixtures.
**It does not** assert that action is physically costless, prohibit declared
process burdens generally, or touch the **unresolved** Definition 6.4
classification — which is identically inert at `η = 1` (resource-model note
§D.4.5).

**D4 — Run `C5b` on the declared in-band baseline.**
*Recommendation:* **adopt.**
*Why it matters:* it is the baseline on which the service-first law has graded
content.
*If rejected:* `C5a` on that baseline tests a **binary band-feasibility
screen**, not a graded valuation (d-12). Giving `C5a` graded content needs
`V_A(z) > 0` — a **different study**, belonging to the separate perturbation
question.
*Adopting authorizes:* `C5b` as the EBU arm of this study. **It does not**
accept `C5b`, freeze it, or decide the full arm set (D7).

**D5 — Adopt `T` = lexicographically greatest, destination id ascending.**
*Recommendation:* **adopt**, with §8.3.1's disclosure recorded.
*Why it matters:* `T` must be deterministic, declared in advance,
field-independent and **α-consistent** (d-15), or `q_EBU ≠ q_ref` is
uninterpretable.
*If rejected:* any replacement must keep those four properties. A
**non-α-consistent** `T` permits a changed vector with **zero** advantage — a
set-dependent artifact indistinguishable from a field effect. Choosing
water-filling instead would **establish** `C5a` ≡ C3 on this baseline rather
than assume it.
*Adopting authorizes:* a fully determined stage 3 with **no residual ties**.
**It does not** make the rule fair, neutral or label-invariant — it is
**identifier-dependent**, and that must be stated wherever results are
reported.

**D6 — Make decision-influence reporting integral, not optional.**
*Recommendation:* **adopt.**
*Why it matters:* the field criterion is **often inoperative** (d-11, d-12), so
without §4A a changed allocation **cannot** be distinguished from a tie-rule
artifact, and cases (a)–(c) collapse together.
*If rejected:* the study cannot interpret its own primary quantity; a zero
changed-choice count would be uninterpretable.
*Adopting authorizes:* recording `q_ref`, `q_EBU`, advantage, range and status
per decision. **It does not** set any tolerance (that is preregistration), and
**does not** license summing local advantages into a global claim.

**D7 — Fix the arm set for this study.**
*Proposed:* `C5b` (EBU arm) + existing **C2** + existing **C3**, with the
matched reference computed as a **same-state diagnostic** alongside `C5b`.
*Recommendation:* **adopt this set**; retain `C4` and `C5a` as **definitions
only**.
*Why it matters:* retaining code or analysis for an arm is **not** a reason to
run it; each arm must earn membership by the question it answers.
*If rejected:* adding `C5a` requires D4's alternative baseline to be
meaningful; adding `C4` requires resolving FINDING-1 (C4 ≡ C0 under an in-band
start).
*Adopting authorizes:* the comparison design's shape. **It does not** accept,
implement, tune or freeze any arm, and **does not** register C5.

**D8 — Eventually run the matched reference as its own evolving arm.**
*Recommendation:* **adopt in principle, schedule later** — and **keep the
same-state diagnostic regardless**; they answer different questions.
*Why it matters:* **a same-state reference cannot establish its own long-run
trajectory** (§8.2.1). Only an independently evolving arm can support a
long-run claim about the field's contribution.
*If rejected:* no long-run claim about field contribution may be made at all —
only same-state decision-influence claims.
*Adopting authorizes:* scheduling that arm in a later study. **It does not**
launch, register or implement it here, and **does not** rename or replace C2.
