# Part 0A — TWO BLOCKING ANALYTICAL FINDINGS (read first)

A design-readiness review found two independent, confirmed problems. **Both
block the study as currently specified.** Full derivations:
`V3.0_DESIGN_READINESS_NOTE_C4_DEGENERACY_AND_P1C_APPLICABILITY.md`.

**FINDING-1 — C4 is behaviourally identical to C0 under the stated initial
condition.** With `L_i ≤ x_i(0) ≤ U_i` and `R_i ≤ L_i`, every branch guard in
the committed marginal is false, so `μ_i = 0` exactly. Then `f_e = 0`, and
`θ_e ≥ 0` gives `J_e = 0`; demand enters C4 only as a cap, so no demand history
can lift it. Zero proposals ⇒ unchanged state ⇒ the same at every subsequent
tick, by induction. C4 delivers zero service in perpetuity. **The fixtures below
do not settle this** — both start outside the band, which is the only reason C4
acts in them.

**FINDING-2 — no permission policy has been adopted for this world.**
`p1c_v29._source_budget` (the complete dispatch, not `robust_budget` alone)
gives budget **0** for `finite` and `irreversible` stock sources and for States
R and I; the robust budget is the **regenerative** State-P branch alone, as its
own docstring says. This world declares no regeneration, so every honest typing
yields zero, `σ = 0`, and **every arm** becomes identical to C0.

Two precisions, correcting an earlier over-reading:

- **Gate-2.1B Theorem 4.1 is PROVED** (full algebra, review §4.1) — an earlier
  revision called it "numerically validated, not proved"; that phrase in
  `p1c_v29.py` refers to *implementation conformance*, not the theorem.
- **The obstacle is the adopted dispatch, not mathematics.** For a `finite`
  source with `x > R_eff` and feasibility (A8), Theorem 4.1 would permit a
  positive one-step-safe export; review §6.4 confirms the reserve is preserved

  choice in force, not a proof that positive export is unsafe for one tick.

**FINDING-3 — "EBU controller" is not one thing.** Committed sources separate
field force, automatic flux, externally motivated finite requests, physical
permission, exact finite EBU evaluation (the quote), action selection/sizing,
and post-resolution attribution. A **registered finite-action EBU selection

too, for a *different* reason than FINDING-1. The remedy needs two named policy
choices: a request-generation rule at event 3, and an acceptance threshold that
admits neutral quotes.

# Part 0 — Correction notice (this revision)

This revision corrects **two** errors and every claim that depended on them.
Both are recorded here rather than silently absorbed.

## 0.1 ERROR A — C3's export was bounded by the reserve coordinate

The original C3 draft bounded export by `E_i = [x_i - R_i]_+`. On illustrative
fixture A, with `L_i = 4`, `R_i = 2`, `x_i = 10`, that gave `E_i = 8`, a
proposal of `q = (6, 1)`, total export 7, and therefore

```
x_i' = 10 - 7 = 3     but     L_i = 4,   so   x_i' < L_i.
```

The source was left **below its own lower homeostatic band**. Two claims
followed and are **false**: "every node ends inside its band" (fixture A), and
"on this fixture C3 dominates C4".

## 0.2 ERROR B — `R_eff` was treated as if it implemented `R`

The correction to ERROR A over-corrected. It reasoned that the committed P1C
budget subtracts `R_eff`, therefore "the reserve is protected for every arm",
therefore C3 need not carry reserve logic at all — and removed it.

**That inference was false.** `R_eff` and `R` are different quantities:

| | `R_eff` | `R` |
|---|---|---|
| what it is | **provider / export floor** | **homeostatic reserve coordinate** |
| where it lives | `p1c_v29.SourceConfig.R_eff` | `NodeSpec.reserve` |
| what it bounds | what a source may **send** | a node's **own stock** condition |
| who uses it | the common resolver, via the robust budget | the committed potential's `chi[R - x]_+^2` branch, and eligible controllers |
| layer | rate layer until converted | quantity |

`R_eff` **does not implement** `R` at any node. In particular **nothing in the
resolver moves resource toward a destination below its `R`** — the resolver
only ever *narrows* what a source sends. A destination sitting below its
homeostatic reserve is invisible to the provider layer entirely.

So removing reserve awareness from C3 did not delegate it — it **deleted** it.
Nothing in the pipeline was left protecting the homeostatic reserve condition.

`world.RESERVE_CONCEPTS` now declares both concepts and their **absence** of
relationship, and `world.require_reserve_concepts_distinct` refuses a statement
that asserts the conflation — while still permitting a correction notice such
as this one to **quote** the refuted claim in order to retract it.

## 0.3 "Dominates" remains withdrawn as a category

Dominance is a relation over a registered metric set, and **slot S-M is
unfilled**. Absent a registered metric set, "A dominates B" is not a wrong
answer; it is a question that has not been posed. Every fixture reports its
observable dimensions **separately, with no aggregate**: `FixtureOutcome`
carries one field per dimension and **no** score, rank, winner or aggregate
field, and a check asserts no such field can exist.

## 0.4 What this revision changed

| Area | Change |
|---|---|
| `R_eff` vs `R` | declared distinct in code, docs and tests; a guard refuses the conflation |
| C3's structure | two-stage band-aware → **three-stage reserve-and-band-aware** |
| C3's identity | `C3-band-aware` → **`C3-reserve-and-band-aware`** |
| C3's source bound | `A_i = [x_i - L_i]_+` (unchanged — the band, correctly) |
| C3's stage 1 | **new**: destination homeostatic **reserve** deficits `[R_j - x_j]_+` |
| `C3View` | now carries `endpoint_reserve` (`R_j`); still no `α, β, χ, μ, f_e`, and no `R_eff` or budget |
| P1C interaction | **analysed, not assumed** — `σ < 1` is reachable; the ordering is proposal-level only (Part VI.7) |
| Topology restriction | moved to **configuration-time** validation; fails closed before any controller exists |

**Every fixture number is derived by executing the declared symbolic rule.**

## II.4 Notation, with the SIDE each quantity is measured on

`eta_e` is dimensionless, so "source-side" and "destination-side" are not
different *units* — they are different **points of measurement**. At `eta = 1`
they coincide numerically, which is exactly why the distinction must be
declared rather than inferred from the arithmetic. Machine-readable:
`world.QUANTITY_SEMANTICS`.

| Symbol | Meaning | Kind / side |
|---|---|---|
| `i`, `j` | source node, destination node; `e = (i,j)` an out-edge of `i` | — |
| `x_i` | current stock at node `i` | quantity |
| `K_i`, `L_i`, `U_i` | hard capacity; declared lower/upper homeostatic band | quantity |
| `R_i`, `R_j` | **homeostatic reserve coordinate** (`NodeSpec.reserve`) | quantity |
| `R_eff` | **provider / export reserve floor** (`p1c_v29`). **Not `R`**, and it does not implement `R`. Available only to a **regenerative** State-P source — see FINDING-2 | **stock quantity** (same units as `x`). The *budget* is a rate because the formula divides by `Δt`; `R_eff` itself is never a rate |
| `q_e` | transfer quantity for the current tick | **source-side sent** |
| `d_e` | demand revealed on edge `e` at tick `t` | **source-side requested transfer** |
| `D_e` | destination-side *delivered* demand — **not used** by this study; declared so a future lossy study cannot silently reuse `d_e` for it. Conversion: `d_e = D_e / eta_e` | destination-side |
| `c_e` | the common per-edge opportunity cap | **source-side** |
| `A_i` | C3's band-safe source budget `[x_i - L_i]_+` | **source-side** |
| `B_i^(k)` | C3's stage-`k` budget (Part IV.C3) | **source-side** |
| `requested / permitted / accepted / measured` | `QuantityLadder` stages; the provider and resolver only narrow them | **source-side** |
| `delivered` | `eta_e * accepted` — the only ladder stage measured at the destination | **destination-side** |
| destination stock increment | `eta_e * q_e` | destination-side |
| source stock increment | `-q_e` — the source loses the **full** sent quantity | source-side |
| `f_e`, `J_e` | local force `mu_i - eta_e mu_j`; Onsager flux `M_e [f_e - theta_e]_+` | **rate** |
| `B_i` | the source's export budget — **never visible to any controller** | source-side quantity |
| `sigma_i` | `min(1, B_i / sum_e q_e^req)`, the resolver's proportional scale | dimensionless |
| `eta_e` | transfer efficiency. **`eta_e = 1` is a PROSPECTIVE FIRST-STUDY RESTRICTION**, not a universal EBU assumption | dimensionless |

A division by `eta_e` converts a **destination-side shortfall** into the
**source-side quantity** that closes it. That is the efficiency correction, not
a unit change — which is why C3's caps read `[R_j - x_j]_+ / eta_e` and not
`[R_j - x_j]_+`.

### II.4.1 Rates and quantities are never mixed

The committed layers speak in **rates**: `d0_v29.edge_flux` returns a flux
`J_e`, and `p1c_v29.robust_budget` returns
`[ (x - eps_x) + dt(u - eps_u) - R_eff ]_+ / dt`, **also a rate**. Stocks,
demand events and every `QuantityLadder` stage are finite **quantities**. The
only sanctioned conversions are

```
q_e  =  dt * J_e            world.tick_quantity_from_rate
J_e  =  q_e / dt            world.rate_from_tick_quantity
```

`world.resolve_shared_source` consumes a **quantity**. A caller wiring
`p1c_v29.robust_budget` to it **must convert first**; passing the rate straight
through is a unit error that is **invisible at `dt = 1`**. That is why the
conversion is a named function and why the suite checks it at
`dt ∈ {0.5, 2.0, 0.25}` — three non-unit values where rate and quantity
provably differ — and not only at `dt = 1`.

For this prospective conservative plant `u = 0`, so `A_i = [x_i - L_i]_+` is
meaningful directly. **A later study with autonomous drift `u != 0` must not
silently reuse it**: C3 would have to be re-derived from the authoritative
no-action-successor baseline. Recorded in C3's preregistration list.

### II.4.2 Prospective first-study domain restrictions

Three restrictions are validated when the **candidate world configuration is
constructed** — before demand, before controller construction, before any tick
(`cc.validate_study_configuration`, called by `build_common_context`). Each is
**a prospective first-study domain restriction: not a universal EBU theorem,
not a claim about future worlds, and not yet a frozen preregistration
parameter.** None fixes a numeric value.

| Restriction | Why | Fails closed at |
|---|---|---|
| `deg⁻(j) ≤ 1` for every node eligible to receive | no committed authority defines a destination-side allocation rule, and a per-source band claim cannot be supported under multi-source contention | configuration validation |
| `0 ≤ R ≤ L ≤ U ≤ K` per node | **committed authority does NOT guarantee it** — `NodeSpec` requires only `lower ≤ upper` and each boundary in `[0, K]`, so `R > L` is constructible and would make "reserve emergency before lower-band deficit" incoherent | configuration validation |
| `eta = 1`, no loss sink | the study is declared conservative | configuration validation |

`R_eff` is **deliberately absent** from the boundary ordering: it is a
provider/export floor, not a homeostatic boundary of the node.

A violating topology **fails during configuration validation** — it does not
survive to `apply_joint` and become an `INVALID` run, which would mis-attribute
a configuration error to a controller's outcome.

# Part IV — Controller decision packets

## IV.0 One common context, five typed projections

Blocking gaps G-1 and G-2 are closed by **one immutable `CommonLocalContext`**,
built by `build_common_context(spec, state, source, tick, schedule)` — which
takes **no controller and no arm label**. It carries the frozen state, the
topology, this tick's demand reveal, the node specifications, the edge
specifications, the common opportunity set and the physical epoch, plus both
digests.

The common context **is not the controller API**. Arms receive **typed
projections** derived from it, and undeclared fields are **structurally
absent** — there is no attribute to read, and `__getattr__` refuses rather than
letting a rule quietly catch an `AttributeError`.

Three different things are recorded separately (`information_ledger()`):

| Concept | Where |
|---|---|
| 1. data **present** in `CommonLocalContext` | `CONTEXT_CONTENTS` |
| 2. data **exposed** by each typed view | read off the dataclass fields themselves |
| 3. data **consumed** by each candidate formula | `FORMULA_CONSUMPTION` |

Collapsing them is how an informational asymmetry hides: "available but unused"
is indistinguishable, in a declaration, from "silently read".

| View | Exposes | Structurally absent |
|---|---|---|
| `C0View` | `tick`, `source`, `out_edges` | every physical quantity |
| `C1View` | + `source_stock`, `demand_here`, `edge_caps`, `source_cap` | neighbour state, specs, edge params |
| `C2View` | **identical fields to `C1View`** | neighbour state, specs, edge params |
| `C3View` | + `source_lower`, `endpoint_stocks`, `endpoint_reserve` (`R_j`), `endpoint_lower`, `endpoint_upper`, `eta`, `dt` | `alpha`, `beta`, `chi`, `mu`, `f_e`, `M_e`, `theta_e`, **`R_eff`**, the provider budget, and its own `R_i` |
| `C4View` | + `source_spec`, `endpoint_specs`, `edge_specs` | `global_V`, future demand, oracle, other arms |

`C1View` and `C2View` having identical fields is the point: **C1 and C2 differ
in what they do with the same information, never in what they receive.**

**No data reaches C4 through a private side channel.** The endpoint
specifications C4 needs are on the *common* context, and C3's projection draws
its band edges from that same object. Declaring these schema fields is **not**
selecting parameters: `EdgeSpec` has no default for `M_e` or `theta_e`, and
`WorldSpec.edge_spec` / `build_common_context` refuse rather than defaulting.

## C1 — local greedy

**1. Formula**

```
D_i(t) = { e in out(i) : d_e(t) > 0 },    n_i(t) = |D_i(t)|
q_e^req = min( d_e(t),  x_i / n_i(t),  c_e )      for e in D_i(t),  else 0
```

**2. Information** — `C1View`: own stock, this tick's demand, the common caps.
No neighbour stock, no band, no reserve, no weight, no edge parameter.

**3. Logic** — no ranking; equal split of `x_i`; it never compares edges
against each other, which is exactly what distinguishes it from C2.

**4. Ties** — the equal share is symmetric across `D_i(t)`, so the rule is
invariant to edge ordering. Residual ordering, where ever needed: **destination
node id ascending** — the same key all five arms declare.

**5. No feasible action** — empty map; no fallback, no retry.

**6. Use of inputs** — `L`, `U`, `R`, `mu`, `f_e`: not read. Demand: this tick
only, as a per-edge bound. Neighbour state: not read.

**7. Common resolver** — proposes only; never sees `B_i` or `sigma`.

**11. Configuration** — the share rule (equal split of the full stock, drafted;
an equal split of a band-safe quantity would make C1 a weak C3 and is **not**
drafted); whether `n_i` counts all out-edges or only those with `d_e > 0`; the
residual/rounding rule; the tie-break key.

## C2 — myopic service

**1. Formula** — under Q-3's resolution the common cap `c_e` already carries
both the demand bound and the destination hard headroom, so C2 reduces to

```
q_e^req  =  c_e * min( 1,  x_i / sum_{e'} c_{e'} )
```

i.e. ask for the whole opportunity, scaled proportionally if the source cannot
cover it. No band, no reserve, no field, no lookahead.

**2. Information** — `C2View`: **identical fields to `C1View`**.

**3. Logic** — accept every positive opportunity, size at its cap, scale down
proportionally. Nothing is rejected for a homeostatic reason.

**4. Ties** — proportional-to-cap scaling is order-invariant by construction.
First-come allocation is explicitly **not** used: it would make the result
depend on edge ordering and would be gameable.

**5. No feasible action** — empty map; the scale factor is defined as 1 when
the denominator is 0, so there is no division-by-zero branch.

**6. Use of inputs** — `L`, `U`, `R`, `mu`, `f_e`: not read. Demand: this tick
only. **Neighbour state: NOT read** — under Q-3 the destination hard headroom
is applied once, for every arm, inside `c_e`, so **no arm gains or loses by
having been coded to rediscover a hard physical law**. (This is a change from
the previous draft, in which C2 read `[K_j - x_j]_+` itself.)

**7. Common resolver** — identical to C1. Because C2 requests the most, it is
the arm most often scaled by `sigma < 1`.

**11. Configuration** — the tie rule among service-optimal vectors
(proportional-to-cap drafted, versus proportional-to-demand or max-min fair);
**Q-3 is resolved**, so C2's remaining choice is only how to distribute within
the common caps; whether service is measured as accepted, delivered or measured
quantity.

**12. Hand-worked examples**

| | Fixture A | Fixture B |
|---|---|---|
| proposal | `(5.4545, 4.5455)` | `(0.5, 2.5)` |
| resolver | `sigma = 0.8` → `(4.3636, 3.6364)` | `sigma = 1/3` → `(0.1667, 0.8333)` |
| post-state | `(2, 7.3636, 18.6364)` | `(2, 3.1667, 1.8333)` |
| delivered | 8 of 12 | 1 of 12 |
| lower-band violations | `i (2 < 4)` | `i`, `j1`, `j2` |
| upper-band violations | `j2 (18.6364 > 16)` | none |
| reserve violations | none | `j2 (1.8333 < 2)` |

*Reading (A).* Same **total** as C1, distributed by cap rather than evenly: C1
and C2 coincide in volume whenever the binding constraint is the source, and
are separated by **shape**.
*Reading (B).* C2 tracks the demand shape (5:1) exactly where C1 split evenly,
so it sends more to the reserve-breaching node than C1 did — but only because
that node *asked* for more. Under mirrored demand it would do the opposite.

**13. Anti-strawman** — yes, and this is the strongest service comparator.
"Meet demand now, as fully as physics allows" is the default objective of most
real dispatch systems. If EBU cannot match it on service, EBU must justify that
on the viability axis — both reported, never merged (design §36).

## C3 — reserve-and-band-aware non-field  *(redrafted; the decisive comparator)*

### The layer separation this draft rests on

```
P1C / provider layer :  protect the PROVIDER / EXPORT FLOOR R_eff.
                        Common to every arm. Does NOT implement R.
C3                   :  voluntarily protect its own lower band L_i, and serve
                        destination homeostatic RESERVE and BAND deficits.
C4                   :  use the graded EBU marginal / force field.
```

C1 and C2 benefit from the common provider protection even though their own
laws contain no export reasoning — **that is shared physical/provider safety,
not unfairness**. But the provider layer protects **export permission**, not
any node's homeostatic reserve condition, and **nothing in the resolver moves
resource toward a destination below its `R`**. So C3 must carry `R_j` itself;
otherwise nothing in the pipeline protects it. That is the correction of
ERROR B (Part 0.2).

**1. Exact symbolic decision formula.** Every symbol is a finite **source-side
quantity** for the current tick; `d_e` is source-side requested transfer; a
division by `eta_e` converts a destination-side shortfall into the source-side
quantity that closes it.

```
SOURCE-SIDE BAND-SAFE BUDGET
    A_i = [ x_i - L_i ]_+                     (voluntary; before P1C)

STAGE BUDGETS, recursively
    B_i^(1) = A_i
    B_i^(2) = [ A_i - sum_e q_e^(1) ]_+
    B_i^(3) = [ A_i - sum_e q_e^(1) - sum_e q_e^(2) ]_+

STAGE 1 - destination homeostatic RESERVE emergencies
    r_e = min( d_e ,  c_e ,  [R_j - x_j]_+ / eta_e )
    q^(1) = W( B_i^(1) ; r )

STAGE 2 - remaining destination LOWER-BAND deficits
    l_e = min( d_e - q_e^(1) ,  c_e - q_e^(1) ,
               [L_j - x_j - eta_e q_e^(1)]_+ / eta_e )
    q^(2) = W( B_i^(2) ; l )

STAGE 3 - ordinary service inside the destination UPPER band
    h_e = min( d_e - q_e^(1) - q_e^(2) ,  c_e - q_e^(1) - q_e^(2) ,
               [U_j - x_j - eta_e(q_e^(1) + q_e^(2))]_+ / eta_e )
    q^(3) = W( B_i^(3) ; h )

PROPOSAL
    q_e^C3 = q_e^(1) + q_e^(2) + q_e^(3) ,    sum_e q_e^C3 <= A_i
```

### The water-filling operator `W`, completely specified

```
W_e(B; b) = min(b_e, lambda)   where   sum_e min(b_e, lambda) = min( B, sum_e b_e )
```

`lambda` is computed in **closed form** from the sorted cap multiset — never by
search, bisection or iteration to a tolerance.

| case | result | why |
|---|---|---|
| `B = 0` | every edge `0` | the level solves `m·lambda = 0`, so `lambda = 0` |
| empty edge set | `{}` | `sum_e b_e = 0 ≤ B`, the saturating branch, vacuously |
| all caps `0` | every edge `0` | `sum_e b_e = 0 ≤ B`, each edge gets its cap, which is `0` |
| `B ≥ sum_e b_e` | every edge its full cap | `lambda = +inf`; nothing is withheld |
| `B < sum_e b_e` | `min(b_e, lambda)`, `lambda` unique | the strictly binding case |

**Order independence is a property of the continuous rule, not of the
implementation.** `W` is a symmetric function of the cap **multiset**, so equal
caps receive equal quantities and any permutation of the edges gives the
identical allocation. Nothing in the continuous rule consults an edge
identifier.

**Finite-precision / discrete residuals.** In exact arithmetic the allocation
already sums to `min(B, sum_e b_e)` and **no residual exists**. A residual can
arise only if a caller rounds or discretises afterwards. Such a caller settles
it by **destination node id ascending**, and that key may **only** move a
residual between edges the continuous rule has **already tied** — it must never
change the continuous allocation. It depends on no EBU quantity, no `mu`, no
`f_e`, no controller outcome and no future information. The implementation
performs no rounding and therefore **reaches no tie-break**.

**Ordering assumptions required.** The lexicographic reading — "reserve
emergency before lower-band deficit" — requires `0 ≤ R_j ≤ L_j ≤ U_j ≤ K_j`,
otherwise the reserve deficit would be the *wider* condition. Committed
authority does **not** guarantee this; it is a prospective first-study domain
restriction validated at configuration time (Part II.4.2). **No numeric value
is invented for `R`, `L`, `U` or `K`.**

**2. Information** — `C3View`: `x_i`, `L_i`; per destination `x_j`, `R_j`,
`L_j`, `U_j`; this tick's demand; the common caps; `eta`, `dt`. It carries
**no** `alpha, beta, chi`, **no** `mu`, **no** `f_e`, **no** edge parameters —
and **no** `R_eff`, no provider budget and not even its own `R_i`. Its own
floor is the band `L_i`; its export permission is the provider's business.

**3. Logic** — three lexicographic passes over one budget, each receiving what
the previous did not spend. Water-filling is the **strong** share rule: an edge
capped below the water level does not forfeit the remainder, it is
redistributed, so C3 exhausts its band-safe budget rather than leaving it
unused.

**4. Ties** — for continuous quantities the rule reaches **no tie-break at
all** (see above).

**5. No feasible action** — if `A_i = 0` all three stage budgets are zero and
C3 proposes the empty map, **however severe the destination deficits it can
see**. A genuine refusal, not a fallback.

**6. Use of inputs**

| | |
|---|---|
| `L` | **read, central.** `L_i` bounds C3's own export; `L_j` sets the stage-2 caps |
| `U` | read, as a stage-3 side condition — **per source only**; see G-4 |
| `R` | **read, central to stage 1.** `[R_j - x_j]_+` is the destination's **homeostatic reserve** deficit. This is `NodeSpec.reserve`, **not** `R_eff` |
| `R_eff` | **not read, and structurally absent.** It is the provider's export floor and is applied after C3 proposes |
| `mu`, `f_e` | **not read**, structurally absent from `C3View` |
| demand | read, this tick only, as a source-side per-edge bound at all three stages |
| neighbouring state | read: `x_j` and the destination's `R_j`, `L_j`, `U_j`, from the same `CommonLocalContext` every arm uses |

**7. Common resolver — IT CAN STILL BIND.** Derived from the formulas, not
assumed. C3 guarantees only `sum_e q_e^C3 ≤ A_i = [x_i - L_i]_+`. The P1C
quantity budget is `[ (x_i - eps_x) + dt(u - eps_u) - R_eff ]_+`, which at
`u = 0` is `[ x_i - eps_x - dt·eps_u - R_eff ]_+`. So `sigma = 1` would be
guaranteed **only if**

```
L_i  >=  R_eff + eps_x + dt * eps_u
```

**and no such ordering is declared** — the boundary restriction orders
`R ≤ L ≤ U ≤ K` and deliberately **excludes** `R_eff`. Therefore:

- `sigma < 1` is reachable, and `q_e^accepted = sigma * q_e^C3`;
- **C3's ordering is a PROPOSAL-LEVEL lexicographic priority**;
- the resolver is **stage-blind** and scales the whole vector proportionally,
  so **a Stage-1 reserve deficit may be left incompletely served while Stage-3
  ordinary service still executes**;
- **the accepted vector is NOT proven lexicographically saturated**, and no
  realised reserve-first or lower-band-first saturation is claimed.

`p1c_binding_demonstration()` exhibits exactly this, `ILLUSTRATIVE_FIXTURE_ONLY`:
with `R_eff = 9 > L_i = 4`, `A_i = 10`,
proposal total `10` against budget `5`
gives `sigma = 0.5`. j1 needed `6`
to clear its reserve and receives `3` — **still below
`R`** — while j2 still receives `2` of pure
Stage-3 service into a node already inside its band.

> scaling** does to a **supplied** budget. It does **not** establish that any
> positive budget is authorized for this world. Under a faithful reading of
> committed P1C — `_source_budget`, not `robust_budget`'s arithmetic alone —
> this world's sources type as `finite` or `irreversible` and the budget is
> **0**, in which case `σ = 0` and the demonstration's premise (a positive
> budget) does not arise. The `R_eff = 9` figure is an arbitrary illustrative
> stock quantity with **no committed permission basis**, as are the fixture
> budgets `B_i = 8` and `B_i = 1`.

**P1C is NOT modified to preserve C3's preference ordering.** And the common
opportunity layer exposes **no P1C-safe joint cap** before proposal:
`source_cap` is the source's own stock, and invariant 7 keeps the budget
invisible to every arm. C3 therefore cannot pre-clamp to it, and the

**8–10.** As the other arms — identical structural argument.

**11. Configuration to preregister**

- the share rule within each stage: capped max-min water-filling (drafted) vs proportional-to-demand within the stage budget;

- whether any residual/rounding rule is needed at all;
- the domain restrictions this rule assumes: `0 ≤ R ≤ L ≤ U ≤ K` and `deg⁻(j) ≤ 1`, both validated at configuration and neither a universal theorem;
- whether a later world with `u != 0` re-derives `A_i` from the authoritative no-action-successor baseline.

## C4 — EBU local-field

**1. Formula** — the committed local law, reused and not re-derived
(`d0_v29.edge_flux`), with the unit conversion made explicit:

```
mu_i     = -2 alpha [L_i - x_i]_+ + 2 beta [x_i - U_i]_+ - 2 chi [R_i - x_i]_+
f_e      = mu_i - eta_e mu_j
J_e      = M_e [ f_e - theta_e ]_+                          (a RATE)
q_e^req  = min( dt * J_e ,  c_e )                           (a QUANTITY)
           then, if sum_e q_e^req > x_i, scale by x_i / sum_e q_e^req
```

Screening comes **first**; the value only orders and sizes what survives it.

**2. Information** — `C4View`: own stock and full `NodeSpec`; each
destination's stock and full `NodeSpec`; the per-edge `EdgeSpec` (`M_e`,
`theta_e`); this tick's demand; the common caps; `eta`, `dt`. All from the
**common** context.

**3. Logic** — rank by `f_e`; **reject** every edge with `f_e <= theta_e`; size
by `dt * J_e`, clipped to the common cap.

**4. Ties** — deterministic function of the view, so exact ties are
measure-zero; where they occur, destination node id ascending — the same key as
C0–C3.

**5. No feasible action** — if every `f_e <= theta_e`, C4 proposes the empty
map: it declines to move resource that no local burden gradient justifies,
**even where demand exists**. This is a real and frequent case and is the main
mechanism by which C4 can lose on the service axis.

**6. Use of inputs** — `L`, `U`, `R` through the potential (`R` **soft**, a
penalty, not the hard floor); `mu` and `f_e` read and central; demand read this
tick only and used **only as a cap** — C4's sizing does not increase with
demand, a real and deliberate weakness that must be reported; neighbour state
read as `x_j` plus the destination's full `NodeSpec`.

**7. Common resolver** — identical to the other arms. **A consequence the study
must report:** the ranked value is the value of the *accepted* vector, so where
`sigma < 1` the vector C4 reasoned about is not the vector that executes.

**8. No global `V`** — structural, plus: locality here is exact rather than
approximate. `V` is separable (Definition 6.1), so the local marginal needs only
the source, its out-edges and their permitted endpoint views (Lemma 6.6). C4
therefore **loses nothing** by being denied the global sum.

**11. Configuration** — `alpha, beta, chi` per node (S-P); `L, U, R, K` per node
(S-W, S-V); `M_e`, `theta_e` per edge — **G-1's schema is now closed**
(`world.EdgeSpec`, in the spec digest) but **both values remain unfilled**, and
`WorldSpec.edge_spec` refuses rather than defaulting them; `dt`, and the
renormalisation rule; **Q-1 is resolved**, so the flux is capped by
`c_e <= d_e` and what remains preregisterable is only whether a later,
separately registered study of autonomous rebalancing lifts that bound;
resolution of **E3**.

# Part VI — Resolutions, open questions, and blocking gaps

## VI.1 Resolved questions (`RESOLVED_QUESTIONS`)

**Q-1 — RESOLVED: opportunities are demand-triggered and demand-bounded.**
This study asks how local policies decide among the **same externally presented
service opportunities**, so `d_e(t) = 0 => c_e(t) = 0`, and always
`c_e(t) <= d_e(t)`, after the common hard physical caps. Applied in
`common_opportunities`, which takes no controller argument, so it binds every
arm **before** any controller logic runs. C4 may therefore not create an
autonomous field-driven transfer where no external service opportunity exists.
**Autonomous EBU homeostatic rebalancing is a different scientific question**
and is left to a separately registered future study rather than mixed into the
sustained-demand comparison.

**Q-2 — RESOLVED, and an earlier answer to it was WRONG.** The committed P1C
robust budget subtracts `R_eff`, the **provider/export floor**. A previous
revision inferred from this that "the reserve is protected for every arm" and
removed reserve awareness from C3 as redundant. **That inference was false.**

`R_eff` bounds what a source may **send**. `R` (`NodeSpec.reserve`) is the
**homeostatic reserve coordinate** of a node's own stock, used by the committed
potential's `chi[R - x]_+^2` branch. `R_eff` does not implement `R` at any
node, and **nothing in the resolver moves resource toward a destination below
its `R`** — the resolver only ever narrows what a source sends.

The correct resolution, in two parts:

1. **the provider floor is common and invisible to every arm** — C1 and C2
   benefit from it without carrying export logic, and that is shared
   physical/provider safety rather than unfairness;
4. **the homeostatic reserve condition is supplied by no common layer**, so a
   controller that wants it must carry it. C3 therefore reads `R_j` and serves
   destination reserve deficits in its **stage 1**, while its own source-side
   floor remains the lower band `L_i`.

Neither `R_eff` nor `R` is given a value here; both remain unfilled
parameters, and they are **never equated**.
`world.require_reserve_concepts_distinct` refuses a statement that asserts the
conflation, while still permitting a correction notice to quote it in order to
retract it.

**Q-3 — RESOLVED: destination hard capacity is common physical feasibility.**
`[K_j - x_j]_+ / eta` is clamped inside `common_opportunities` for every arm,
so no controller gains or loses by having been coded to rediscover a hard
physical law, and an arm that ignores it does not crash its own tick into
INVALID. **That per-edge bound is exact only for an isolated incoming transfer
with no same-tick outgoing action.** The authoritative simultaneous condition is
the **joint successor constraint**

```
0  <=  x_j + sum_{e -> j} eta_e q_e^acc - sum_{e : j -> k} q_e^acc  <=  K_j
```

re-checked on the full accepted increment by `world.hard_feasible` via
`world.joint_successor`, using the model's own incidence convention.

## VI.4 Blocking gaps (`BLOCKING_GAPS`) — both fail closed

**G-3 — no authoritative contested-destination allocation rule exists.** When
several sources simultaneously feed one destination and their individually valid

`world.require_resolved_destination_contention` **detects** the contention and

**G-4 — C3's upper-band preservation is per-source and is NOT established under

### Two corrections to the claims made about that boundary

**(a) The AST check is narrower than previously described.** It inspects
**direct calls in one file**. It does **not** prove that an imported module, a
helper, a callback or a dynamic dispatch reached from that file cannot execute a
transition. A stronger guarantee would require call-graph analysis or runtime
instrumentation; neither is implemented. The claim is therefore the narrow one —
*no direct transition call in this file* — and not *no transition can occur*.

**(b) The CI refusal check was too weak, and is corrected.** It used
`if python … ; then fail`, which accepts **any nonzero exit** as success — a
`SyntaxError`, an `ImportError` or an ordinary test failure would all have
passed as though the refusal had been proved. It now compares the exit code to
**exactly 2** and requires the `REFUSED` message, so it proves the specific
refusal it claims.

### Scope of the "static" label

**"Non-model-advancing static/pure" describes the V3.0 subset of the CI
workflow, not the workflow as a whole.** The steps above that subset include
older V2.2–V2.9 suites whose execution class is declared separately and is not
all static. The workflow must not be described as a static-only workflow.

**This correction was made without executing that tick again.** The boundary
was validated by static inspection, parsing and pure functions only.
