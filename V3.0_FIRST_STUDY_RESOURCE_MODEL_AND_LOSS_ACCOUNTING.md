# A. Resource declaration

## A.1 The domain

> **One homogeneous, conserved, continuously divisible scalar resource,
> transferred losslessly between active nodes in a closed conservative world.**

| symbol | meaning | units |
|---|---|---|
| `x_i` | active stock at node `i` | carrier quantity |
| `q_e` | finite **source-side** transfer quantity during the declared action/tick | carrier quantity |
| `η_e` | transfer efficiency; **`η_e = 1` for every first-study transfer** | dimensionless |
| `J_e` | transfer **rate**, with `q_e = Δt · J_e` | carrier quantity / time |
| `w` | cumulative loss account (inactive in this study) | carrier quantity |

There is **no regeneration and no autonomous stock drive** in this first study.
The theoretical quantity domain is the **nonnegative reals**, subject to
physical constraints (`0 ≤ x_i ≤ K_i`, `q_e ≥ 0`, joint feasibility).

## A.2 Divisibility

Continuous divisibility is a **study-domain assumption, not a universal EBU
principle**.

Numerical representation, measurement resolution and solver precision are
**separate matters** and are not licence to introduce a minimum lot size, a
rounding grid or an integer restriction. No such restriction is introduced
here, and none may be introduced under the phrase "measurement resolution": if
physical quantities are quantized, that is a **different action domain
requiring an explicit declaration**.

Future domains may use integer, lot-sized, indivisible or heterogeneous
resources. The **physical action model** determines the admissible quantities;
**EBU evaluates the corresponding transitions**. Changing divisibility does not,
by itself, change the finite-difference EBU equation.

## A.3 `η = 1` is a scope constraint

`η_e = 1` is the **author-supplied scope constraint** for this prospective
first study. It is not a claim that transfers are physically lossless in
general, and it is not a property of EBU. `WorldSpec` accepts `η ∈ (0,1]` and
refuses `η < 1` without a declared loss sink.

**The complete study is not registered, frozen, accepted or ready to execute.**

## A.4 Demand and service in a closed world

**External demand is an externally generated request signal.** It does not, by
itself, add, consume or remove physical stock.

**Service, for this study, means fulfilling the declared transfer/delivery
request.** It is *not* silently reinterpreted as irreversible consumption,
resource production, or satisfaction of an unmodeled end-use process. The
existing service definitions are preserved; no new success metric is invented
in this task.

Two consequences, stated plainly because they are easy to get wrong:

1. **Repeated movement of the same resource is not production of new
   resource.** A high cumulative service total in a closed conserved world
   records circulation, not creation.
2. **Consumption, leakage, evaporation, regeneration and external supply are
   absent.** Introducing any of them requires its own physical state/boundary
   accounting and a **separately authorized scope change**.

The first study therefore concerns **lossless conservative controller behavior
under persistent requested transfers**. It does **not** answer the programme's
regeneration, disturbance or loss-aware long-run questions.

# B. Conservation architecture

## B.1 Lossless first-study boundary

For one transfer `a = (i, j, q)`:

```
x_i⁺ = x_i − q
x_j⁺ = x_j + q
```

hence

```
Δ Σ_i x_i = 0.
```

For **simultaneous** transfers, all accepted increments are aggregated against
**the same frozen baseline** before conservation is evaluated. This is what
`joint_successor` does, and it is why a node that both receives and sends
within one tick is evaluated **once, on its net increment**.

Any existing inactive loss ledger is retained consistently: **at `η = 1` its
increment must be zero**. There is deliberately **no** universal requirement
that every historical loss ledger contain zero — a nonzero *level* `w` is not a
conservation failure, and F-L1 carries a nonzero pre-existing `w` precisely so
that no check can confuse the **increment** `Δw` with the **level** `w⁺`.

## B.2 Loss-aware foundation boundary

For a declared fixed efficiency `0 < η_e ≤ 1`:

```
Δx_i = − q_e
Δx_j = + η_e q_e
Δw   = (1 − η_e) q_e
```

For a simultaneous group, `Δw = Σ_e (1 − η_e) q_e`.

**Active-resource balance:**

```
Δ Σ_i x_i = − Δw
```

**Expanded accounting balance:**

```
Δ ( Σ_i x_i + w ) = 0
```

**Signed balance error and absolute residual:**

```
r_cons = | ( Σ_i x_i⁺ + w⁺ ) − ( Σ_i x_i + w ) |
```

Two disciplines govern it:

- **A nonzero accumulated `w` is not a conservation failure.** The *residual*,
  not the amount of recorded loss, must satisfy the declared closure rule.
- **The sink increment must come from the declared action law.** It is
  **never** computed as an arbitrary balancing plug chosen to make the residual
  vanish. `conservation_profile` computes the expected sink from
  `Action.loss` and refuses a mismatch.

**Total closure alone does not prove that the source, destination and sink
increments are individually correct.** They are checked separately. This is not
a stylistic preference — it is the committed position:

> `CONSERVATION_AND_BOUNDARY_ACCOUNTING_FOUNDATION.md` §4.1 — "a zero residual
> means that the observed inventory change agrees with the declared boundary
> exchange for the selected quantity, boundary, resolution, and transition. It
> does not prove that every exchange was observed or that the chosen state is
> physically complete."

Negative control **NL6** exhibits exactly this: a transition whose per-node
increments are both wrong, with a sink chosen so the total closes. `r_cons` is
`0.0`; the per-node identity check refuses it.

## B.3 Boundary consistency

Every ledger states which of these it describes:

| label | meaning | balance |
|---|---|---|
| `ACTIVE_SUBSYSTEM` | the active subsystem, loss as **outward flow** | `Δ Σ x = − Δw` |
| `EXPANDED_ACCOUNTING` | expanded accounting **including** the sink | `Δ ( Σ x + w ) = 0` |

`conservation_profile` **requires** one of the two and refuses an unlabelled
ledger, because an unlabelled ledger is how the same loss comes to be counted
**both** as an expanded internal sink increment **and** as an additional
external outflow at the same accounting level.

## B.4 Units, and what may not be added

All additions to stocks and loss ledgers carry the **same declared
carrier-quantity units**. `interior_delta`, `sink_delta`, `expected_sink` and
every per-node quantity are carrier quantities for one transition.

- They are **not rates**. The committed layers speak in rates (`d0_v29.edge_flux`
  returns `J_e`; `p1c_v29.robust_budget` returns a rate), and the only
  sanctioned conversion is `q = Δt·J` via `tick_quantity_from_rate`. **Some
  committed mathematical sources use `q` for a rate**; that conversion is
  recorded when they are applied, and `Δt` is neither omitted nor duplicated.
- They are **not EBU burden units**. **A physical quantity is never added
  directly to a burden-valued expression** without a separately justified
  conversion.

**The equations require a common conserved carrier quantity.** A dummy sink is
**not** used to "prove" conservation of utility, quality, money or anything the
physical model does not actually conserve.

**The first study remains an abstract idealized carrier model.** No physical
embodiment is declared, and none is invented here.

## C.2 The two defects that were found

Both were demonstrated by pure evaluation on constructed states, not inferred.

### Defect 1 — an undeclared sink change masks an active-stock discrepancy

In a world declaring **no** loss channel (`loss_sink == ""`, `is_conservative`
true), an interior loss of `2.0` paired with a sink credit of `2.0` returns

```
conservation_residual(...)  ==  0.0
```

The transition reports as **conserved** while active resource vanished into an
account the world never declared.

### Defect 2 — withdrawal from the irreversible loss account

A sink that **decreases** by `3.0` while the interior gains `3.0` also returns
`0.0`. That is resource recovered from an irreversible cumulative loss account.
`WorldState` does not catch it: it refuses only a **negative** level, not a
**decreasing** one, and it has no view of the spec.

### What these two defects are, and what they are NOT

**Both are properties of `conservation_residual` evaluated on a SUPPLIED pair
of endpoint states.** Each was produced by **constructing a malformed `after`
state by hand** and handing it to the residual.

**Neither shows that `apply_joint` generates an invalid sink.** It cannot: it
never accepts a caller-supplied successor. It builds one via
`state.successor(totals, loss)` with `totals` from `Action.increment` and
`loss` from `Action.loss` — i.e. **from the declared action law** — so the
malformed pairs above are **not in its image**. No defect in `apply_joint` is
claimed, and none was found.

The distinction that matters:

| object | how the successor arises | can exhibit the defects? |
|---|---|---|
| `apply_joint` | constructed **by the action law** | **no** |
| `conservation_residual` used as a standalone audit over two supplied states | **supplied by the caller** | **yes** — demonstrated |

The exposure is therefore to **any validator or future caller that checks a
transition it did not itself construct** — which is exactly how an independent
audit is supposed to work, and exactly why a residual alone is not enough.

### Why the repair is not a change to `conservation_residual`

`r_cons` is **correct as a residual** — its formula is exactly §B.2's. The
defect is that a residual **alone** was being relied on for a guarantee it does
not provide, which is what committed §4.1 already warns about. The prescribed
fix is therefore the one the design itself states: **check the individual
identities separately.**

# D. Sink and atomic-action semantics

## D.1 What `w` is

An **irreversible cumulative loss account** of represented carrier quantity
removed from the active/useful domain. Nonnegative and **nondecreasing** under
the declared transfer-only model.

Whether `w` is an inactive physical sink **inventory** or cumulative
**outward-flow accounting** is left open. **Neither reading licenses treating
it as reusable stock.**

## D.2 What `w` is not

Not an available transfer source · not a demand-generating node · not service ·
not a wallet or issuance account · not a Möbius or interaction account · not
automatically a homeostatic-potential factor.

The first three are enforced **structurally**, not by convention: a `loss_sink`
may not be a topology node, and every edge endpoint must be a node, so **no
edge can reach the sink**. `WorldState.total()` is the **interior** total and
excludes it.

**The global accumulated-loss value is not exposed to local controllers**
merely because the audit ledger contains it.

## D.3 `w` and the potential

`V` is a function of the **active stocks only**. Equivalently:

```
Ṽ(x, w) = V(x),    explicitly independent of w.
```

**This is a declared omission of sink burden from this model. It is NOT a
finding that waste is harmless or that loss has no physical consequences.**

No waste-burden factor, sink capacity, recovery efficiency or new scientific
parameter is added.

### D.4.4 What is settled regardless

- **`V` does not read `w`** — structural, not conventional.
- **Conservation bookkeeping values nothing.** The ledger's presence proves

- **`C_a ≡ 0` in every fixture here**, with **no synthetic surcharge anywhere**.
- **No burden term is introduced by this task**, and no committed cost

### D.4.5 Why Study 1 is unaffected

**At `η = 1` the `λ_L` term is identically zero whichever category it belongs
to**, and the first study declares the idealized scope `C_a = 0`. The
unresolved classification therefore **blocks nothing in the lossless study**.
It must be settled **before any study declaring a nonzero `λ_L`** — i.e.
together with, not before, the loss-aware scope decision.

## D.5 Atomic physical transformations

**Loss production is a deterministic consequence of the transfer action, not an
independently selected action.** The action remains `a = (i, j, q)`, with all
declared immediate physical increments recorded **once**.

`Action` is deliberately non-recursive — no `parent`, no `children`, no
`expand()` — so a causal chain must be a chain of **separate atomic actions**,
each with its own state change and receipt.

**Material recovery, if ever modeled**, requires an actual **recoverable
waste-stock representation** and a **separate physical transformation** with
its own feasibility conditions, quantity, state changes, affected potential
factors and audit record. It is **not** a credit against the irreversible
account — which is exactly what `sink_increment` refuses.

The original transfer is **not** retrospectively expanded into its later causal
consequences. The same principle applies to longer chains (fuel conversion,
electricity delivery, use, water transfer): **linked atomic transformations,
not one hidden mega-action.** No additional process burden is invented merely
because an upstream or downstream action exists.

## E.1 The `η`-dependence that matters most

Row 20 is the substantive scientific finding of the impact map.

`S(q) = Σ_e η_e q_e` is measured **destination-side**. The step *"on the
service-maximal set the total export `Σ_e q_e` is fixed"* — on which d-11's
constant source term, and hence the whole field-flatness and comparator
analysis, depends — holds because maximising `S` fixes `η Σ_e q_e` **when `η` is
common across the source's out-edges**. `η = 1` satisfies this.

Under **heterogeneous `η_e`** it fails: fixing `Σ_e η_e q_e` leaves `Σ_e q_e`
free, the source term `v_i(z_i) − v_i(z_i − Σ_e q_e)` **varies**, and the field
criterion can become operative for a reason unrelated to destination flatness —
it would price transport loss through the source term.

**These conclusions are therefore scoped to common-`η` worlds and must not be
exported into a heterogeneous loss-aware study without re-derivation.** The
controllers were **not** redesigned here.

# H. Remaining author decisions

Only genuinely unresolved questions are listed. Each states the proposition,
its source, the consequence, and a recommendation. **None is resolved here.**

### H-1. Should `conservation_profile` be wired into `apply_joint`?

- **Proposition:** the authoritative transition function should compute the
  decomposed profile rather than only the total residual.
- **Source:** §B.2's separate-identity requirement vs the "smallest safe
  change" and "do not change first-study behavior" constraints.
- **Consequence:** `apply_joint` cannot currently exhibit either defect — it
  builds its successor from the action law — so the change would be
  **defensive only**, and it adds a failure mode to the authoritative
  transition path. Testing it **requires a model transition**, which this task
  does not authorize.
- **Recommendation:** **defer.** Keep the audit separate until a lossy study is
  actually authorized; revisit together with the transition-suite coverage gap
  (§C.5). Low risk either way.

### H-2. Does a future lossy study need per-edge `η_e`?

- **Proposition:** `EdgeSpec` should carry `eta` so efficiency can vary by edge.
- **Source:** the mathematical notation admits `η_e`; the implementation
  supports a **single common `η`**.
- **Consequence:** this is the **hinge** for row 20. Under common `η` the
  existing d-7/d-11/d-13/§4A results survive unchanged. Adding per-edge `η_e`
  **invalidates the constant-source-term step** and requires re-deriving the
  entire comparator and field-flatness analysis. It also changes a public
  schema and every affected spec digest.
- **Recommendation:** **do not add it now.** It is a material scope expansion,
  not a correction. If a loss-aware study is authorized, treat the
  re-derivation as a **precondition**, not a follow-up.

### H-3. Is `w` an inventory or outward-flow accounting?

- **Proposition:** the model should declare which.
- **Source:** §D.1 leaves it open; committed §5.1 makes the augmented
  coordinate **optional and domain-specific** and warns that a generic
  resource-stock loss *"must not automatically be relabelled heat"*.
- **Consequence:** it does not affect this study (`Δw ≡ 0`). It **does**
  determine whether a future recovery transformation is even representable.
- **Recommendation:** **leave open.** Deciding it requires a declared physical
  embodiment, and the first study deliberately has none. Deciding it now would
  be inventing domain facts.

### H-4. Settle the Definition 6.4 scope question for the extended model

- **Proposition:** declare explicitly that Definition 6.4's four-way test is
  evaluated against **`V_loc`'s arguments**, that `Ṽ(x,w) = V(x)` is the
  declared state functional, and that **no extension pricing `w` is
  admissible** for this programme — which would place the `λ_L` term in
  **category 2** as the source's candidate states.
- **Source:** Def 6.4 body `:362–364`, categories 1–2 `:373–384`,
  no-double-count `:396–400`, candidate `:404–406`, **O9** `:407–410` — see
  §D.4.2 for which way each clause points.
- **Why it matters:** the source's clauses **conflict** once the state carries
  a loss coordinate the potential ignores, and **O9 registers exactly this case
  as open**. Without an authored interpretation there is no defensible
  classification for a nonzero `λ_L`.
- **Consequence of rejecting / not deciding:** none for Study 1 — at `η = 1`
  the term is **identically zero** whichever category it is, and `C_a = 0` is
  the declared idealized scope. It becomes **blocking only for a study
  declaring a nonzero `λ_L`**.
- **Recommendation:** **do not decide now.** Decide it **together with** the
  loss-aware scope decision (H-2), because the interpretation and the
  heterogeneous-`η` question are the same scope expansion. Deciding it now
  would settle an open problem in order to close a documentation item.
- **Adopting it would authorize:** using the historical candidate cost form in
  a future lossy design. **It would NOT authorize** selecting `λ_L`, adding any
  burden term, or changing Study 1.
