## 2. Discovery and existing compatibility gap

The existing authoritative protocol, plan, execution/finalization sources, and
macOS environment compatibility sources do not prescribe
`sys.orig_argv[0]`. Static inspection found that the current runner and
finalizer nevertheless require the first process-visible original argument to
equal `/opt/homebrew/bin/python3` as part of their exact-tuple checks.

The isolated probe launched Homebrew Python 3.14.2 through the official shell
path with the frozen flags and observed that macOS exposes the framework's
`Python.app` executable as `sys.orig_argv[0]`. The probe performed no project
import, Git mutation, model step, scientific call, artifact creation, or
outcome inspection. The current checks would therefore reject the unchanged
official shell invocations before receipt creation or any finalizer action.

## 3. Three frozen Python identities and their distinct roles

For Homebrew Python 3.14.2 on this frozen macOS platform, the identities are:

| Identity | Exact path | Role |
|---|---|---|
| Official shell invocation path | `/opt/homebrew/bin/python3` | The external command path in both official shell invocations and the unchanged receipt `python.invoked_as` value. |
| Existing frozen executable realpath | `/opt/homebrew/Cellar/python@3.14/3.14.2/Frameworks/Python.framework/Versions/3.14/bin/python3.14` | The unchanged realpath required for the official path and `sys.executable`. |
| Exact process-visible `sys.orig_argv[0]` | `/opt/homebrew/Cellar/python@3.14/3.14.2/Frameworks/Python.framework/Versions/3.14/Resources/Python.app/Contents/MacOS/Python` | The macOS framework launcher identity exposed inside the Python process. |

These paths have different roles. The `Python.app` launcher path does not
replace, rename, or reinterpret the official shell invocation path, the
receipt `python.invoked_as`, or the executable-realpath check. It is not an
operator-selectable executable or runtime substitution.
