## 1. What kind of study this is

The author has selected the first long-horizon exact-EBU study as a
**normalized mechanism study**.

- **No claim of empirical calibration.** No parameter below was estimated from
  data, fitted to an observation, or derived from any measurement of any real
  system. No data was read.
- **No claim about any real external system.** Nothing here describes an
  ecosystem, a grid, a market, an organisation, or any physical installation.
- **Parameters describe declared synthetic worlds only.** A parameter value is
  a *declaration* that fixes a synthetic world, in the same sense that a unit
  test fixture declares its inputs. It is not an estimate of anything.

The question is mechanical: **do repeated exact-finite-EBU decisions preserve
homeostasis, reserve protection, service and recovery in declared synthetic
worlds, including deliberately severe but recovery-capable stress?**

A mechanism study answers that inside its declared worlds and nowhere else.
Establishing that any group below describes a real system would require
empirical parameter identification and then a calibration study — both separate
programmes, neither designed, neither authorized, and neither substitutable by
the algebra in this file.

## 3. Normalization, and where it stops being valid

Three exact scale symmetries of the committed law permit three raw numbers to
be set by declaring units. Verified function by function against `d0_v29.py`,
`p1c_v29.py`, `service_v30.py` and `ebu_quote_v30.py`: under stock scale `a`,
time scale `b` and potential scale `c`, `penalty -> c*v`, `marginal -> (c/a)*mu`,
`natural_drive -> (a/b)*u`, `edge_flux -> f:(c/a), J:(a/b)`, `robust_budget ->
(a/b)*Q`, `classify_state` invariant, `cell_curvature_sup -> (c/a^2)*L_V`, both
`dt` certificates `-> b*dt`, `state_difference -> c*dV`, `ProcessCost.cost ->
c*C`, hence `exact() -> c*Delta_e`.

Units adopted here:

| Unit | Set to | Effect |
|---|---|---|
| Stock | the source reserve floor | `R_eff = 1` |
| Time | one source regeneration time | `rho = 1` |
| Potential | destination deficit stiffness | `alpha_dst = 1` |

**Limitations of this normalization — all four are real:**

1. **The time unit is only defined for a regenerative source with `rho > 0`.**
   `d0_v29._regen` returns `0.0` when `source` is `none`/`finite` or `rho <= 0`,
   so `1/rho` does not exist for those source types. Every family below uses a
   **logistic regenerative** source, which is exactly why the unit is available.
   A finite or irreversible source would need a different time unit, and its
   P1C export budget is zero anyway.
2. **The EBU scale is not a fourth freedom.** `Delta_e` has the dimension of
   potential, so fixing `alpha_dst` fixes the EBU scale. There is no separate
   normalization of EBU values, and no EBU number below is comparable to any
   number from any differently normalized study.
3. **Two numerical tolerances are not scale-invariant.** `service_v30.tol(v) =
   1e-9*(1+|v|)` and the `num_tol*(1+|R_eff|)` form at `p1c_v29.py:400` are
   mixed absolute-relative. Both are confined to diagnostics — `tol` feeds only
   `materially_below_reserve`/`reserve_crossing`, documented as "diagnostic
   layer ONLY: never used for physical updates, P1C budgets, accepted
   quantities, quotes, service, unmet demand, ledgers, Allee/dead-source
   thresholds, or certificates". Setting `R_eff = 1` keeps these tolerances
   behaving as relative ones, which is one reason that unit is chosen.
4. **Normalization removes units, not choices.** Every remaining number below is
   a declared dimensionless group. Normalization proves the model does not care
   about the missing three; it says nothing about whether the rest are right.

## 4. Structure shared by all three families

### 4.1 Topology (A1) — one source, two out-edges

```
            edge e1 (eta, theta, M)
  source s ------------------------> destination d1
      |
      |     edge e2 (eta, theta, M)
      +-----------------------------> destination d2
```

One regenerative source, two out-edges, two distinct destinations.
`sum d_out(s) = 2`, `E = 2`, `m = 2`, so the structure admits a two-action joint
transition whenever the menu offers at least two candidates, and `double_count`
is then defined on it. Where the budget is zero the menu is empty and no
transition occurs at all, so this is a property of the structure, not of every
tick of a run. Destinations are distinct, so the shared endpoint is the
**source**, and interaction enters through the shared P1C budget and the shared
source potential.

### 4.2 Fraction ladder — `F = 5`

Proposed ladder `(1/5, 2/5, 3/5, 4/5, 1)`.

`F = 5` is a genuinely medium resolution and is **not inherited**: the
repository contains two registered ladders, `service_v30.QUANTS` with `F = 2`
and `gate1dc_v30.FRACTIONS` with `F = 4`, and neither is used here. `F = 5` is
chosen because the feasibility window derived in §6.1 is `1 <= sigma < F`, and
the extreme family needs a window wider than `F = 4` provides.

`K = F * sum d_out(s) = 5 * 2 = 10`.

### 4.3 Process cost

`service_v30._process_cost` builds `ProcessCost(c0=0, c1=LAM_L*dt*(1-eta))` with
no quadratic term, so the implemented cost is `C(q) = LAM_L*dt*(1-eta)*q`.
Proposed cost group `Pi_cost = LAM_L*(1-eta)/theta = 0.5`, giving
`LAM_L = 0.5` at `theta = 0.1`, `eta = 0.9`.

To first order `linear_diagnostic = dt*q*(f - LAM_L*(1-eta))`, so the process
cost acts exactly like a shift of the flux driving force, structurally the same
role as the deadband `theta`. With `Pi_cost = 0.5 <= 1` we have
`LAM_L*(1-eta) = 0.05 < theta = 0.1 < f` on every menu candidate, so the
**first-order screening quantity** `linear_diagnostic` is non-negative there.
`dt` cancels from `Pi_cost`, so that observation holds at any timestep.
`LAM_L = 0.1` in `service_v30` is inherited from a locked Gate-1 plan and is
**not** used as a default.

**That is a screening observation, not a sign guarantee on the settled value.**
`ebu_quote_v30` documents `linear_diagnostic` as over-quoting for convex `v`, so
`exact(q) <= linear_diagnostic(q)`. A non-negative first-order value therefore
places **no lower bound** on the exact finite EBU quote, which may be negative at
any rung, at every rung, or at none. The cost group is chosen so that the
first-order screen does not exclude the menu outright. It does **not** establish
that any exact quote is non-negative, and the study must **not** be described as
guaranteed not to measure refusal. Whether exact quotes come out positive,
negative or mixed is an empirical result of a run that has not happened.

### 4.4 Declared normalized world (identical across families except `x_s(0)`)

| Cell | alpha | beta | chi | L | U | R | K | source | rho | s | d | lam | kappa |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| source `s` | 0.5 | 1.0 | 0.5 | 2.0 | 6.0 | **1.0** | 8.0 | **logistic** | 1.0 | 0 | 0 | 0 | 0 |
| dest `d1` | **1.0** | 1.0 | 0.0 | 1.0 | 4.0 | 0.0 | 6.0 | none | 0 | 0 | 0.25 | 0 | 0 |
| dest `d2` | **1.0** | 1.0 | 0.0 | 1.0 | 4.0 | 0.0 | 6.0 | none | 0 | 0 | 0.25 | 0 | 0 |

| Edge | eta | theta | M |
|---|---|---|---|
| `e1`, `e2` | 0.9 | 0.1 | 10.0 |

P1C: `source_type = "regenerative"`, `R_eff = 1.0`. `service_v30.py:265`
constructs `SourceConfig(R_eff=world.cells[cid].R)`, so `R_eff` equals the
source's penalty reserve breakpoint by implementation convention, not by a
free choice. `eps_x = eps_u = 0`, adopted as the **exact-model conformance
convention** documented in `SourceConfig` — the docstring states this "is NOT an
empirical recommendation" and that Amendment 4 §20.4 forbids fitting margins. A
non-zero-margin variant is a separate proposal and is not made here.

**No Allee source anywhere.** `source = "logistic"`, so `_regen` returns
`rho*x*(1-x/K)` with no `(x/A - 1)` factor and no unclipped negative branch.
Allee collapse is not the intended stress mechanism in any family, so it is
excluded by construction rather than avoided by parameter choice.

**Source deficit floor above the reserve floor (`L_s = 2 > R_s = 1`).** This is
why the source potential can stay live under reserve-binding rather than sitting
flat: in the operating band `R_s < x_s < L_s` the source is above its reserve,
so export is permitted, while `mu_s = -2*alpha_s*(L_s - x_s) != 0`, so the
source contributes to the endpoint difference whenever it is in that band. So
`double_count` is not forced to zero by a flat-band source. Whether it is
actually non-zero in a run is an empirical result, not a property established
here.

### 4.5 Certificate and timestep

From `cell_curvature_sup`, the branchwise sup sums simultaneously active
weights: source `2*(alpha_s + chi_s) = 2.0` below `R_s`; destination
`2*alpha_d = 2.0` below `L_d`. So `L_V = lv_exact = 2.0`.

For two edges sharing a source the Gershgorin overlap term is
`S_e . S_e' = (-1)(-1) = 1`, so with `M = 10`, `eta = 0.9`:

```
one_edge     dt <= 2 / (L_V * M * (1+eta^2))            = 0.055249
gershgorin   dt <= 2 / (L_V * M * (1+eta^2 + 1))        = 0.035587   <- binding
Pi_tau = 0.5 ->  dt = 0.0177936          (56.20 ticks per regeneration time)
```

`Pi_tau = 0.5` leaves a factor-two margin below the certified bound rather than
sitting on it.

**The timestep is not freely variable at fixed stress.** `sigma` scales roughly
with `Pi_tau` (§6.1), so halving `Pi_tau` would push every family below the
feasibility floor `sigma >= 1`. A timestep-robustness variant therefore requires
re-solving the headroom, and cannot be added as a free second timestep. Each
family below uses **one certified timestep**.

## 6. Static feasibility checks

**What these checks are.** Every calculation in this section is evaluated at a
**declared reference state** — a family's episode-start state or its
shock-trough state — using committed closed-form functions. They establish
**necessary design conditions**: had one failed, the design would be infeasible
and could be rejected before any implementation.

**What they are not.** They are not an invariant proof over a trajectory. No
complete induction is supplied anywhere in this file, and none is attempted. In
particular, the realized pre-shock state of episode 2, 3 or 4 depends on whether
recovery from the previous episode actually completed, which no static check can
determine; a later episode entered with less headroom than declared would face
the same absolute shock as a larger fraction of its actual headroom. Whether an
executed run remains inside these conditions at every tick is an **empirical
result of a run that has not happened**.

### 6.1 Reserve stress and the window `1 <= sigma < F`

`action_menu` sets `q_acc = min(q_req, budget)` and `QuoteSchedule._domain`
refuses any `q > q_acc`, so every rung whose request exceeds the budget collapses
to the *same* accepted quantity and therefore the same exact value. With rungs
`phi_i`:

```
sigma  = J_tot / Q_max                       binding stress
F_eff  = #{ phi_i : phi_i < 1/sigma } + 1    distinguishable accepted quantities
```

`sigma >= 1` is required for the budget to bind at all; `sigma < F` is required
for at least two rungs to remain distinguishable. **Resolution sets the width of
the usable stress window**, which is why `F` and the stress level cannot be
chosen independently.

| Family | point | `f` | `J_tot` | `Q_max` | `sigma` | `F_eff` | `1 <= sigma < 5` |
|---|---|---|---|---|---|---|---|
| N | start | 0.5900 | 9.8000 | 9.4147 | 1.0409 | 5 | **OK** |
| N | trough | 0.5000 | 8.0000 | 4.2915 | 1.8641 | 3 | **OK** |
| H | start | 0.5000 | 8.0000 | 4.2915 | 1.8641 | 3 | **OK** |
| H | trough | 0.4640 | 7.2800 | 2.2417 | 3.2475 | 2 | **OK** |
| X | start | 0.4600 | 7.2000 | 2.0140 | 3.5751 | 2 | **OK** |
| X | trough | 0.4520 | 7.0400 | 1.5584 | 4.5175 | 2 | **OK** |

**A correction to an earlier statement.** An earlier chat-only audit suggested
solving for the transport group `Pi_M = M*alpha_dst/rho` to hit a target
`sigma`. That is wrong once `dt` is tied to the certificate. Since
`dt_cert ~ 1/M` and `Q_max ~ h/dt`, both `J_tot` and `Q_max` are proportional to
`M`, and **`M` cancels exactly**:

```
sigma  ->  4*(f - theta)*Pi_tau / ( h * L_V * (1 + eta^2 + overlap) )   as M grows
```

Reserve stress is controlled by **headroom**, driving force, total curvature and
the timestep safety fraction — not by the edge capacity. This is why the three
families differ in `h` and in nothing else, and why raising the reserve
stiffness `chi_s` would *reduce* stress by raising `L_V` and shrinking `dt`.

### 6.2 Shock depth at the declared pre-shock states

For each family the shock is a declared extra withdrawal of `Delta` stock units
with `Pi_shock = Delta / h < 1`. Therefore

```
x_post = x_pre - Delta > x_pre - h = R_eff
```

so a shock applied at the **declared** episode-start headroom leaves the source
above the reserve floor. Numerically: N `1.15 - 0.09 = 1.06 > 1`; H
`1.06 - 0.036 = 1.024 > 1`; X `1.02 - 0.008 = 1.012 > 1`. This is established for
the declared pre-shock state only. If a run entered a later episode with less
headroom than declared, the same absolute shock would be a larger fraction of
the actual headroom and the inequality could fail.

`classify_state` returns **state I** when `x >= R_eff` but `x + dt*u < R_eff`,
and `_source_budget` records that zero export cannot then prevent the breach. A
shock delivered as a `d_extra` pulse makes `u` negative for that tick, so the
no-state-I condition must be checked explicitly. It reduces exactly to
`d_extra <= Q_max`:

| Family | `d_extra = Delta/dt` | `Q_max` at shock tick | `d_extra <= Q_max` |
|---|---|---|---|
| N | 5.0580 | 9.4147 | **OK** |
| H | 2.0232 | 4.2915 | **OK** |
| X | 0.4496 | 2.0140 | **OK** |

Independently, the source has `s = d = lam = kappa = 0`, so between shocks
`u = g(x) = rho*x*(1-x/K) > 0` for every `x` in `(0, 8)`. `classify_state`
returns state I only when `x + dt*u < R_eff <= x`, which requires `u < 0`. So
**state I cannot arise from the source's own drive between shocks for as long as
`x` remains in `(0, 8)`**, and the table above excludes it at the declared shock
states. That is a conditional statement about declared states; it is not a proof
that the trajectory satisfies its premises at every tick.

### 6.3 Menu non-emptiness at the reference states

`Q_max = h/dt + u` and, at the reserve floor itself, `Q_max(x=1) = g(1) =
0.875 > 0`. So for a source at or above the reserve floor with `x` in `(0, 8)`,
the robust budget is strictly positive, and a non-empty menu then requires only
some `J_e > 0`, which §6.1 confirms at every tabulated reference state.

This does **not** show that the menu is never empty over a run. The budget is
zero in state R and in state I, and whether either is reached at some tick
depends on the realized trajectory. Empty-menu and refusal behaviour is
therefore **not shown to be unreachable**. It is simply not exercised by any
declared reference state, and it is not a behaviour these families are designed
to test — see §10.

## 7. Deterministic shock schedule

**No stochastic rule, seed, random sampling, or adaptive shock appears anywhere.**
The schedule is fully predeclared by tick index and is identical across arms, so
arms differ only in their selection rule.

```
tick indexing      1-based; "tick t" is the t-th tick of the run
shock convention   a shock occupies the FIRST tick of the episode it opens;
                   burn-in contains no shock tick

burn-in            ticks     1 ..  240    240 ticks, no shock
episode 1          ticks   241 ..  580    shock on tick  241, then recovery
episode 2          ticks   581 ..  920    shock on tick  581, then recovery
episode 3          ticks   921 .. 1260    shock on tick  921, then recovery
episode 4          ticks  1261 .. 1600    shock on tick 1261, then recovery
end of run         tick             1600

burn-in 240 + 4 episodes x 340 ticks = 1600 = T          (partition, no overlap)
shock spacing 340 ticks >= k*tau, k = 4, tau ~ 76-79     (4*79 = 316 <= 340)
post-shock recovery window 339 ticks per episode         (316 <= 339, still OK)
```

Each shock is one tick of declared `d_extra = Delta/dt` applied through
`natural_drive(c, x, s_extra=0, d_extra=...)`, which is the committed law's own
declared-additional-demand argument. No state is written directly.

Horizon check: `T >= burn_in + n_s*k*tau = 240 + 4*4*79 = 1504`, and
`240 + 4*340 = 1600`, so `T = 1600` satisfies the condition with margin.
`n_s = 4 >= 2` gives recovery **repeatability**, which B2 requires and a single
episode cannot show. `k = 4` gives `e^-4 ~ 0.018`, about 98 percent recovery,
above the 95 percent that `k = 3` provides.

**The horizon condition remains necessary, not sufficient.** `tau_dst =
1/(2*eta^2*M*alpha_dst*dt) = 3.47` ticks is the destination-side lower-bound
estimate; the source-side linearisation `tau_src ~ 1/(|rho*(1-2x/K) - kappa|*dt)`
gives 75-79 ticks and dominates by more than twentyfold. Both are local
linearisations about a declared state, the coupled system is not a single
exponential, and neither establishes the sign or size of the correction.

## 8. Recovery capability

Four conditions, each checkable statically at the declared reference states. All
four hold there for all three families. None is a whole-trajectory guarantee.

1. **Regeneration is strictly positive on the operating band.** `g(x) =
   x*(1-x/8) > 0` for `x` in `(0,8)`; the declared band is `[1.0, 1.15]`. No
   Allee term exists, so there is no negative unclipped branch and no collapse
   threshold.
2. **Flux shut-off is reachable.** Flow stops when `f <= theta`, i.e.
   `2*eta*alpha_d*(L_d - x_d) <= theta + 2*alpha_s*(L_s - x_s)`. At the source
   floor `x_s = 1` this is `x_d >= 0.38889`, comfortably below `L_d = 1.0`. Once
   destinations rise past it, export ceases and the source regenerates freely.
3. **Destinations can actually reach that level.** At the source floor the
   delivered rate per destination is `eta*Q_max/2 = 0.39375`, against declared
   demand `d_dst = 0.25`. The net fill rate is positive, so destinations rise.
   This is the condition that makes the source *unpin* from the floor: because
   `Q_max(x=1) = g(1)` exactly, a source held at the floor with permanently
   deficient destinations would export precisely its regeneration and never
   recover. Recovery therefore depends on destination demand, and
   `eta*g(1)/2 > d_dst` is the condition required for it at that state.
4. **State I is excluded at the declared states**, by §6.2, so at those states
   the source is not in the branch where refusing to export cannot prevent a
   breach. This is a reference-state check, not a trajectory-wide exclusion.

**Caveat, stated plainly.** Every check above is evaluated at a *declared*
reference state. Whether a trajectory visits that state, and whether it stays
within these conditions at every tick, are questions only execution can answer.
These are design-time **necessary conditions**, not guarantees, and no complete
invariant proof is supplied. Recovery capability is a hypothesis this study
would test, not a property it assumes.

## 9. Constraint checklist

**Exact-EBU.** The governing value is only
`Delta_e(q) = V_loc(z) - V_loc(z + dt*S_e*q) - C_a(q)`, evaluated as an exact
finite endpoint difference by `QuoteSchedule.state_difference` plus
`ProcessCost.cost`. Never per unit, never sampled quadrature, never a surrogate.
`linear_diagnostic` over-quotes for convex `v` and must never settle. Under
Option B the joint transition is quoted once; `group_quote`, `naive_sum`,
`double_count` are recorded and nothing is allocated.

**P1C.** Admissibility precedes EBU: `classify_state` then `robust_budget` then
menu then ranking. A non-positive budget yields an empty menu. Every candidate is
pre-capped by `q_acc = min(q_req, budget)` before any value is consulted. The
authoritative `q_acc` comes from `p1c.p1c_step`; `_screen_budget` is menu
screening only.

**Certificate.** `dt = 0.0177936 <= 0.035587`, the binding Gershgorin bound, with
`Pi_tau = 0.5`. `L_V = 2.0` from `lv_exact`.

**Known build gap, unchanged.** `service_v30.action_menu` applies the budget
per candidate, not to the action pair; `select_arm_B` returns a single
candidate; and `gate1dc_v30.py:934` hard-asserts `len(outcome.q_acc) != 1`. A
correct `m = 2` study requires a joint budget cap, a two-action comparator
selector and a generalized request-shaping identity. None exists. This is
implementation work under separate authorization and is **not** a cost question.

Every cell describes a **declared reference state**, not a whole run. "not at
ref" means the condition is not exercised at that reference state — **not** that
it cannot occur during execution.

**Action-capable cases:** all six declared reference states above. Each has a
non-empty feasible menu and at least two distinguishable accepted quantities.

**Intentionally no-action cases: none are proposed.** No declared reference
state empties the menu, so refusal behaviour is not exercised by these families.
That is a statement about the reference states, **not** a proof that refusal is
unreachable during a run.

**A genuine reserve-breach or collapse case is intentionally absent.** Inducing
one would need a condition that drives the source through the reserve floor into
state R — `Pi_shock > 1`, for instance — together with its own recovery
analysis, its own terminal-state handling, and its own stopping and reporting
rules. That belongs to a **separately registered terminal-case protocol**, which
does not exist and is **not added here**. It is recorded as a known untested
behaviour, not as an oversight.

## 11. Preliminary local resource calculation

**Local Apple M4 Pro software estimate only. Not AWS throughput. Not a dollar
estimate. Not a host recommendation. Not an EBU scientific result.**

Constants are the committed E-settled, `m = 2`, forward measurements in
`results/benchmarks/d5/d5-raw-001/d5_summary.json`. `K = 10` is **not** a
measured D5 grid point; the grid is `{1, 2, 4, 8, 16, 32}`. The `K = 10` row is
therefore an **explicitly labelled approximation** by linear interpolation
between the measured `K = 8` and `K = 16` points, and the two measured rows
bracketing it are given so the approximation can be bounded rather than trusted.

All three families share `K = 10`, `T = 1600` and `R = 4`, so their resource
figures are **identical**. Proposed run composition:
`R = 1 world x 4 arms x 1 certified timestep x 1 variant = 4`;
`records = R * T = 6,400`.

| Basis | CPU (s) | logical (MB) | retained memory (MB) |
|---|---|---|---|
| `K = 8` — **measured** | 0.2495 | 10.77 | 27.01 |
| `K = 10` — **APPROXIMATION** | 0.2507 | 11.92 | 30.43 |
| `K = 16` — **measured** | 0.2542 | 15.35 | 40.68 |

Wall-clock floor for one trajectory, `T * t_record / 1e9`, is about **0.063 s**

**Scope of this proposal.** The 1,600-tick, four-run design is an **initial

**The honest conclusion from these numbers: this initial candidate is not a
compute problem.** At roughly a quarter of a second of CPU and about

to run it.** D1 checkpoint/restart remains a selected direction and should be
built, but its motivating constraints — a memory ceiling and bounded rework —
do not bind at this scale. They would bind for a B3 drift study, a larger
variant grid, or a longer horizon, none of which is proposed here.

## 13. What these families test, and what they cannot claim

**Can test.** Whether repeated exact-finite-EBU decisions under a binding
preservation budget preserve reserves, service and homeostasis across four
declared shock-recovery episodes; whether recovery is repeatable across
episodes; whether `double_count` is non-zero when the source potential is live;
how ladder resolution degrades as stress rises; and whether reserve protection
holds at 2 percent headroom. Each is a question the study would answer
empirically. None is a property the design guarantees in advance.

**Cannot claim.** Behaviour after a genuine reserve breach, which no declared
condition here induces and which needs a separately registered terminal-case
protocol. Empty-menu or refusal behaviour, which no declared reference state
exercises. That exact EBU quotes will be non-negative: the first-order screen in
§4.3 places no lower bound on the settled exact value. Anything about
destination-side shared endpoints, since destinations here are distinct.
Anything about heterogeneous out-degree, larger networks, or drift over horizons
much longer than a relaxation time. Anything about a real external system.

## 13a. Prospective two-action decision semantics

**Prospective, like everything else here.** This section records the decision
rule the author has chosen for the exact-EBU arm. It does not adopt the N/H/X
families, the four-arm set, or any parameter tuple: §1 still governs, and this
file still reads **PROPOSED, NOT ADOPTED** until an author-adoption statement
is recorded in the repository.

### The rule, in order

1. P1C/homeostatic admissibility screens the candidates first.
2. Enumerate the permitted action sets of size at most `m = 2`, under the
   declared distinct-edge rule.
3. Apply the shared-source proportional joint budget cap to each set.
4. Compute the exact finite **joint** EBU only for the resulting **accepted**
   action vector:
   `Delta_e(q) = V_loc(z) - V_loc(z + dt*S_e*q) - C_a(q)`.
5. Select on that exact joint value, for the vector that would actually
   execute.
6. Record `group_quote`, `naive_sum` and `double_count`; allocate nothing
   between actions. O3 remains open.

**What this corrects.** The superseded rule ranked candidates on their
uncapped menu quantities and then executed a different, joint-capped quantity.
The ranked value and the settled value were different objects, which makes the
quantity choice partly cosmetic - the same defect the O14 plan's
`request_shaping.reason` identifies for Gate 1D. Under the rule above the
ranked value **is** the executed value.

### What is derived, and what is declared

| Element | Status | Source |
|---|---|---|
| The joint EBU formula | **derived** | `v30_o14_multi_edge_plan.json` -> `aggregate_quote_diagnostics.group_quote`, verbatim, over the source and its destinations |
| `naive_sum`, `double_count` | **derived** | the same entry: the sum of independently frozen per-edge quotes, and their difference |
| Act condition, exact-EBU arm | **derived** | registered `heuristic.act_condition`: act only on a strictly positive value, otherwise rest |
| Act conditions, comparator arms | **derived** | the frozen selectors: `select_arm_S` declines a non-positive score, `select_arm_B` never rests |
| Proportional joint cap | **derived** | `p1c_v29.p1c_step`'s per-source block: `sigma = min(1, Q_max/Q_req)`, `q_acc = sigma*q_req` |
| No per-unit ranking | **derived** | registered falsifier F8; no EBU value is ever divided by a quantity |
| Arm B's set-level score | **DECLARED** | no committed authority; the author's forward-work package |
| Arm S's set-level score | **DECLARED** | no committed authority; the author's forward-work package |
| Set-level tie-breaking | **DECLARED** | generalizes the registered identifier rule; the extension itself is declared |
| Multi-action settlement form | **UNRESOLVED** | see below |

### The three declared set-level rules

These are **declarations, not derivations.** No committed authority registers
a set-level score for either comparator arm: both are registered only as
per-candidate, one-action rules. The author has declared the following
prospectively, and `longhorizon_v30.DECLARED_SET_SCORES` carries each one
marked `DECLARED.` against the exact-EBU arm's `DERIVED.`, so the distinction
survives in the code and not only in this file.

**A. The matched non-EBU comparator (arm B).** Rank sets by their member force
values in **descending lexicographic order**; accepted quantities are the next
tie level only. On a one-action set this is exactly the registered
per-candidate rule "largest `f`, tie by larger `q_acc`, then lower edge index,
then lower quantity-menu index", which is the only fidelity claim made for it.
The quantities are the **accepted** ones from the joint cap, never the menu's
independently clamped figures, so this arm ranks the vector that would execute
exactly as the exact-EBU arm does.

Sets of different size compare by the standard lexicographic **prefix rule**: a
shorter key ranks below any key extending it, implemented by padding each
segment to width `m` with `-inf`. This is safe only under the registered menu
invariant - a candidate enters the menu only when `J_e = M_e*[f_e - theta_e]_+`
is positive with `theta_e >= 0`, so `f_e > 0` for every real menu candidate -
because under it the prefix rule and zero-padding coincide, and a second action
can never be appended to raise a set's rank while making it physically worse.
`longhorizon_v30` **enforces** that invariant rather than assuming it: a
non-positive member force is refused, not ranked.

*How far this is from the alternatives.* Over 125 force grids at `m = 2`, the
declared rule selects **exactly** what largest-total-force selects, every time.
With strictly positive per-edge forces the lexicographic argmax is the pair of
the two largest forces - and so is the sum argmax, because adding a positive
force always raises a sum. The two therefore **select identically** and differ
only in their induced ranking, which is never used. Against maximum-of-set and
average-of-set the declared rule does diverge. So of the three aggregations
this document previously named as the open alternatives, the declaration is
observationally identical to one and distinguishable from the other two. It
remains a declaration.

**B. The stock-blind control (arm S).** Rank sets by **total accepted delivered
service to positive-demand destinations**:

`sum over members of  eta_e * q_acc_e * 1[declared demand rate of the destination > 0]`

On a one-action set this is exactly the registered per-candidate score
`eta_e * q_acc * 1[demand > 0]`, ties by lower edge index then lower
quantity-menu index. Its declared limitation - blindness to destination stock
buffers - is preserved: no destination stock, no potential and no quote enters
the score, which the test suite asserts by AST inspection of the selector.

**C. Final ties.** The ascending tuple of edge identifiers, then the ascending
tuple of quantity-menu identifiers. This generalizes the registered
"deterministic identifiers only, no hidden physical objective" from one
`(edge, quant_index)` pair to the tuples of a set. **No cardinality preference
is imposed** - an earlier draft imposed one that is registered nowhere, and it
was removed. Where a one-action set does win a tie against a two-action set, it
wins because its edge tuple is a prefix, not because fewer actions are
preferred.

### What is still NOT derivable - do not invent it

**The settlement form for a multi-action tick is not determined.**
The locked plan prohibits "no aggregate-quote settlement (O3 open)" and marks
`E_aggregate_source_group_quote` as "NOT REGISTERED FOR EXECUTION (O3 open):
no settling aggregate arm exists in this study". Selecting on a joint value is
not settling on one, and recording the triple without allocation is explicitly
registered as non-settling - so the rule above stays inside the prohibition.
But what is *settled and recorded as the tick's EBU* when two actions execute
is fixed by no committed authority. **Unresolved, and it blocks execution.**

It is recorded in code as `longhorizon_v30.OPEN_LAUNCH_GATES`, and the
`DecisionRecord` type cannot carry a settled value at all: `settled_ebu` and
`allocation_between_actions` are permanently `None` and `o3_open` is
permanently `True`.

### Operation count at `m = 2`

Counted by instrumenting `d0_v29.penalty` around one `evaluate_action_sets`
call on one frozen synthetic state - a pure-function call count, not a tick.
With one source, `sum d_out(s) = 2`, and `F` fractions per edge, the
enumeration is `2F` singletons plus `F*F` pairs. A singleton touches two cells;
a pair touches three.

| `F` | menu `K = 2F` | singletons | pairs | sets | `d0.penalty` calls | vs the superseded per-candidate rule |
|---|---|---|---|---|---|---|
| 2 | 4 | 4 | 4 | 8 | 88 | 5.50x |
| 4 | 8 | 8 | 16 | 24 | 288 | 9.00x |
| **5** | **10** | **10** | **25** | **35** | **430** | **10.75x** |
| 8 | 16 | 16 | 64 | 80 | 1,024 | 16.00x |

One `ebu_quote_v30.QuoteSchedule.exact(q)` performs exactly **4** penalty
evaluations (counted, not assumed), so `F = 5` costs **107.5 exact-quote
equivalents**. D5's committed `exact` unit cost is 1,773.812 ns, the mean of
its forward and reversed medians (1,779.583 and 1,768.042 ns), so that is about
**190,685 ns** of ranking arithmetic per decision - an upper bound, since the
`exact` unit carries per-call overhead a batched enumeration does not repeat.

This is **added to** the committed per-record figure, not substituted into it.
The D5 E-settled record performs `m` settlements and one fixed joint replica
and evaluates no per-candidate exact quote at all; refitting its committed
cells gives `t_record(K) = 36,764 + 204.2*K` ns, or **38,806 ns** at `K = 10`.
So the exact-EBU arm projects to **229,491 ns** per record, about **5.91x** the
record alone.

**These are projections, not measurements.** They are arithmetic over D5's
committed unit-operation costs on one Apple M4 Pro. They are not a new
benchmark, not AWS throughput, not a host recommendation, and not a cost
estimate in any currency.

Two facts about *which* arms pay it were previously mis-stated here and are
corrected: as implemented, **three of the four arms** reach their selector
through `evaluate_action_sets`, which quotes every enumerated set, so arms B
and S pay the enumeration cost even though their declared scores never read the
quote. Arm A is the released `p1c_step` on the full world and is **not costed
at all** - no committed measurement covers a `p1c_step` tick, and none is
invented. Any total is therefore a lower bound over three arms of four.

The conclusion from §11 survives: the three menu arms over 1,600 ticks project
to about **1.10 s** of local single-threaded CPU, which is not a compute
problem. `V3.0_LONG_HORIZON_COST_AND_LAUNCH_PLAN.md` re-derives this together
with memory, storage and checkpoint costs, and identifies the one quantity that
does scale badly - checkpoint write amplification, which is quadratic in the
number of checkpoints under the full-rewrite atomic write.

## 14. Non-claims

This candidate, and any study built from it, must not claim:

- **no EBU wallet** — cumulative signed EBU is an evaluation variable, never a
  balance, never spendable, never a price;
- **no allocation and no causal attribution** — joint EBU is never divided among
  actions, and `double_count` is a named endpoint comparison, not a
  decomposition and not a cause;
- **no O3 settlement** — O3 remains open;
- **no external validity** — results hold inside the declared synthetic worlds
  and nowhere else;
- **no theorem claim from numerical results** — a numerical study cannot prove a
  general proposition, and no run here is evidence for any theorem;
- **no Gate 1E claim** — Gate 1E remains registered and untouched; Gate 2
  remains paused;
- **no empirical calibration** — no parameter above estimates anything real.
