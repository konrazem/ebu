# EBP V2.9 — Preregistered Behavioral-Validation Protocol (DRAFT)

**Status: design and preregistration only.** This document registers, *before any
V2.9 experiment is run*, the research question, models, worlds, parameters, outcome
definitions, hypotheses, falsification criteria, and statistical protocol for testing
whether the V2.8 local loss-aware law produces useful *behavior*. **No V2.9 engine,
test, experiment, figure, PDF, or result exists at this gate.** Success is defined
here so the later implementation cannot redefine it after seeing results.

Epistemic labels are used strictly throughout: **Definition / Hypothesis / Required
invariant / Experimental criterion / Falsification criterion / Open question / Not
claimed.**

Baseline: the `v2.8.0` release (merge commit `05ba912`). The V2.8 mathematics
(`Foundation_v2.8_discrete_draft.md`), all engines (`energy_balance.py`,
`ebu_v22.py`–`ebu_v26.py`), the EBU ledger, and all released tests are **frozen** and
are not modified by V2.9.

---

## 1. Central research question

> **When the V2.8 local loss-aware law is repeatedly applied by spatially local
> processes, does it produce bounded, viable, demand-serving and regenerative
> behavior without actors evaluating global system state or simulating the future?**

This decomposes into questions that must never be conflated, because they have
different evidence standards and different failure modes:

| # | Question | Kind |
|---|----------|------|
| Q1 | Does each D0 tick obey the V2.8 inequality (Theorem 4.4/6.1)? | theorem consistency (validation of implementation, not proof) |
| Q2 | Does repeated D0 evolution remain bounded over long horizons? | dynamical stability (partly beyond the proved one-step results) |
| Q3 | Does mathematical burden reduction (decreasing `V`) produce actual *viability*? | functional success — **not implied by Q1/Q2** |
| Q4 | Is demand actually served, rather than stability achieved through hoarding? | functional success / anti-hoarding |
| Q5 | Are regenerative (Allee) sources preserved? | functional success |
| Q6 | Does the law recover from disturbances (supply/demand/efficiency/topology shocks)? | functional success |
| Q7 | What changes when flows are limited by a finite population of actors? | approximation study (Stage B, outside the V2.8 theorem) |

**Not claimed:** that a positive answer to Q1/Q2 implies positive answers to Q3–Q6.
Hypothesis H10 makes measuring that gap an explicit objective.

## 2. Definitions

**Definition 2.1 (world).** A directed graph of cells `i` with state `x_i`, per-cell
parameters `(K_i, L_i, U_i, α_i, β_i, χ_i, s_i, d_i, λ_i, κ_i, ρ_i, A_i)` and
per-edge parameters `(M_e, θ_e, η_e)`, exactly as in V2.8 §2 (Defs 2.1–2.4). The
reserve is `R_i = A_i + δ` on regenerative cells (V2.4 convention), else inactive.

**Definition 2.2 (the local law under test).** The V2.8 loss-aware Onsager flux:
`f_e = μ_i − η_e μ_j`, `J_e = M_e[f_e − θ_e]₊`, with `μ = ∇V` for
`v_i(x) = α_i[L_i−x]₊² + β_i[x−U_i]₊² + χ_i[R_i−x]₊²`.

**Definition 2.3 (D0 tick — Stage A).** One synchronous frozen-state explicit-Euler
step (V2.8 Def 3.2): all forces and fluxes computed from the single frozen state
`xⁿ`, then `x^{n+1} = xⁿ + Δt(u(xⁿ) + S J(xⁿ))`. No clipping, no sequential
application, no conflict scaling.

**Definition 2.4 (certified timestep).** `Δt_certified` is a step size for which a
V2.8 sufficient bound guarantees per-tick non-increase of `V` in the undriven case:
either the spectral bound `2/(L_V‖S D_M^{1/2}‖₂²)` (Thm 5.2), the active-set bound
(Thm 5.5), or the degree-weighted Gershgorin bound (Rmk 5.4). Every run reports
`r_Δt = Δt / Δt_certified` and *which* certificate produced `Δt_certified` (§4.3).

**Definition 2.5 (burn-in).** A preregistered initial segment of each run excluded
from post-burn-in means (but never from theorem-consistency checks, which apply to
every tick).

## 3. Two stages, kept prominently separate

### Stage A — theorem-compatible D0 field flow

Each directed edge is a *local transport opportunity* — a process, not an agent.
Every tick:

```
read frozen local state (both endpoints of each edge)
calculate local force        f_e = μ_i − η_e μ_j
calculate local edge flux    J_e = M_e [f_e − θ_e]₊
combine all fluxes           S J
apply one synchronous update x ← x + Δt (u + S J)
```

This is the **first** behavioral system to test because it is exactly the object the
V2.8 theorems govern. Any Stage-A theorem-consistency failure is a bug or a genuine
counterexample and must be reported (Falsification F1).

### Stage B — actor-constrained approximation

A finite population of actors can activate only a subset of edges per tick. **This
is not automatically covered by the V2.8 theorem** and is registered as a separate
experiment, never silently as "the D0 law". Candidate constraints (registered here,
final values fixed in the implementation gate *before* confirmatory runs):

- actor position (a cell; stationary in the base variant);
- one local observation radius (base: 1 hop — the actor sees its own cell and von
  Neumann neighbours only);
- maximum carried/transferred quantity per tick (`q_max`);
- maximum one edge traversal or action per tick per actor;
- conflict rule when several actors select overlapping cells: proportional source
  scaling (DE-core convention) **or** random priority — the chosen rule is a
  registered design axis, not a tunable;
- simultaneous (frozen-state) versus sequential execution — simultaneous is the
  default for Stage B so that any Stage-B deviation from D0 is attributable to
  *sparsity*, not to sequencing; sequential execution appears only in ablation P3;
- actor density and `q_max` swept upward as an approximation ladder to the full D0
  field flow.

**Experimental criterion (Stage-B convergence).** Stage B "approaches D0" if the
paired per-tick state discrepancy `max_t ‖x_actor(t) − x_D0(t)‖∞` and every Class-C
functional metric (§10) converge monotonically-in-trend toward the D0 values as
actor density and `q_max` increase, on paired layouts and seeds. Hypothesis H9;
Falsification F9.

## 4. Information boundary

### 4.1 What a local decision process may read

An edge process (Stage A) or actor (Stage B) deciding a transfer on edge `(i, j)`
may read **only**:

- the source cell state `x_i` and its declared local parameters
  (`L_i, U_i, K_i, α_i, β_i, χ_i, R_i, x_min_i`);
- the destination neighbour's state `x_j` and the same declared parameters;
- edge efficiency `η_ij`, mobility `M_ij`, activation threshold `θ_ij`;
- locally available capacity and declared reserve information (headroom
  `K_j − x_j`, source floor).

### 4.2 What it must not read or calculate

- total `V` (any global functional);
- global viability or any experiment evaluation metric;
- total grid resources;
- any non-neighbouring cell's state;
- an all-pairs path or global routing structure;
- the global future trajectory, counterfactual rollouts, or any `H`-tick simulation
  (the V2.3/V2.4 horizon machinery is explicitly *not* part of the law under test);
- global EBU balances (the ledger is frozen and outside the decision loop, §15).

**Definition 4.2.1 (evaluation/decision separation).** `V`, viability, served
demand, and all §10 metrics are computed by the *researcher harness* for evaluation.
They are never inputs to any decision function.

### 4.3 The timestep certificate is designer knowledge, not actor knowledge

- A **global spectral certificate** (`λ_max` of the Gram matrix, Thm 5.2/5.5) may be
  computed by the experiment designer once per world as a *proof certificate*. It is
  configuration, not actor knowledge: no decision function receives it.
- A **conservative local certificate** must also be implemented so the experiment
  does not depend solely on an expensive global solve: the degree-weighted
  Gershgorin bound of V2.8 Rmk 5.4, computable from each edge's local incidences
  (`Δt ≤ 2 / (L_V · max_e M_e[(1+η_e²) + Σ_{e'≠e}|S_e·S_{e'}|])`), with `L_V` from
  the declared per-cell weights. This is still designer-side configuration.
- **Required invariant (certificate reporting):** every run records which
  certificate produced `Δt_certified`, its value, and `r_Δt`.

### 4.4 Planned automated enforcement (implementation gate)

**Required invariant (information boundary).** The decision function's signature
must accept only a local view object (two endpoint states + declared parameters +
edge constants). A planned automated test **fails** if:

- the decision function receives the world/grid object, the full state vector, or
  any harness metric;
- a probe world where all *non-neighbouring* cell states are replaced by NaN (or a
  guard proxy that raises on read) changes the decision output or triggers a read;
- decisions on a translated/isolated copy of the local neighbourhood differ from
  decisions in the full world (locality-by-construction check).

These boundary tests belong to `test_v29.py` (planned, §14) and are Class-A
outcomes (§10-A); a violation is Falsification F2.

## 5. Registered comparison models (policies)

All policies share identical physics parameters, layouts, seeds, disturbances, and
accounting wherever comparison is meaningful. Unavoidable semantic differences are
documented here, not hidden.

| Policy | Definition | Status vs V2.8 theorem |
|--------|------------|------------------------|
| **P0 — no transport** | natural dynamics only (`J ≡ 0`) | baseline; theorem trivially inactive |
| **P1 — exact D0** | loss-aware, frozen-state, synchronous edge flow (Def 2.3), unconstrained state | the theorem object |
| **P1K — bounded D0** | P1 plus physical clamping: demand saturation at empty cells and clip-with-accounted-spill at `0`/`K` | **outside the theorem** (clipping/saturation are V2.8 §11 exclusions); required for driven long-horizon worlds; every clamp event is counted and reported |
| **P2 — loss-blind ablation** | replace `f_e = μ_i − ημ_j` with `μ_i − μ_j` (all else identical to P1/P1K) | ablation; V2.8 Counterexample D predicts failure modes as `η` falls |
| **P3 — sequential-live ablation** | otherwise-identical transfers applied one at a time against live state, in descending-force order (DE-family convention) | ablation; V2.8 Obs 9.2 predicts causal-radius violations |
| **P4 — oversized-step ablation** | P1 with `Δt` above the certified bound (`r_Δt > 1`) | ablation; V2.8 Counterexample A predicts overshoot |
| **P5 — V2.4 threshold-aware engine** | the existing, unmodified `ebu_v24.step_v24(rule="threshold_penalty")` | practical comparator; **explicitly not theorem-equivalent** (post-drive marginals, loss-blind force, sequential execution, line-searched sizing, clipping) |
| **P6 — actor-limited D0 approximation** | Stage-B model of §3 (frozen-state simultaneous, sparse activation) | separate second-stage model, outside the theorem |

**Documented semantic differences.** (i) P1 is unconstrained, so in driven worlds
its state can leave `[0, K]` and "serve demand" from nothing — therefore *functional*
(Class C) metrics are primarily assessed on P1K, while *theorem-consistency*
(Class A) metrics are primarily assessed on P1; both are reported. (ii) P5 applies
drive before transport and evaluates marginals post-drive; its per-tick metrics are
aligned by tick boundary, not by sub-step. (iii) P3's transfer order is a registered
choice (descending force); randomized-order P3 is an exploratory variant only.
(iv) No released implementation (V2.4/V2.5/V2.6) is changed.

## 6. Registered worlds

Progressively harder fixtures. W1–W5 include **undriven theorem-compatible**
variants (no supply/demand/regen/leak; unconstrained; H2 applies); W7–W15 are
**driven regenerative worlds outside the existing convergence theorem** (reported as
behavior, not as theorem tests).

| # | World | Purpose |
|---|-------|---------|
| W1 | two cells, one/two edges | smallest fixture; analytic expectations |
| W2 | three-cell relay chain | locality, relay transport, causal radius |
| W3 | small line and ring (n = 8) | boundary vs periodic effects |
| W4 | checkerboard supply/demand grid | dense alternating gradients |
| W5 | genuinely randomized grid | stochastic primary comparisons |
| W6 | clustered supply spatially separated from demand | long transport chains |
| W7 | logistic regenerative sources | driven regeneration |
| W8 | Allee-threshold sources | reserve preservation (Q5, H6) |
| W9 | finite stocks (`ρ = 0`) | depletion behavior |
| W10 | external flows (supply/leak only) | open-system throughput |
| W11 | mixed-source world (logistic + Allee + finite + external) | heterogeneous realism |
| W12 | supply shock (cut `s` at shock tick) | recovery (Q6) |
| W13 | demand shock (step `d` up at shock tick) | recovery (Q6) |
| W14 | transport-efficiency shock (drop `η` at shock tick) | loss-awareness under stress (H4) |
| W15 | partial topology/edge failure (remove a fraction of edges) | robustness |

**Required invariant (layout diversity).** All randomized layouts must genuinely
change across seeds: a planned test hashes each generated layout (cells, edges,
parameters, initial state) and **fails** if supposedly different seeds produce
identical layouts unexpectedly.

## 8. Outcome classes — mathematical stability is not functional success

### Class A — theorem consistency (Required invariants; validation, not proof)

- per-tick V2.8 inequality residual `V(x^{n+1}) − V(xⁿ) − [drive − dissipation + R_n]`
  (must be ≤ 0 up to declared tolerance `1e-9·(1+|V|)` on P1 ticks satisfying D0
  assumptions);
- count and maximum magnitude of violations (target for P1: **zero**, H1/F1);
- stock/loss ledger residual per tick (Thm 8.1; tolerance `1e-12·scale`); for P1K,
  the ledger extends with counted spill/saturation terms and must still reconcile;
- causal-radius violations (one-hop probe, Thm 9.1) for synchronous policies;
- local-information-boundary violations (§4.4).

### Class B — dynamical stability (Experimental criteria)

- boundedness of the state trajectory (`max_t ‖x(t)‖∞` finite and, for P1K, within
  `[0, K]` by construction — so for P1K boundedness is assessed on P1's unconstrained
  twin where meaningful);
- boundedness of `V(t)`;
- post-burn-in trend of `V` (sign of a robust linear fit over the last 50% of the
  run);
- classification into: converged / bounded oscillation / unbounded accumulation /
  collapse (each defined numerically in the implementation gate before confirmatory
  runs, from tail variance and trend);
- sensitivity of all of the above to `r_Δt` and to graph size.

**Not claimed / not accepted:** "the simulation did not crash" is not a stability
definition and will not be reported as one.

### Class C — functional success (Experimental criteria)

- percentage of viable cells (`x_i ≥ L_i`), final and post-burn-in mean;
- cumulative and post-burn-in demand served; cumulative unmet demand
  (unmet = `max(0, d_i − available)` per tick; meaningful in P1K/P5/P6);
- regenerative reserve crossings (ticks with `x_i < R_i` on regenerative cells);
- permanently dead sources (Allee cells with `x < A` and non-positive regeneration
  at run end);
- shock-recovery time (ticks from shock until viability ≥ 90% of its pre-shock
  post-burn-in mean) and persistence of recovery (must hold ≥ 100 consecutive
  ticks — the V2.4 "sustained recovery" convention);
- transport loss `(1−η)`-outflow and total transport work.

### Class D — anti-hoarding condition (Experimental criterion)

A run is **not** called successful merely because it preserves sources by refusing
to serve demand. Preregistered combined requirement — **preserve AND serve**:

```
preserve: zero permanently dead sources AND reserve-crossing fraction ≤ 5% of
          regenerative-cell-ticks post-burn-in
serve:    post-burn-in demand served ≥ 95% AND final-tick viability ≥ 85%
          AND post-burn-in mean viability ≥ 90%
success:  preserve AND serve
```

These thresholds are **experimental criteria** (conventional, not theorem-derived);
a sensitivity analysis at ±5 percentage points around each threshold is required,
and conclusions that flip within that band must be reported as fragile. Both final
values and post-burn-in means are always reported side by side, so a favorable mean
cannot conceal terminal collapse.

## 9. Preregistered hypotheses

Stated as hypotheses, **not** conclusions:

- **H1.** Exact D0 (P1) has zero theorem-inequality violations under its declared
  assumptions and tolerances.
- **H2.** In undriven feasible worlds, P1 produces non-increasing `V` at the
  certified timestep (`r_Δt ≤ 1`).
- **H3.** Oversized timesteps (P4, `r_Δt > 1`) reproduce the predicted overshoot,
  including the exact Counterexample-A threshold on its fixture.
- **H4.** Loss-aware D0 (P1/P1K) outperforms the loss-blind ablation (P2) on Class-C
  metrics, with the gap widening as `η` decreases below 1.
- **H5.** Synchronous D0 preserves the declared one-hop causal radius; the
  sequential-live ablation (P3) can violate it.
- **H6.** Including regenerative-reserve pressure in `μ` (`χ > 0`) reduces
  Allee-threshold crossings and permanently dead sources relative to `χ = 0`.
- **H7.** For a nonempty feasible region of supply, demand, regeneration and loss,
  P1K achieves bounded preserve-and-serve behavior (§8-D).
- **H8.** Outside that feasible region the law cannot manufacture capacity: collapse
  or unmet demand occurs, and is reported as the *correct* physical outcome, not as
  policy failure.
- **H9.** Stage-B actor-limited behavior (P6) approaches P1 as actor density and/or
  `q_max` increase (§3 convergence criterion).
- **H10.** A decreasing `V` is **not assumed** to imply functional success; the
  measured relationship between Class-B and Class-C outcomes is itself a primary
  result, whatever its direction.

## 10. Preregistered falsification criteria

Outcomes that count **against** the model and must be reported, never tuned away:

1. **F1.** Any V2.8 inequality violation under exact D0 assumptions beyond declared
   numerical tolerance.
2. **F2.** Nonlocal information used by a supposedly local decision (any §4.4 test
   failure).
3. **F3.** Persistent increase of `V` in an undriven certified P1 run.
4. **F4.** Correctly decreasing `V` while viability or served demand collapses
   (mathematics-behavior divergence).
5. **F5.** Stability achieved only through hoarding (passes "preserve", fails
   "serve", across the sensitivity band).
6. **F6.** Repeated destruction of regenerative sources despite reserve-aware
   marginal pressure (`χ > 0`).
7. **F7.** Loss-aware D0 performing systematically worse than loss-blind transport
   (P2) for reasons that cannot be explained and documented.
8. **F8.** Dependence on one deterministic layout presented as stochastic evidence
   (layout-hash test failure, or conclusions that vanish across seeds).
9. **F9.** Actor-limited performance failing to approach D0 even with increasing
   density/capacity.
10. **F10.** Stability requiring per-action global optimization or future rollout
    (i.e., only policies that violate the information boundary succeed).

## 11. Statistical and reporting protocol

- paired seeds for every policy comparison (identical layout + disturbance per
  seed);
- report mean, standard deviation, median, and range per metric; **paired
  differences** with confidence intervals where appropriate (bootstrap percentile CI
  over the ≥ 30/40 paired seeds; nonparametric sign test as the robustness check);
- individual-run results stored (one record per run, machine-readable), never only
  aggregates;
- **phase maps** over swept axes (e.g. `η × d`, `r_Δt × M`, density × `q_max`), not
  only selected example trajectories;
- final and post-burn-in measurements reported together (§8-D);
- deterministic fixtures (W1–W3 analytic cases) reported separately from stochastic
  studies (W5+);
- exact commands, seeds, and parameter files recorded with every reported table;
- **no claim of scale invariance** from only a few grid sizes — grid-size results
  are reported per size with the tested range stated;
- **no "strict dominance" claim** unless it holds in every declared paired case and
  every declared metric.

**Exploratory vs confirmatory.** Seeds 0–9 and any parameter exploration are
*exploratory*; they may inform implementation and protocol amendments. Confirmatory
results use only preregistered seeds 100–139 and the parameters of §7. Any protocol
amendment after exploratory runs must be committed to this document *before* the
confirmatory runs execute, with a changelog entry; confirmatory runs may be executed
exactly once per protocol version.

## 13. Explicit scope exclusions

V2.9 must **not** introduce: transferable EBU; markets; prices; exchange; debt;
ownership; strategic ledger agents; learning adversaries; changes to V2.5/V2.6
accounting; or any claim about replacing money. V2.9 tests whether the *physical
local law* produces useful system behavior. The EBU ledger remains frozen and
**outside the decision loop** (observational only, exactly as released in V2.5).

## 14. Code-review notes and documented discrepancies (no released file modified)

Reviewed for accuracy of the descriptions above: `energy_balance.py`, `ebu_v24.py`,
`ebu_v25.py`, `ebu_v26.py`, `test_math.py`, `test_v28.py`,
`Foundation_v2.7_math.md`, `Foundation_v2.8_discrete_draft.md`,
`results/v2.8/MANIFEST.md`. Findings:

- **No released engine implements Stage A.** DE-core/DE24/DE26 all split drive from
  transport, evaluate marginals post-drive, and apply transfers sequentially; a new
  `d0_v29.py` is therefore required rather than reuse — this matches V2.8 Def 3.3
  and Assumption 3.4 and is a design consequence, not a code defect.
- **Actor-based proposal narrowing.** The released engines let each actor propose
  only its single steepest out-edge; exact D0 requires *all* eligible edges to flow.
  Stage B therefore resembles the released engines' sparsity more than P1 does —
  useful for interpreting P5/P6 differences.
- **Unconstrained vs physical state.** The V2.8 theorems are unconstrained; every
  released engine clips to `[0, K]` and saturates demand. The protocol handles this
  with the explicit P1 / P1K split (§5) instead of pretending one model does both.
- **P5's reserve marginal** (`ebu_v24.marg`) is applied only in reserve-aware rules
  (`threshold_penalty`, `penalty_horizon`); the registered P5 comparator is
  `threshold_penalty` — the V2.4 recommended practical rule.
- **Ledger separation is already clean in V2.5:** with `selection="physics"` the
  physics trajectory is identical regardless of ledger mode, which is exactly the
  observational role §13 requires.

- **Open question:** Stage-B conflict rule (proportional scaling vs random

  before confirmatory runs.
- **Open question:** whether P1K's saturation events should also gate a "feasible
  region" estimate for H7/H8 (a-priori feasibility from totals vs empirical).

  be documented before runs; if none is available, H7/H8 regions are mapped

- **Not claimed:** any V2.9 result will *prove* the V2.8 theorems, extend them to
  the DE family, or establish multi-tick convergence for driven worlds — those
  remain open mathematics (V2.8 §13).

## 17. Pre-implementation Amendment 1 (2026-07-26)

**Status:** registered *before* any V2.9 implementation code was written or any

### 17.1 Stage-B conflict rule (frozen default; future gate)

The finite-actor default is registered as **frozen-state proportional scaling**:

1. all actors observe the same frozen state `xⁿ`;
2. actors propose actions independently (no communication);
3. proposals are grouped by source cell;
4. if the proposed withdrawals from a source exceed its locally available
   capacity, **all** withdrawals from that source are scaled proportionally;
5. the scaled transfers are applied simultaneously;
6. actor enumeration order cannot affect the result (Required invariant, to be
   tested when Stage B is implemented).

This composite (scaling + simultaneous application) is **outside the current D0
theorem** and will be implemented only in a later gate. Sequential-live
application remains registered exclusively as ablation P3, never as the default.

### 17.2 P1K definition (frozen)

P1K is a **diagnostic physical wrapper around the unconstrained D0 proposal**.
The exact raw proposal is computed first, with flux decisions unchanged:

```
y = x + Δt (u + S J)
```

Then, per cell with declared physical interval `[0, K_i]`:

```
x'_i        = min(K_i, max(0, y_i))
shortfall_i = [−y_i]₊           (lower-bound shortfall)
spill_i     = [y_i − K_i]₊
x'_i        = y_i + shortfall_i − spill_i     (identity, checked exactly)
```

The term **"lower-bound shortfall"** is used rather than "unmet demand": the
deficit at the floor can be caused by demand, leakage, or excessive transport-out,
and the per-cell components of `u` and `(SJ)_i` are preserved in diagnostics so
later attribution is possible.

**Required invariant (P1K ledger):**

```
Σ_i (x'_i − x_i) = Δt [ Σ_i u_i − Σ_e (1−η_e) J_e ] + Σ_i shortfall_i − Σ_i spill_i
```

Prominent statements: **P1K is outside the V2.8 D0 theorem** (clipping/projection
is a §11 exclusion of the note); **clipping is never silent** (every shortfall and
spill is recorded and reported); **a P1K run cannot be cited as direct
confirmation of the unconstrained theorem.**

### 17.3 Feasibility classification (frozen necessary-condition screen)

A registered world is screened by **necessary-but-not-sufficient** conditions:

1. **Total balance:** long-run available external input plus sustainable
   regeneration is not smaller than demand plus leakage plus an estimated
   unavoidable transport loss (`(1−η)` on required flows).
2. **Source-side sustainability:** no requirement exceeds a source's maximum
   sustainable isolated yield; for logistic regeneration this is
   `g_max = ρK/4` (V2.7 Thm 3.1).
3. **Path existence:** every net-demand cell is reachable in the transport graph
   from some net-supply or sustainable-regeneration cell.
4. **Cut capacity (estimate):** for spatially separated worlds (W6), the
   per-tick transport capacity across the separating cut is not smaller than the
   far side's net demand; labeled an estimate because realizable flux depends on
   forces.
5. **Allee accounting:** Allee sources are counted as sustainably available
   **only** above their driven reserve `x_r` (V2.7 Thm 4.2); below it their
   yield counts as 0.

Total-balance and cut-capacity checks are **necessary conditions, not guarantees
of functional success**. A world failing a necessary condition is still simulated
where registered (H8), and its collapse is reported as the correct physical
outcome — never as evidence that the local law failed to manufacture impossible
capacity, and never silently excluded.

### 17.4 Stability classification (frozen dimensionless rules)

Floating-point tolerance and scientific thresholds are separate: Class-A theorem
consistency uses `1e-9·(1+|V|)` (numerical); everything below is scientific.

Let `B` be the burn-in end, `W` the post-burn-in window, split into quarters
`Q1..Q4`. Scale floor: `s₀ = max( V(x_B), 10⁻³·V(x₀), 10⁻⁹ )`. Define:

- normalized trend `τ = (mean_{Q4} V − mean_{Q1} V) / s₀`;
- normalized amplitude `a = (max_{Q4} V − min_{Q4} V) / s₀`;
- state-boundedness flag: `max_{t∈W} ‖x(t)‖∞ ≤ 10·max_i K_i` (P1 only; P1K is
  bounded by construction);
- normalized stock `σ(t) = Σ_i x_i(t) / Σ_i x_i(0)`.

Frozen classes (evaluated in this order; first match wins):

| Class | Rule |
|-------|------|
| **accumulation** | state-boundedness flag fails, or `τ > +0.05` with `mean V` increasing across all consecutive quarter pairs |
| **collapse** | `σ(end) < 0.05` and `σ` non-recovering (no `t` in `Q4` with `σ(t) > 0.10`) |
| **converged** | `|τ| ≤ 0.01` and `a ≤ 0.01` |
| **bounded oscillation** | bounded, not accumulating/collapsing/converged, and `a > 0.01` with `|τ| ≤ 0.05` |
| **unclassified** | anything else (reported as such, never folded into a success class) |

Rationale: `0.01` sits far above double-precision noise on the metrics' scales
and below any scientifically claimed change; `0.05`/`5%` are conventional
sensitivity-tested margins (§8-D band applies). These are **experimental
criteria**, distinct from theorem consistency, functional preserve-and-serve
success (§8-D, unchanged), and from each other.

**Deterministic calibration procedure (analytic fixtures only).** Before any
stochastic V2.9 run, the cutoffs are checked against four analytic fixtures with
known ground truth: (i) logistic harvest at a stable fixed point → must classify
**converged**; (ii) the flip 2-cycle at `ρ = 2.6` (V2.7 §3) → **bounded
oscillation**; (iii) logistic harvest with `h > ρK/4` from below the basin →
**collapse**; (iv) a constant positive drive on an unconstrained cell →
**accumulation**. If any fixture misclassifies, cutoffs are adjusted using
analytic fixtures alone and the change is recorded here. Seeds 0–9 and 100–139
are **not** consulted for calibration in this gate.

## 18. Pre-experiment Amendment 2 — bounded-wrapper interpretation and semantic corrections (2026-07-26)

**Status:** registered *before* any V2.9 behavioral experiment (exploratory or
confirmatory). Motivated by a reproduced Gate-1.1 diagnostic fixture: when the raw
D0 withdrawal exceeds the source's physically available stock, exact D0 drives the
source negative while the destination still receives the full lossy inflow; P1K
then projects the source back to zero and its ledger closes **only because the
lower-bound shortfall appears as an explicit positive projection correction**. The
ledger is not in error — but lower projection can make a destination appear served
by stock the source never physically possessed. This amendment restricts
interpretation accordingly. It does not delete or weaken H1–H10, F1–F10, or
Amendment 1.

### 18.1 Restricted P1K interpretation (Required invariants of interpretation)

1. P1K is a **diagnostic projection wrapper**, not a physically realized
   constrained transport law.
2. **P1K ledger closure does not prove that every delivered transfer was
   physically available** (the closure includes the projection corrections by
   construction).
3. A run with **material lower-bound shortfall is ineligible** for a successful
   "preserve AND serve" conclusion (§8-D).
4. P1K shortfall must **never** automatically be called unmet demand: the deficit
   at the floor may be caused by demand, leakage, or excessive transport-out, and
   requires causal attribution before naming.
5. Destination service occurring during a lower-bound projection **must not be
   counted as valid physical service**.
6. P1K's legitimate use is to **detect where exact D0 leaves the physically
   admissible state space** (and to keep long-horizon driven runs bounded for
   diagnosis).
7. P1K remains **outside the V2.8 theorem**.
8. Exact D0/P1 behavioral success may be claimed **only** for trajectories that
   remain inside the declared physical domain **without projection**.

**Definition (boundary tolerance).** To distinguish floating-point noise from
material projection:

```
tau_b = 1e-12 * max(1, max_i K_i, max_i |y_i|)
material_shortfall = max_i(shortfall_i) > tau_b
material_spill     = max_i(spill_i)     > tau_b
```

Exact shortfall and spill values are always recorded **without rounding**,
regardless of this classification. A material shortfall makes the run ineligible
for physical preserve-and-serve success. Material **spill** does not by itself
invalidate physicality (discarded excess can be physically meaningful), but it is
counted as loss and prevents claiming exact unconstrained D0 behavior for that
tick.

### 18.2 Registered future policy P1C (NOT implemented in this gate)

**P1C — capacity-constrained synchronous realization** (tentative name):

1. calculate local proposals from one frozen state;
2. determine the physically available withdrawal at each source;
3. proportionally scale competing withdrawals at that source;
4. apply the scaled lossy transfers simultaneously;
5. record unmet local requests and spill explicitly;
6. preserve actor/edge ordering invariance.

P1C is **outside the existing V2.8 theorem** and requires separate mathematical
and empirical analysis before any claim. P1 is **not** silently replaced by P1C;
they are distinct registered policies.

### 18.3 Corrected supply/demand semantics (frozen)

- `s` — **non-negative** baseline external supply;
- `s_extra` — **non-negative** tick-dependent additional supply;
- `d` — **non-negative** baseline demand;
- `d_extra` — **non-negative** tick-dependent additional demand;
- regeneration remains a separate **signed** local term where the declared law
  permits it (Allee below threshold is negative by physics);
- leakage remains non-negative.

An arbitrary signed test drive `u` is represented by the decomposition
`u = u⁺ − u⁻` with `u⁺ = max(u, 0)` as supply and `u⁻ = max(−u, 0)` as demand.
Negative supply is rejected by the engine and is not used anywhere — including in
cross-conformance tests — as a signed-drive escape hatch.

### 18.4 Accumulation-order contract (corrected scope)

Synchronous accumulation of edge contributions is **permutation invariant within a
declared strict floating-point tolerance**. The current implementation accumulates
per-cell contributions with `math.fsum` (a correctly-rounded sum on IEEE-754
doubles), and the tested fixtures are observed bit-identical under edge
reordering — but **cross-platform bit identity is not promised**: it is not a
mathematical guarantee across every Python build and hardware platform unless a
canonical accumulation order is enforced end-to-end. Conformance tests therefore
assert permutation invariance within a strict scale-aware tolerance and *report*
the observed residual, rather than requiring universal bit identity.

## 20. Amendment 4 — Preservation Architecture Adoption (2026-07-27)

**Status: additive protocol adoption.** This amendment adopts, as *registered
design targets for later gates*, the preservation architecture corrected and
proved-where-possible by the independent Gate-2.1B review
(`V2.9_OBJECTIVE_ALIGNMENT_REVIEW.md`), which is the **controlling correction**
of the earlier proposal in `V2.9_OBJECTIVE_ALIGNMENT_DRAFT.md`. It adds
definitions, frozen semantics, next-gate ordering, and open problems. It does
**not** rewrite or weaken §§17–19 (Amendments 1–3), does **not** alter the
historical wording of H1–H10 or F1–F10, and does **not** touch any engine,
test, experiment, result, or the two objective-alignment documents. Nothing is
implemented, calculated, or simulated in this gate.

### 20.1 Purpose

**V2.8 supplies a loss-aware local physical flow law and a discrete dissipation
theorem under its stated assumptions. It does not provide a hard
regenerative-reserve guarantee. Gate 2.1B derived a separate barrier-certified
aggregate export constraint. V2.9 adopts that constraint as the candidate
preservation architecture to be implemented and tested in later gates.**

**The preservation architecture is designed so that future regenerative risk is
encoded in present local source properties. An actor does not evaluate global
`V`, inspect the whole world, or simulate future trajectories when choosing an
action.**

> **Not claimed.** The preservation architecture has **not** been behaviorally
> validated. Adoption here is registration of a design target and its frozen
> semantics; validation is deferred to Gates 2.2–2.4 (§20.15). Nothing in this
> amendment is a consequence of the V2.8 theorem, and no Gate-2 result (D1–D8)
> is reinterpreted or contradicted by it.

### 20.2 Adopted source update and units

Adopt the per-source synchronous update (matches `d0_v29.py:377`, aggregating
all outgoing edges rather than treating one action as the whole export):

```
x_i^{n+1} = x_i^n + Δt ( u_i^n + I_i^n − Q_i^n ),                          (A4.1)
```

| symbol | meaning | units |
|---|---|---|
| `x_i` | physical stock | stock |
| `u_i^n` | on-site natural net drive `s+g−d−λ−κx` | stock · time⁻¹ |
| `I_i^n` | certified incoming **usable** flow (post-loss) | stock · time⁻¹ |
| `Q_i^n = Σ_{e∈out(i)} q_e` | aggregate source withdrawal **rate** (pre-loss) | stock · time⁻¹ |
| `q_e` | accepted withdrawal rate on outgoing edge `e` | stock · time⁻¹ |
| `Δt > 0` | tick duration | time |
| `R_i^eff` | effective regenerative reserve | stock |

Every term of (A4.1) is dimensionally `[stock]` (`Δt · rate = stock`). Transport
efficiency affects **destination receipt**:

```
destination receipt on edge e = η_e q_e,                                  (A4.2)
```

but the **source loses the full `q_e`**. Therefore **source preservation is
governed by the pre-loss withdrawal `q_e` (hence `Q_i`), not by `η_e q_e`.**

### 20.3 Adopted conservative safe-export budget and feasibility

Adopt the conservative action-time **aggregate** budget:

```
Q_{i,max}^n = [ x_i^n + Δt·u_i^n − R_i^eff ]_+ / Δt.                       (A4.3)
```

Frozen interpretation:

1. it is an **aggregate source withdrawal-rate budget**, not a separate
   allowance for each edge or actor;
2. **uncommitted incoming flow is not counted**;
3. **certified** incoming flow may be recorded diagnostically, but the first
   P1C implementation **must conservatively ignore it** when constructing
   `Q_{i,max}` (the proof of Theorem 4.1 uses `I_i ≥ 0` only as one-sided slack);
4. allowing certified incoming flow to *expand* the budget requires a later,
   separately reviewed amendment;
5. the budget is valid **only together with** the separate feasibility
   condition (A4.4).

Adopt the feasibility condition:

```
x_i^n + Δt·u_i^n ≥ R_i^eff.                                                (A4.4)
```

> **Replacing a negative budget with zero does not guarantee preservation if the
> no-export successor already lies below the reserve.** (When (A4.4) fails,
> `Q_{i,max}^n = 0` by the clamp, yet `x_i^{n+1} = x_i^n + Δt(u_i + I_i) <
> R_i^eff` when `I_i = 0`: the source is *locally infeasible*, State I of §20.7,
> not preserved.)

### 20.4 Adopted robust (tolerance-aware) budget — no empirical values

Register the tolerance-aware candidate:

```
Q_{i,max}^rob = [ (x_i^n − ε_{x,i}) + Δt(u_i^n − ε_{u,i}) − R_i^eff ]_+ / Δt,   (A4.5)
```

with `ε_{x,i}` a stock-measurement/error margin and `ε_{u,i}` a drive-rate
uncertainty margin. Four **distinct** margin kinds must be kept separate and
never conflated:

1. **numerical floating-point tolerance** (as in Class-A theorem checks,
   `1e-9·(1+|V|)` etc. — a rounding budget, not a physical margin);
2. **physical measurement uncertainty** (`ε_{x,i}`, `ε_{u,i}`);
3. **ecological-model uncertainty** (parameter/law error);
4. **discretionary ecological safety margin `δ_i`**.

**No empirical value for any margin is chosen in this gate.** All margins must be
**preregistered before confirmatory preservation experiments** and **must not be
fitted after observing D9/D10 outcomes**.

### 20.5 Adopted preservation-state classification

Mutually distinguishable action-time states (evaluated on the frozen state):

- **State P — preservable:** `x_i^n ≥ R_i^eff` **and** `x_i^n + Δt·u_i^n ≥
  R_i^eff`. The source may export up to its aggregate safe budget (A4.3)/(A4.5).
- **State R — recovery required:** `x_i^n < R_i^eff`. Default export budget is
  **zero**; the source requires regeneration, restoration, or certified inflow
  before ordinary extraction resumes. **Even if positive drive would lift it
  above reserve during the same tick, the first P1C implementation must remain
  conservative and permit no export when the source begins the tick below
  reserve.**
- **State I — locally reserve-infeasible:** `x_i^n ≥ R_i^eff` **but**
  `x_i^n + Δt·u_i^n < R_i^eff`. Zero export cannot prevent the next reserve
  violation. The system must **report the state as locally infeasible without
  external support** and must **not** claim the local preservation controller
  succeeded.
- **State F — unrestricted / noncritical flow:** used **only** for declared
  external flow sources governed by a flow cap rather than a stock reserve.

> **Invariance status (Gate 2.1B).** Do not call the entire safe set
> automatically forward-invariant. **The reserve set is controlled-invariant only
> on its one-step feasibility kernel** `K₁ = { x ∈ S : x_i + Δt·u_i ≥ R_i^eff for
> every critical i }`. **The infinite-horizon kernel remains an open problem**
> (§20.16).

### 20.6 Adopted P1C semantics (next implementation target)

Register **P1C** as the next implementation target, with the frozen tick order:

1. freeze the current state;
2. compute on-site drives;
3. construct local views;
4. compute each edge's raw requested withdrawal `q_e^req`;
5. group requested withdrawals by source;
6. compute each source's preservation state (§20.5) and aggregate budget
   (A4.3)/(A4.5);
7. apply source-local **proportional** allocation;
8. apply all accepted transfers **simultaneously**;
9. record service, loss, rationing, feasibility, and reserve diagnostics;
10. compute evaluation-only global metrics **after** decisions are complete.

For a **preservable** source (State P), with
`Q_i^req = Σ_{e∈out(i)} q_e^req`: if `Q_i^req > 0`, define

```
σ_i = min( 1, Q_{i,max}^rob / Q_i^req ),   q_e^acc = σ_i · q_e^req.        (A4.6)
```

If `Q_i^req = 0`, all accepted exports are zero. For **recovery-required (R)** or
**locally infeasible (I)** sources, the default accepted export is **zero**.

Frozen required P1C properties: aggregate preservation budget; source-local
coordination; synchronous application; proportional allocation; edge-order
invariance within declared numerical tolerance; no phantom stock; no global
objective evaluation; no future rollout; no hidden use of evaluation metrics;
explicit rationing and unmet-service accounting.

> **P1C remains outside the V2.8 theorem until separately proved** (it is a
> barrier-certified constrained allocation / projected law; the V2.8 descent
> theorem assumes the unconstrained flux and does not transfer — Gate 2.1B §8.3).

### 20.7 Adopted service interpretation

Service may be counted **only from physically accepted and delivered flow**:

```
q_e^delivered = η_e · q_e^acc.                                            (A4.7)
```

- raw requested flow is **not** service;
- projected shortfall is **not** service;
- unbacked withdrawal is **not** service.

When requested demand exceeds safe deliverable supply, record: requested demand;
accepted withdrawal; delivered stock; unmet demand; preservation state; and the
reason for rationing or infeasibility.

> A policy **must not** receive a "preserve and serve" success label if
> preservation was achieved only by hiding demand or invalidating service
> accounting (consistent with §8-D and Amendment 2 §18.1).

### 20.8 Adopted source-type interpretation

- **external renewable flow:** flow-cap semantics (State F);
- **logistic regenerative stock:** reserve **plus** the local one-tick export
  budget (A4.3);
- **Allee regenerative stock:** driven-root-based effective reserve plus margin
  (A4.8);
- **finite / non-regenerating stock:** positive extraction is **depletion**, not
  sustainable regeneration;
- **irreversible ecological capacity:** safe extraction rate **zero**; loss
  enters irreversible debt (§20.9).

For logistic sources, `(1−m)·ρK/4` is an **equilibrium-oriented long-run
ceiling, not a universal per-tick guarantee from arbitrary initial stock**
(V2.7 Thm 3.1–3.3; realised safe export is `min(Q_{i,max}, (1−m)ρK/4)` and even
that requires basin and flip conditions).

For Allee sources, adopt the **candidate design-time certification** (not a
proved universal formula):

```
R_i^eff ≥ sup_{ω∈Ω_i} x_{r,i}(ω) + δ_i,                                    (A4.8)
```

where `x_{r,i}(ω)` is the driven unstable middle root (V2.7 Thm 4.2) over the
declared operating envelope `Ω_i`. The envelope `Ω_i`, margin `δ_i`, timestep
effect, and uncertainty margins must be **declared before confirmatory
experiments**.

### 20.9 Adopted ecological-debt semantics (design target)

Adopt a resource-specific debt **vector** `D = (D_1, …, D_m)`. For account `r`:

```
D_r^{n+1} = max( 0, D_r^n + O_r^n + Λ_r^n − Ĉ_r^n ).                       (A4.9)
```

Frozen principles: all terms in account `r` use the same physical resource unit;
**no cross-account netting**; wallet/token transfer cannot reduce physical debt;
labour alone cannot reduce physical debt; payment alone cannot reduce physical
debt; **only verified physical restoration may reduce reversible debt**;
irreversible debt cannot be repaid by tokens or unrelated restoration;
finite-resource extraction must be reported as depletion even if socially
authorised; the debt equation is a **design target, not implemented in this
gate**. The split `D_r = D_r^rev + D_r^irr` has `D_r^irr` monotone
non-decreasing (`Ĉ_r` never reduces it).

> A detailed **attribution formula** for `O_r`, `Λ_r`, or `Ĉ_r` is **not** frozen
> here; those remain **open implementation definitions requiring later review**
> (§20.16).

### 20.10 Adopted restoration-credit semantics (account-scoped only)

Adopt only the account-scoped principle:

```
1 unit of verified net reduction in D_r  ↔  1 unit of restoration credit
                                            in account r.                 (A4.10)
```

Later implementation must include: no-action counterfactual; action-burden
debit; persistence; live-state telescoping; no double-credit; no
natural-regeneration credit; damage-then-repair non-profitability; split-action
invariance; multi-actor attribution; collusion resistance.

> **V2.5 and V2.6 do not yet implement this complete restoration-credit
> definition.** (V2.5 provides live-state telescoping and loss/extraction debits;
> V2.6 found a confirmed guarded exploit on 1 of 12 layouts. Neither provides the
> counterfactual, persistence, irreversibility, or resource-specificity above.)

### 20.11 Adopted scalar-EBU restriction

**A single fungible scalar EBU is not yet scientifically justified.** The next
accounting implementation must begin with **resource-specific accounts**.
Scalarisation requires a **separately reviewed** rule for conversion,
normalisation, or constrained exchange between non-substitutable accounts. **No
conversion weight, ecological price, or universal energy-equivalent factor may be
silently introduced.** This does **not** reject the long-term EBU monetary
concept; it prevents premature aggregation from hiding ecological damage.

### 20.12 Adopted information boundary

P1C decisions **may read**: own-source stock; own-source drive and regeneration
parameters; own-source type; own effective reserve `R_i^eff`; own **remaining
aggregate source budget**; requested outgoing actions; adjacent destination
information already permitted by the local flow rule (V2.9 §4 /
`d0_v29.LocalView`).

P1C decisions **may not read**: global `V`; world-wide viability; global debt;
whole-world state; future trajectories; evaluation summaries; confirmatory
outcomes.

> `R_i^eff` may be computed through **design-time ecological certification** or
> **slow monitoring updates** and stored in the present local field. **It is not
> recomputed through a global solve on every action.** Three timescales are kept
> distinct: design-time certification (non-local, once), slow monitoring updates
> (out-of-band), and action-time local decisions (every tick, local only).
