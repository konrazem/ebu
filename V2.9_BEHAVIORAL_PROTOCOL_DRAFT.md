# EBP V2.9 — Preregistered Behavioral-Validation Protocol (DRAFT)

**Status: design and preregistration only.** This document registers, *before any
V2.9 experiment is run*, the research question, models, worlds, parameters, outcome
definitions, hypotheses, falsification criteria, and statistical protocol for testing
whether the V2.8 local loss-aware law produces useful *behavior*. **No V2.9 engine,
test, experiment, figure, PDF, or result exists at this gate.** Success is defined
here so the later implementation cannot redefine it after seeing results.

Epistemic labels are used strictly throughout: **Definition / Hypothesis / Required
invariant / Experimental criterion / Falsification criterion / Open question / Not
claimed.**

Baseline: the `v2.8.0` release (merge commit `05ba912`). The V2.8 mathematics
(`Foundation_v2.8_discrete_draft.md`), all engines (`energy_balance.py`,
`ebu_v22.py`–`ebu_v26.py`), the EBU ledger, and all released tests are **frozen** and
are not modified by V2.9.

---

## 1. Central research question

> **When the V2.8 local loss-aware law is repeatedly applied by spatially local
> processes, does it produce bounded, viable, demand-serving and regenerative
> behavior without actors evaluating global system state or simulating the future?**

This decomposes into questions that must never be conflated, because they have
different evidence standards and different failure modes:

| # | Question | Kind |
|---|----------|------|
| Q1 | Does each D0 tick obey the V2.8 inequality (Theorem 4.4/6.1)? | theorem consistency (validation of implementation, not proof) |
| Q2 | Does repeated D0 evolution remain bounded over long horizons? | dynamical stability (partly beyond the proved one-step results) |
| Q3 | Does mathematical burden reduction (decreasing `V`) produce actual *viability*? | functional success — **not implied by Q1/Q2** |
| Q4 | Is demand actually served, rather than stability achieved through hoarding? | functional success / anti-hoarding |
| Q5 | Are regenerative (Allee) sources preserved? | functional success |
| Q6 | Does the law recover from disturbances (supply/demand/efficiency/topology shocks)? | functional success |
| Q7 | What changes when flows are limited by a finite population of actors? | approximation study (Stage B, outside the V2.8 theorem) |

**Not claimed:** that a positive answer to Q1/Q2 implies positive answers to Q3–Q6.
Hypothesis H10 makes measuring that gap an explicit objective.

## 2. Definitions

**Definition 2.1 (world).** A directed graph of cells `i` with state `x_i`, per-cell
parameters `(K_i, L_i, U_i, α_i, β_i, χ_i, s_i, d_i, λ_i, κ_i, ρ_i, A_i)` and
per-edge parameters `(M_e, θ_e, η_e)`, exactly as in V2.8 §2 (Defs 2.1–2.4). The
reserve is `R_i = A_i + δ` on regenerative cells (V2.4 convention), else inactive.

**Definition 2.2 (the local law under test).** The V2.8 loss-aware Onsager flux:
`f_e = μ_i − η_e μ_j`, `J_e = M_e[f_e − θ_e]₊`, with `μ = ∇V` for
`v_i(x) = α_i[L_i−x]₊² + β_i[x−U_i]₊² + χ_i[R_i−x]₊²`.

**Definition 2.3 (D0 tick — Stage A).** One synchronous frozen-state explicit-Euler
step (V2.8 Def 3.2): all forces and fluxes computed from the single frozen state
`xⁿ`, then `x^{n+1} = xⁿ + Δt(u(xⁿ) + S J(xⁿ))`. No clipping, no sequential
application, no conflict scaling.

**Definition 2.4 (certified timestep).** `Δt_certified` is a step size for which a
V2.8 sufficient bound guarantees per-tick non-increase of `V` in the undriven case:
either the spectral bound `2/(L_V‖S D_M^{1/2}‖₂²)` (Thm 5.2), the active-set bound
(Thm 5.5), or the degree-weighted Gershgorin bound (Rmk 5.4). Every run reports
`r_Δt = Δt / Δt_certified` and *which* certificate produced `Δt_certified` (§4.3).

**Definition 2.5 (burn-in).** A preregistered initial segment of each run excluded
from post-burn-in means (but never from theorem-consistency checks, which apply to
every tick).

## 3. Two stages, kept prominently separate

### Stage A — theorem-compatible D0 field flow

Each directed edge is a *local transport opportunity* — a process, not an agent.
Every tick:

```
read frozen local state (both endpoints of each edge)
calculate local force        f_e = μ_i − η_e μ_j
calculate local edge flux    J_e = M_e [f_e − θ_e]₊
combine all fluxes           S J
apply one synchronous update x ← x + Δt (u + S J)
```

This is the **first** behavioral system to test because it is exactly the object the
V2.8 theorems govern. Any Stage-A theorem-consistency failure is a bug or a genuine
counterexample and must be reported (Falsification F1).

### Stage B — actor-constrained approximation

A finite population of actors can activate only a subset of edges per tick. **This
is not automatically covered by the V2.8 theorem** and is registered as a separate
experiment, never silently as "the D0 law". Candidate constraints (registered here,
final values fixed in the implementation gate *before* confirmatory runs):

- actor position (a cell; stationary in the base variant);
- one local observation radius (base: 1 hop — the actor sees its own cell and von
  Neumann neighbours only);
- maximum carried/transferred quantity per tick (`q_max`);
- maximum one edge traversal or action per tick per actor;
- conflict rule when several actors select overlapping cells: proportional source
  scaling (DE-core convention) **or** random priority — the chosen rule is a
  registered design axis, not a tunable;
- simultaneous (frozen-state) versus sequential execution — simultaneous is the
  default for Stage B so that any Stage-B deviation from D0 is attributable to
  *sparsity*, not to sequencing; sequential execution appears only in ablation P3;
- actor density and `q_max` swept upward as an approximation ladder to the full D0
  field flow.

**Experimental criterion (Stage-B convergence).** Stage B "approaches D0" if the
paired per-tick state discrepancy `max_t ‖x_actor(t) − x_D0(t)‖∞` and every Class-C
functional metric (§10) converge monotonically-in-trend toward the D0 values as
actor density and `q_max` increase, on paired layouts and seeds. Hypothesis H9;
Falsification F9.

## 4. Information boundary

### 4.1 What a local decision process may read

An edge process (Stage A) or actor (Stage B) deciding a transfer on edge `(i, j)`
may read **only**:

- the source cell state `x_i` and its declared local parameters
  (`L_i, U_i, K_i, α_i, β_i, χ_i, R_i, x_min_i`);
- the destination neighbour's state `x_j` and the same declared parameters;
- edge efficiency `η_ij`, mobility `M_ij`, activation threshold `θ_ij`;
- locally available capacity and declared reserve information (headroom
  `K_j − x_j`, source floor).

### 4.2 What it must not read or calculate

- total `V` (any global functional);
- global viability or any experiment evaluation metric;
- total grid resources;
- any non-neighbouring cell's state;
- an all-pairs path or global routing structure;
- the global future trajectory, counterfactual rollouts, or any `H`-tick simulation
  (the V2.3/V2.4 horizon machinery is explicitly *not* part of the law under test);
- global EBU balances (the ledger is frozen and outside the decision loop, §15).

**Definition 4.2.1 (evaluation/decision separation).** `V`, viability, served
demand, and all §10 metrics are computed by the *researcher harness* for evaluation.
They are never inputs to any decision function.

### 4.3 The timestep certificate is designer knowledge, not actor knowledge

- A **global spectral certificate** (`λ_max` of the Gram matrix, Thm 5.2/5.5) may be
  computed by the experiment designer once per world as a *proof certificate*. It is
  configuration, not actor knowledge: no decision function receives it.
- A **conservative local certificate** must also be implemented so the experiment
  does not depend solely on an expensive global solve: the degree-weighted
  Gershgorin bound of V2.8 Rmk 5.4, computable from each edge's local incidences
  (`Δt ≤ 2 / (L_V · max_e M_e[(1+η_e²) + Σ_{e'≠e}|S_e·S_{e'}|])`), with `L_V` from
  the declared per-cell weights. This is still designer-side configuration.
- **Required invariant (certificate reporting):** every run records which
  certificate produced `Δt_certified`, its value, and `r_Δt`.

### 4.4 Planned automated enforcement (implementation gate)

**Required invariant (information boundary).** The decision function's signature
must accept only a local view object (two endpoint states + declared parameters +
edge constants). A planned automated test **fails** if:

- the decision function receives the world/grid object, the full state vector, or
  any harness metric;
- a probe world where all *non-neighbouring* cell states are replaced by NaN (or a
  guard proxy that raises on read) changes the decision output or triggers a read;
- decisions on a translated/isolated copy of the local neighbourhood differ from
  decisions in the full world (locality-by-construction check).

These boundary tests belong to `test_v29.py` (planned, §14) and are Class-A
outcomes (§10-A); a violation is Falsification F2.

## 5. Registered comparison models (policies)

All policies share identical physics parameters, layouts, seeds, disturbances, and
accounting wherever comparison is meaningful. Unavoidable semantic differences are
documented here, not hidden.

| Policy | Definition | Status vs V2.8 theorem |
|--------|------------|------------------------|
| **P0 — no transport** | natural dynamics only (`J ≡ 0`) | baseline; theorem trivially inactive |
| **P1 — exact D0** | loss-aware, frozen-state, synchronous edge flow (Def 2.3), unconstrained state | the theorem object |
| **P1K — bounded D0** | P1 plus physical clamping: demand saturation at empty cells and clip-with-accounted-spill at `0`/`K` | **outside the theorem** (clipping/saturation are V2.8 §11 exclusions); required for driven long-horizon worlds; every clamp event is counted and reported |
| **P2 — loss-blind ablation** | replace `f_e = μ_i − ημ_j` with `μ_i − μ_j` (all else identical to P1/P1K) | ablation; V2.8 Counterexample D predicts failure modes as `η` falls |
| **P3 — sequential-live ablation** | otherwise-identical transfers applied one at a time against live state, in descending-force order (DE-family convention) | ablation; V2.8 Obs 9.2 predicts causal-radius violations |
| **P4 — oversized-step ablation** | P1 with `Δt` above the certified bound (`r_Δt > 1`) | ablation; V2.8 Counterexample A predicts overshoot |
| **P5 — V2.4 threshold-aware engine** | the existing, unmodified `ebu_v24.step_v24(rule="threshold_penalty")` | practical comparator; **explicitly not theorem-equivalent** (post-drive marginals, loss-blind force, sequential execution, line-searched sizing, clipping) |
| **P6 — actor-limited D0 approximation** | Stage-B model of §3 (frozen-state simultaneous, sparse activation) | separate second-stage model, outside the theorem |

**Documented semantic differences.** (i) P1 is unconstrained, so in driven worlds
its state can leave `[0, K]` and "serve demand" from nothing — therefore *functional*
(Class C) metrics are primarily assessed on P1K, while *theorem-consistency*
(Class A) metrics are primarily assessed on P1; both are reported. (ii) P5 applies
drive before transport and evaluates marginals post-drive; its per-tick metrics are
aligned by tick boundary, not by sub-step. (iii) P3's transfer order is a registered
choice (descending force); randomized-order P3 is an exploratory variant only.
(iv) No released implementation (V2.4/V2.5/V2.6) is changed.

## 6. Registered worlds

Progressively harder fixtures. W1–W5 include **undriven theorem-compatible**
variants (no supply/demand/regen/leak; unconstrained; H2 applies); W7–W15 are
**driven regenerative worlds outside the existing convergence theorem** (reported as
behavior, not as theorem tests).

| # | World | Purpose |
|---|-------|---------|
| W1 | two cells, one/two edges | smallest fixture; analytic expectations |
| W2 | three-cell relay chain | locality, relay transport, causal radius |
| W3 | small line and ring (n = 8) | boundary vs periodic effects |
| W4 | checkerboard supply/demand grid | dense alternating gradients |
| W5 | genuinely randomized grid | stochastic primary comparisons |
| W6 | clustered supply spatially separated from demand | long transport chains |
| W7 | logistic regenerative sources | driven regeneration |
| W8 | Allee-threshold sources | reserve preservation (Q5, H6) |
| W9 | finite stocks (`ρ = 0`) | depletion behavior |
| W10 | external flows (supply/leak only) | open-system throughput |
| W11 | mixed-source world (logistic + Allee + finite + external) | heterogeneous realism |
| W12 | supply shock (cut `s` at shock tick) | recovery (Q6) |
| W13 | demand shock (step `d` up at shock tick) | recovery (Q6) |
| W14 | transport-efficiency shock (drop `η` at shock tick) | loss-awareness under stress (H4) |
| W15 | partial topology/edge failure (remove a fraction of edges) | robustness |

**Required invariant (layout diversity).** All randomized layouts must genuinely
change across seeds: a planned test hashes each generated layout (cells, edges,
parameters, initial state) and **fails** if supposedly different seeds produce
identical layouts unexpectedly.

## 8. Outcome classes — mathematical stability is not functional success

### Class A — theorem consistency (Required invariants; validation, not proof)

- per-tick V2.8 inequality residual `V(x^{n+1}) − V(xⁿ) − [drive − dissipation + R_n]`
  (must be ≤ 0 up to declared tolerance `1e-9·(1+|V|)` on P1 ticks satisfying D0
  assumptions);
- count and maximum magnitude of violations (target for P1: **zero**, H1/F1);
- stock/loss ledger residual per tick (Thm 8.1; tolerance `1e-12·scale`); for P1K,
  the ledger extends with counted spill/saturation terms and must still reconcile;
- causal-radius violations (one-hop probe, Thm 9.1) for synchronous policies;
- local-information-boundary violations (§4.4).

### Class B — dynamical stability (Experimental criteria)

- boundedness of the state trajectory (`max_t ‖x(t)‖∞` finite and, for P1K, within
  `[0, K]` by construction — so for P1K boundedness is assessed on P1's unconstrained
  twin where meaningful);
- boundedness of `V(t)`;
- post-burn-in trend of `V` (sign of a robust linear fit over the last 50% of the
  run);
- classification into: converged / bounded oscillation / unbounded accumulation /
  collapse (each defined numerically in the implementation gate before confirmatory
  runs, from tail variance and trend);
- sensitivity of all of the above to `r_Δt` and to graph size.

**Not claimed / not accepted:** "the simulation did not crash" is not a stability
definition and will not be reported as one.

### Class C — functional success (Experimental criteria)

- percentage of viable cells (`x_i ≥ L_i`), final and post-burn-in mean;
- cumulative and post-burn-in demand served; cumulative unmet demand
  (unmet = `max(0, d_i − available)` per tick; meaningful in P1K/P5/P6);
- regenerative reserve crossings (ticks with `x_i < R_i` on regenerative cells);
- permanently dead sources (Allee cells with `x < A` and non-positive regeneration
  at run end);
- shock-recovery time (ticks from shock until viability ≥ 90% of its pre-shock
  post-burn-in mean) and persistence of recovery (must hold ≥ 100 consecutive
  ticks — the V2.4 "sustained recovery" convention);
- transport loss `(1−η)`-outflow and total transport work.

### Class D — anti-hoarding condition (Experimental criterion)

A run is **not** called successful merely because it preserves sources by refusing
to serve demand. Preregistered combined requirement — **preserve AND serve**:

```
preserve: zero permanently dead sources AND reserve-crossing fraction ≤ 5% of
          regenerative-cell-ticks post-burn-in
serve:    post-burn-in demand served ≥ 95% AND final-tick viability ≥ 85%
          AND post-burn-in mean viability ≥ 90%
success:  preserve AND serve
```

These thresholds are **experimental criteria** (conventional, not theorem-derived);
a sensitivity analysis at ±5 percentage points around each threshold is required,
and conclusions that flip within that band must be reported as fragile. Both final
values and post-burn-in means are always reported side by side, so a favorable mean
cannot conceal terminal collapse.

## 9. Preregistered hypotheses

Stated as hypotheses, **not** conclusions:

- **H1.** Exact D0 (P1) has zero theorem-inequality violations under its declared
  assumptions and tolerances.
- **H2.** In undriven feasible worlds, P1 produces non-increasing `V` at the
  certified timestep (`r_Δt ≤ 1`).
- **H3.** Oversized timesteps (P4, `r_Δt > 1`) reproduce the predicted overshoot,
  including the exact Counterexample-A threshold on its fixture.
- **H4.** Loss-aware D0 (P1/P1K) outperforms the loss-blind ablation (P2) on Class-C
  metrics, with the gap widening as `η` decreases below 1.
- **H5.** Synchronous D0 preserves the declared one-hop causal radius; the
  sequential-live ablation (P3) can violate it.
- **H6.** Including regenerative-reserve pressure in `μ` (`χ > 0`) reduces
  Allee-threshold crossings and permanently dead sources relative to `χ = 0`.
- **H7.** For a nonempty feasible region of supply, demand, regeneration and loss,
  P1K achieves bounded preserve-and-serve behavior (§8-D).
- **H8.** Outside that feasible region the law cannot manufacture capacity: collapse
  or unmet demand occurs, and is reported as the *correct* physical outcome, not as
  policy failure.
- **H9.** Stage-B actor-limited behavior (P6) approaches P1 as actor density and/or
  `q_max` increase (§3 convergence criterion).
- **H10.** A decreasing `V` is **not assumed** to imply functional success; the
  measured relationship between Class-B and Class-C outcomes is itself a primary
  result, whatever its direction.

## 10. Preregistered falsification criteria

Outcomes that count **against** the model and must be reported, never tuned away:

1. **F1.** Any V2.8 inequality violation under exact D0 assumptions beyond declared
   numerical tolerance.
2. **F2.** Nonlocal information used by a supposedly local decision (any §4.4 test
   failure).
3. **F3.** Persistent increase of `V` in an undriven certified P1 run.
4. **F4.** Correctly decreasing `V` while viability or served demand collapses
   (mathematics-behavior divergence).
5. **F5.** Stability achieved only through hoarding (passes "preserve", fails
   "serve", across the sensitivity band).
6. **F6.** Repeated destruction of regenerative sources despite reserve-aware
   marginal pressure (`χ > 0`).
7. **F7.** Loss-aware D0 performing systematically worse than loss-blind transport
   (P2) for reasons that cannot be explained and documented.
8. **F8.** Dependence on one deterministic layout presented as stochastic evidence
   (layout-hash test failure, or conclusions that vanish across seeds).
9. **F9.** Actor-limited performance failing to approach D0 even with increasing
   density/capacity.
10. **F10.** Stability requiring per-action global optimization or future rollout
    (i.e., only policies that violate the information boundary succeed).

## 11. Statistical and reporting protocol

- paired seeds for every policy comparison (identical layout + disturbance per
  seed);
- report mean, standard deviation, median, and range per metric; **paired
  differences** with confidence intervals where appropriate (bootstrap percentile CI
  over the ≥ 30/40 paired seeds; nonparametric sign test as the robustness check);
- individual-run results stored (one record per run, machine-readable), never only
  aggregates;
- **phase maps** over swept axes (e.g. `η × d`, `r_Δt × M`, density × `q_max`), not
  only selected example trajectories;
- final and post-burn-in measurements reported together (§8-D);
- deterministic fixtures (W1–W3 analytic cases) reported separately from stochastic
  studies (W5+);
- exact commands, seeds, and parameter files recorded with every reported table;
- **no claim of scale invariance** from only a few grid sizes — grid-size results
  are reported per size with the tested range stated;
- **no "strict dominance" claim** unless it holds in every declared paired case and
  every declared metric.

**Exploratory vs confirmatory.** Seeds 0–9 and any parameter exploration are
*exploratory*; they may inform implementation and protocol amendments. Confirmatory
results use only preregistered seeds 100–139 and the parameters of §7. Any protocol
amendment after exploratory runs must be committed to this document *before* the
confirmatory runs execute, with a changelog entry; confirmatory runs may be executed
exactly once per protocol version.

## 13. Explicit scope exclusions

V2.9 must **not** introduce: transferable EBU; markets; prices; exchange; debt;
ownership; strategic ledger agents; learning adversaries; changes to V2.5/V2.6
accounting; or any claim about replacing money. V2.9 tests whether the *physical
local law* produces useful system behavior. The EBU ledger remains frozen and
**outside the decision loop** (observational only, exactly as released in V2.5).

## 14. Code-review notes and documented discrepancies (no released file modified)

Reviewed for accuracy of the descriptions above: `energy_balance.py`, `ebu_v24.py`,
`ebu_v25.py`, `ebu_v26.py`, `test_math.py`, `test_v28.py`,
`Foundation_v2.7_math.md`, `Foundation_v2.8_discrete_draft.md`,
`results/v2.8/MANIFEST.md`. Findings:

- **No released engine implements Stage A.** DE-core/DE24/DE26 all split drive from
  transport, evaluate marginals post-drive, and apply transfers sequentially; a new
  `d0_v29.py` is therefore required rather than reuse — this matches V2.8 Def 3.3
  and Assumption 3.4 and is a design consequence, not a code defect.
- **Actor-based proposal narrowing.** The released engines let each actor propose
  only its single steepest out-edge; exact D0 requires *all* eligible edges to flow.
  Stage B therefore resembles the released engines' sparsity more than P1 does —
  useful for interpreting P5/P6 differences.
- **Unconstrained vs physical state.** The V2.8 theorems are unconstrained; every
  released engine clips to `[0, K]` and saturates demand. The protocol handles this
  with the explicit P1 / P1K split (§5) instead of pretending one model does both.
- **P5's reserve marginal** (`ebu_v24.marg`) is applied only in reserve-aware rules
  (`threshold_penalty`, `penalty_horizon`); the registered P5 comparator is
  `threshold_penalty` — the V2.4 recommended practical rule.
- **Ledger separation is already clean in V2.5:** with `selection="physics"` the
  physics trajectory is identical regardless of ledger mode, which is exactly the
  observational role §13 requires.

## 15. Open questions and unresolved design decisions

- **Open question:** numeric definitions of the four Class-B stability classes
  (tail-variance/trend cutoffs) — to be fixed in the implementation gate before
  confirmatory runs.
- **Open question:** Stage-B conflict rule (proportional scaling vs random
  priority) — registered as a design axis; the default must be chosen and committed
  before confirmatory runs.
- **Open question:** whether P1K's saturation events should also gate a "feasible
  region" estimate for H7/H8 (a-priori feasibility from totals vs empirical).
- **Open question:** the exact feasibility characterisation for H7/H8 (supply +
  regeneration ≥ demand + losses along achievable routes) — an a-priori sketch will
  be documented before runs; if none is available, H7/H8 regions are mapped
  empirically and labeled as such.
- **Not claimed:** any V2.9 result will *prove* the V2.8 theorems, extend them to
  the DE family, or establish multi-tick convergence for driven worlds — those
  remain open mathematics (V2.8 §13).
