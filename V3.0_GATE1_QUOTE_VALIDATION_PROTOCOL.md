## 2. Frozen implementation target

The Gate-1 deliverable is a **pure observational quote module**:

- no mutation of physical state;
- no wallet mutation;
- no actor-health logic;
- no global evaluation;
- no future rollout;
- no P1C replacement (P1C remains the physical permission layer, unchanged);
- no EBU exchange.

**Registered intended future files (NOT created in this gate):**
`ebu_quote_v30.py`, `test_v30_quote.py`, `audit_v30_quote.py`,
`results/v3.0/gate1/`. None of these may exist before the commit that
introduces this protocol and plan is pushed; creating them is Gate 1B work
under separate authorization.

The quote law under validation is frozen in the plan's `quote_law` block:
`z = x + Δt·u(x)`;
`Δe(q) = V_loc(z) − V_loc(z + Δt S_e q) − C_a(q)` on `[0, q_acc]`;
settlement is the exact finite-difference value at the measured point of the
schedule committed before execution; the linear form
`Δt q(μ_i − η μ_j) − C_a(q)` is a diagnostic only.

## 4. Registered falsifiers (F1–F12)

F1 a quote requires global state or future rollout. F2 natural regeneration
produces actor credit. F3 a closed undriven damage–repair cycle earns
positive net EBU. F4 splitting produces more total EBU than the equivalent
aggregate action within the declared first-model scope. F5 a positive quote
bypasses P1C. F6 adding the observational quote changes the physical
trajectory. F7 a partial execution is valued by an after-the-fact rule not
contained in the committed schedule. F8 unauthorized overexecution receives
positive credit. F9 a represented physical burden is counted again in `C_a`.
F10 the V2.6 adversary earns positive EBU while producing persistent
physical harm under P1C within the declared search space. F11 a wallet,
actor health value, price, or global metric enters the quote. F12 a test
passes only because every action is zero or every edge is inactive.

**All failures are reported, never tuned away. A triggered falsifier is a
result.**

## 5. Fixtures, random checks, and tolerances (frozen)

- **Deterministic analytic fixtures first**: E1, E2, E3, the regeneration
  fixture (`ρ=0.4, K=20, x=10 ⇒ g=2, z=12`, idle quote 0), and the split
  counterexample (32 vs 20), with the exact expected values frozen in the
  plan's `worked_examples` block.
- **Conformance seed: 30001** — a fresh seed not used by any earlier study.
- **Prohibited during conformance:** behavioral seeds 0–9 (V2.9 exploratory)
  and 100–139 (V2.9 confirmatory). V2.6 layout seeds 0–11 appear **only**
  inside the Q22 replay protocol, which is not conformance and runs only in
  a later authorized gate.
- **Frozen ranges and counts** (plan `random_checks`): `x ∈ [0, 24]`;
  `α, β ∈ {0.5, 1, 2}`; `χ ∈ {0, 1}`; `R ∈ {0, 8}`;
  `η ∈ {0.5, 0.7, 0.9, 1.0}`; `Δt ∈ {0.2, 1.0}`; `q` uniform in
  `[0, q_acc]`; `c₀ ∈ {0, 0.05}`; `λ_L ∈ {0, 0.1}`. Case counts per group
  as fixed in the plan (e.g. Q6: 16 branch fixtures + 200 random; Q7: 100;
  Q8: 100×5; Q10/Q11: 50 sequences each).
- **Non-vacuity (F12 guard):** at least 50% of generated random cases per
  group must have `q > 0` and exact-quote magnitude `> 10⁻⁶`; a vacuous
  group fails.
- **Tolerances:** analytic fixtures `1e-9·(1+|expected|)`; identities
  `1e-9·(1+|V|)`; ledger-style checks `1e-12·scale`; Q17 byte-identity =
  exact float tuple equality; JSON safety fail-closed (`allow_nan=False`).
- **Random checks are numerical validation only, never proof.**
- **No behavioral trajectory may run in this gate**, and none may run during
  conformance.

## 6. Change control

This protocol and the plan may be amended only by normal commits with a
dated changelog entry here, never after the confirmatory conformance run of
the affected group has started. Confirmatory conformance executes exactly
once per plan version. A passing regression suite of the released code
validates the released code only — it does not validate the V3.0 quote law,
and V3.0 check totals are kept separate from all released-suite totals.
