# Finding 1 — C4 ≡ C0 under full-homeostasis initial conditions

## 1.1 Premises (all currently required)

| # | Premise | Source |
|---|---|---|
| P1 | `L_i ≤ x_i(0) ≤ U_i` for every node | stated design requirement |
| P2 | `R_i ≤ L_i` for every node | `world.NODE_BOUNDARY_ORDERING` (candidate domain restriction) |
| P3 | `v_i(x) = α[L−x]₊² + β[x−U]₊² + χ[R−x]₊²`, separable | Definition 6.1, `d0_v29.penalty` |
| P4 | `θ_e ≥ 0` | `d0_v29.Edge.__post_init__` (`_req_nonneg("theta", …)`) |
| P5 | `J_e = M_e[μ_i − η_e μ_j − θ_e]₊`, `q_e = min(Δt·J_e, c_e)` | `d0_v29.edge_flux`; C4 draft |
| P6 | demand supplies only opportunities and caps | Q-1 resolution, `common_opportunities` |
| P7 | no autonomous stock-changing term in the plant | verified below |

## 1.2 The marginal is exactly zero in band

Committed `d0_v29.marginal`:

```python
m = 0.0
if x < L: m += -2*alpha*(L - x)
if x > U: m += +2*beta *(x - U)
if x < R: m += -2*chi  *(R - x)
```

Under P1, `x_i ≥ L_i` ⇒ `x_i < L_i` is false; `x_i ≤ U_i` ⇒ `x_i > U_i` is
false. Under P2, `x_i ≥ L_i ≥ R_i` ⇒ `x_i < R_i` is false. All three guards
are strict inequalities, so the boundary cases `x = L`, `x = U`, `x = R = L`
are included. Therefore

```
μ_i = 0   exactly   (not within tolerance)   for every node i.        (1)
```

## 1.3 Every C4 proposal is zero

From (1), for every edge `e = (i,j)`:

```
f_e = μ_i − η_e μ_j = 0 − η_e·0 = 0
excess = f_e − θ_e = −θ_e ≤ 0                      by P4
J_e = M_e·excess if excess > 0 else 0 = 0          d0_v29.edge_flux
q_e = min(Δt·J_e, c_e) = min(0, c_e) = 0           since c_e ≥ 0
```

`c_e` enters only as an upper bound (P5, P6), so **no demand value can raise
`q_e` above zero**. This holds for arbitrary `d_e(t)`, arbitrary `c_e`, and
arbitrary `M_e > 0`.

## 1.4 The state is unchanged, and the argument closes by induction

The resolver only narrows: `q_e^acc = σ·q_e^req = σ·0 = 0` for any `σ ∈ [0,1]`.
With all accepted quantities zero, `Action.increment` is never constructed
(`execute_tick` skips `ladder.accepted ≤ 0`), the joint increment is the zero
vector, and

```
x(t+1) = x(t).                                                        (2)
```

**P7 verified:** `ebu_test_world` contains no drive, regeneration or source
term. `WorldState.successor(deltas, loss)` is reached only from `apply_joint`,
whose `totals` come solely from `Action.increment`. `d0_v29.natural_drive`
exists in the committed substrate but **is not referenced by the study world at
all**, and the study declares `u = 0`.

So `x(t+1) = x(t)` still satisfies P1 and P2, and (1)–(2) reapply. By induction
over ticks, for **every** demand history:

```
q^{C4}(t) = 0  and  x(t) = x(0)  for all t ≥ 0.                       (3)
```

This is exactly C0's behaviour. **C4 and C0 produce identical proposals,
identical accepted vectors, identical state trajectories and identical
per-tick records (modulo `controller_id`).**

## 2.4 CORRECTION — withdrawn: "P1C concerns resource leaving the system"

**An earlier revision of this note claimed that P1C's reasoning is about a
provider being drawn down "with the resource leaving the accounted system".
That claim is withdrawn as false.**

P1C's update already carries **both** directions. Amendment 4 (A4.1) and
Theorem 4.1's assumption **(A6)** are explicit:

```
x_i^{n+1} = x_i + Δt ( u_i + Σ_in η_e q_e^acc − Σ_out q_e^acc )      (A4.1)
(A6)  incoming usable flow  I_i^n ≥ 0,  with  I_i^n = Σ_in η_e q_e^acc
```

So internal transfers are inside P1C's own model. Theorem 4.1's proof uses
`I_i ≥ 0` only as **one-sided slack** — it *drops* `Δt·I_i` to obtain a lower
bound — which is why incoming flow is excluded from the budget (§4.1:
"counting `I_i` in the budget is unnecessary and (if uncommitted) unsafe").
That is a **conservatism**, not an assumption that resource leaves the system.

### What the actual distinction is

**Global conservation and local source preservation are different
properties.** They are not in tension and neither implies the other:

| Property | Statement | Holds here? |
|---|---|---|
| **global conservation** | `Σ_i x_i` is invariant (η = 1, no sink) | **yes**, by construction |
| **local source preservation** | `x_i^{n+1} ≥ R_i^eff` for the *sending* node | **only under Theorem 4.1's (A8)–(A9)** |

A transfer can preserve the system total **while drawing down its source** —
that is exactly the case the reserve bound exists to constrain. So the earlier
framing was not merely imprecise; it misidentified which property is at stake.
Nothing about conservation makes a source's own lower bound automatic.

Consequently **Theorem 4.1 is mathematically applicable to internal transfers
of a conserved scalar**, under its stated assumptions (A1)–(A9), with no
reinterpretation required: `Q_i` is the aggregate out-edge rate (A4), incoming
is admitted and discarded as slack (A6), and the conclusion is the sending
node's own reserve bound.

### What still does *not* follow

Mathematical applicability is **not** adoption. Specifically:

- it does **not** override P1C's adopted source-type dispatch, under which a
  `finite` or `irreversible` source's budget is **0** (§2.2);
- it does **not** supply a permission policy for this candidate study;
- it does **not** make proportional scaling the adopted allocator for a new
  study (§2.6).

| Layer | For a `finite` source with `x > R_eff` and (A8) holding |

## 3.3 The decisive consequence: finite-action selection does *not* by itself escape Finding 1

Two independent reasons, both from committed definitions.

**(a) The existing menu is still flux-derived.** `candidate_menu` enumerates
*fractions of each out-edge's raw loss-aware flux* (`M_sel = frac·M_e`). When
`μ ≡ 0` the flux is 0 for every fraction, `q = 0` is deliberately not
enumerated, so the **menu is empty and every arm rests — including the service
arm S**. No committed source generates a finite request from *external demand*;
event 3's slot is unfilled in every implementation.

**(b) From full homeostasis, no positive quote exists.** With `x_i ∈ [L_i,U_i]`,
`R_i ≤ L_i` and `u = 0`, we have `z = x` and `v_i(z_i) = v_j(z_j) = 0`, so

```
Δe_quote(q) = 0 − [ v_i(z_i − Δt q) + v_j(z_j + Δt η q) ] − C_a(q)  ≤  0
```

because `v ≥ 0` and `C_a ≥ 0`, **with equality exactly when the transfer keeps
both endpoints inside their bands and `C_a(q) = 0`.** There is no burden to
reduce, so the best attainable quote is **neutral (0)**, never positive.
Consequently `select_arm_D`'s **strictly-positive** threshold rests — the same
zero service as Finding 1, reached by a *different* mechanism (threshold, not
zero flux).

**What follows.** A demand-driven finite-action EBU arm becomes non-degenerate
only if **both** gaps are closed by explicit author decisions:

- **(C-i) a request-generation rule at event 3** that converts an external
  service request into a finite proposed quantity. No committed source supplies
  one; this is a new policy.
- **(C-ii) an acceptance threshold at event 6 that admits neutral (zero-quote)
  actions** — i.e. "serve demand when it costs the represented world nothing",
  which under `C_a = 0` is exactly the band-preserving transfers. The existing
  registered rule uses **strictly positive** and would rest.

Both are genuine policy choices. **Neither is invented here**, and the
existence of an exact quote does **not** imply either of them — the quote is a
valuation computed after permission, and committed sources say explicitly that
it "can never be an authorisation".

## 3.4 What O14 shows about obtaining positive export

`o14_v30.screen_budget` is the committed precedent and it is instructive:
*"O14 registers **regenerative sources only**"*, and it returns `0.0` for every
other state/type combination. When a registered experiment needed positive
export, it **registered regenerative sources** — it did not transplant
`robust_budget` onto a finite source. That is consistent with Finding 2 and with
§2.4a: the obstacle is the adopted dispatch, and the committed way around it was
to change the *source type*, declared up front.

## 4.1a Direction C has been worked out concretely — see the design packet

`V3.0_DIRECTION_C_DEMAND_DRIVEN_FINITE_ACTION_DESIGN_PACKET.md` now carries a
full prospective design for direction C: provisional id
**`C5-demand-driven-exact-EBU`** (variants `C5a` EBU-first, `C5b`
service-first), a demand-driven opportunity rule that requires **no positive
flux**, the group functional `F_G(q) = V_A(z) − V_A(T_G(z,q))` as the decision
object, a proposed common **internal-transfer permission rule** with a distinct
provider floor `P_i`, and both lexicographic analyses.

**Results from that packet, as corrected in its own §0 correction log.**

1. **The (C-ii) "neutral quote" gap closes by itself** under a lexicographic law
   with rest included: `F_G(0) = 0` makes rest beat every negative-value vector
   at stage 1, and stage 2 then takes the largest service among value-maximal
   vectors. No new threshold parameter is needed.
2. **`C5a` is NOT a established duplicate of C3.** The earlier "probable
   duplicate" verdict is **withdrawn**: packet d-8 gives agreement on the
   admissible set and on maximum immediate service, which is **not** equality of
   decision maps. C3 selects the max-min-fair point; `C5a` selects whatever the
   declared tie rule picks, and different points give different successor
   states. Conversely, if the tie rule is the *only* difference, that difference
   **must not be attributed to graded EBU**.
3. **`C5b` differs from C2 only where the budget binds**, and only **at a shared
   frozen state** — not across independently evolving trajectories. C3 may
   deliberately deliver less than either.
4. **The decisive correction (packet d-11, d-12): the field criterion is often
   inoperative.** At fixed total export the source term is constant, so `F_G`
   varies on the service-maximal set only if some destination's burden is
   non-flat. From an all-in-band baseline `C5a`'s EBU stage is a **binary
   band-feasibility screen** with no graded content, and `C5b`'s stage 2 is
   **flat** wherever destinations stay in band — in which case the **residual
   tie rule, not EBU, selects the allocation.** This is the same underlying
   cause as the C4 zero-action finding, reappearing in a mechanism that does
   respond to demand.
5. **Per-edge quotes must not be summed** (packet d-2): the interaction is the
   mixed second difference, `≥ 0` by convexity, so summation overestimates. A
   worked instance gives naive `0` against true `−4`, straddling the accept
   boundary. Additivity is "not guaranteed", never "always different".
6. **Pipeline (packet d-8a, d-8b):** publishing the aggregate cap needs **no
   committed amendment** — committed event 2 already computes budgets before
   event 3 — and amends only my own `OPPORTUNITY_INVARIANTS` item 7. Under that
   architecture the selected vector **executes unchanged**, which d-8b derives
   from in-degree ≤ 1 and frozen-state caps.
7. **Matched reference and decision influence (packet §4A).** The comparison is
   not "does `C5b` out-serve C2" — at a shared state it usually does not. It is
   *"when the field had a choice, did it change the choice, and was that a field
   effect or a tie-rule artifact?"* The reference is
   `q_ref = T(M_i)` against `q_EBU = T(argmax_{M_i} F_G)` with the **same**
   field-independent `T`. **`q_ref` is not C2**: C2's rule coincides with it only
   in the degenerate singleton case, so the reference is a separate candidate
   **no-field ablation** and C2 is preserved unchanged. `T` must satisfy
   restriction consistency (Sen's α, d-15); given that and exact optimisation,
   **changed choice ⟺ strictly positive field advantage** (d-16), so a changed
   vector with zero advantage signals a defect rather than an EBU effect. Five
   interpretation cases are distinguished, and **a zero changed-choice count is
   a result, not an inconclusive run**.

**One new load-bearing assumption is exposed:** `C_a ≡ 0`. Definition 6.13a
permits a fixed activation cost `c₀ > 0`, and with any such cost `C5a` returns
to rest — the Finding-1 degeneracy reached through the cost term.

## 4.2 Recommendation

**Direction C, paired with a permission decision (B0 or B1 from Part 3.B), and
within C the service-first variant `C5b` under the published-cap pipeline.** Not
adopted — recommended for the author's decision. `C5b` rather than `C5a` **not**
because `C5a` duplicates C3 (that claim is withdrawn) but because, on the
declared all-in-band baseline, `C5a`'s EBU stage carries **no graded content**
(packet d-12) while `C5b`'s **can** be operative, since its per-edge caps run to
`K_j` rather than `U_j`. The decisive caveat: `C5b` is operative **only on the
subset of states where `F_G` is non-constant on the service-maximal set**, so
the configuration must **instrument and report that subset** — otherwise an
EBU effect cannot be distinguished from a tie-rule artifact. `C5b` also does not
preserve homeostasis as a constraint (§4.3).

**Why C.** It is the only direction whose subject matter is the intended
question. The automatic flux answers "where does the field push?"; the intended
question is "what should this actor do about *this request*?", and those are
different objects. Committed sources already separate them (§3.1) and already
provide most of the machinery: the event ordering has a proposal slot and a
decision slot; the exact finite quote is derived and dimensionally audited; and
three selection rules, including an EBU one and a service comparator, are
registered with declared tie-breaking and an explicit rest branch. **C is
mostly assembly of committed parts plus two declared policy choices** — not new
theory.

**Why not A.** A is honest and is the correct holding position, but it answers
nothing.

**Why not B.** B is legitimate and may eventually be wanted, but it changes the
**plant** to make the *existing* mechanism active, and the mechanism it
activates still responds to its own gradient rather than to requests. It would
produce a regulation result and leave the service question untouched. It is also
the heaviest in obligations: conservation/boundary accounting, controller- and
field-independence, and re-derivation of C3's `A_i`.

## 4.3 Limitations of the recommendation, stated plainly

1. **C does not escape Finding 1 by itself** (§3.3). Without (C-ii) admitting
   neutral quotes, a strictly-positive threshold rests and C is as degenerate as
   the flux. This is the single most important caveat.
2. **C does not escape Finding 2.** A permission basis is still required; under
   B0 the budget is zero and C delivers nothing.
3. **The quote law is candidate**, and **E3** records `f_e, Ψ_e, J_e`
   unregistered for the declared domain — so C's valuation inherits candidate
   status.
4. **O14's selection rules are registered at O14's scope**, with regenerative
   sources and a flux-derived menu. Reusing them here is not automatic and
   would need their scope re-examined.
5. **Multi-action additivity is unresolved** (E2/O3). A selection rule choosing
   *one* candidate per source per tick avoids the issue; anything that sums
   simultaneous quotes does not.
6. **C changes what "the EBU arm" means.** It must be registered as a
   **separate, separately identified candidate arm** (e.g. C5), never as a
   silent redefinition of C4 — otherwise the comparison's history becomes
   unreadable.

**No direction is adopted here, and no controller was changed.** Every item
above is a preregistration-relevant decision and therefore an author act.
