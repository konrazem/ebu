## 2. Strict serialization and publication primitives

Every JSON parser must accept UTF-8 without BOM and reject duplicate object
keys, `NaN`, `Infinity`, `-Infinity`, trailing data, comments, invalid UTF-8,
and every non-JSON token. Every number must be finite, and a Boolean is not a
number where a numeric field is required.

Receipt and execution-start JSON use their registered insertion order and:

```python
json.dumps(value, ensure_ascii=True, allow_nan=False,
           separators=(",", ":"), sort_keys=False).encode("utf-8") + b"\n"
```

Canonical hashing and nested canonical evidence use sorted-key compact JSON,
`ensure_ascii=True`, `allow_nan=False`, UTF-8, and no final newline. Summary
uses sorted keys, `ensure_ascii=True`, `allow_nan=False`, `indent=2`, and one
final LF. Each trace row is sorted-key compact strict JSON plus one LF.

The trace is exactly one gzip member over the 6,000 concatenated JSON lines,
with empty filename, `mtime=0`, compression level 9, and no comment or extra
field. Validation decompresses, strictly parses and reserializes every row,
recompresses using that rule, and requires byte identity. Every text artifact
is UTF-8 without BOM, contains LF rather than CR or CRLF, contains no NUL, and
ends in exactly one LF.

The only temporary basenames, all directly inside the result directory, are:

|---|---|

| execution-start | `.v30_gate1dc_execution_started.json.tmp` |

Each temporary is opened at that exact name with
`O_WRONLY|O_CREAT|O_EXCL` and `O_NOFOLLOW` where available, mode `0600`, only
after `lstat` proves absence. Random or alternate names are forbidden. Its
`st_dev` must equal the result directory's `st_dev`.

Publication writes every byte, flushes, `fsync`s the file, changes the mode to
`0444`, `fsync`s again, closes, and atomically creates the absent final path by
`link(temp, final)`. Collision fails closed. The destination directory is
`fsync`ed before the final path counts as durable. The temporary alias is then
unlinked and the directory is `fsync`ed again. No alternate publication
primitive is permitted.

After any receipt final path exists, exceptions, signals, `SIGKILL`, power
loss, and interpreter termination preserve every final and temporary residue.
The normal publishing process may unlink its temporary alias only after the
final link is durably fsynced. A recovery finalizer may unlink a leftover alias
only after proving it is the same inode as its complete, valid final path; this
completes publication and does not discard unique bytes. No other post-receipt
cleanup is permitted.
