# V3.0 Long-Horizon Study — Shape and Cost Worksheet

**Status:** PROSPECTIVE AUTHOR-CHOICE WORKSHEET. Nothing here is selected,
preregistered, or authorized. It converts the remaining open decisions into
four choices and a parametric cost form. No dollar figure appears, and none
can until the choices below are made and a cross-host measurement exists.

---

## 1. Fixed decisions and the governing equation

Already selected and not reopened by this worksheet:

| # | Decision | Selected |
|---|---|---|
| D1 | Topology and O3 handling | **Option B — shared endpoints permitted, no attribution** |
| D3-2 | Simultaneous-action bound | **`m = 2`** |
| D2a-4 | Reserve regime | **R-b reserve-binding** |

Under Option B the physical transition and exact joint EBU are computed once;
`group_quote`, `naive_sum` and `double_count` are recorded; joint EBU is never
allocated to individual actions; O3 stays open; no causal claim is made.

The governing value is only:

`Δe(q) = V_loc(z) − V_loc(z + Δt·S_e·q) − C_a(q)`

evaluated as an exact finite endpoint difference over the affected cells.
Never per unit, never by sampled quadrature, never a surrogate objective.
Physical/homeostatic admissibility is evaluated **before** any EBU value is
consulted: P1C classifies state and computes the export budget first, an
empty budget yields an empty menu, and every candidate is pre-capped before
ranking.

**Candidate count:** `K = F × Σ_{s∈S} d_out(s) ≤ F × E`.

## 2. Measured D5 constants (local only)

From the committed run `results/benchmarks/d5/d5-raw-001/`, executed at
revision `dcb2ebe`, launcher `normal-shell`, on an Apple M4 Pro with CPython
3.14.2. **Non-scientific software measurement. Not an EBU result, not an AWS
measurement, not a host recommendation, not a budget.**

Unit operations (ns, median):

| Operation | ns |
|---|---|
| `state_difference` | 1,254 |
| `exact` (the governing value) | 1,776 |
| `canonical_json` | 2,202 |
| `commitment_hash` | 2,766 |
| `build_quote` (3 SHA-256 commitments) | 22,180 |

A settled action performs **5** SHA-256 commitments in total (3 in
`build_quote`, 1 in `register`, 1 in `settle`), confirmed by the untimed
audit cell.

Per record at `m = 2` (ns, serialized bytes, retained bytes):

| K | E-none | E-full | E-settled |
|---|---|---|---|
| 1 | 1,502 ns / 871 B / 2,329 B | 24,163 ns / 964 B / 2,522 B | 37,101 ns / 1,114 B / 2,489 B |
| 8 | 2,906 ns / 1,522 B / 4,265 B | 176,232 ns / 2,084 B / 5,225 B | 38,986 ns / 1,765 B / 4,425 B |
| 32 | 7,292 ns / 3,776 B / 10,985 B | 715,559 ns / 5,946 B / 14,636 B | 43,258 ns / 4,019 B / 11,124 B |

**Two-point slopes** between the measured K = 1 and K = 32 endpoints (not
regression fits):

| Policy | ns per extra candidate | bytes per extra candidate | retained bytes per extra candidate |
|---|---|---|---|
| E-none | 186.8 | 93.7 | 279.2 |
| E-full | **22,303** | 160.7 | 390.8 |
| E-settled | **198.6** | 93.7 | 278.5 |

E-full's slope reproduces `build_quote` almost exactly, because it commits
every candidate. E-settled is nearly flat in `K`, because it commits only the
`m` settled actions. At `K = 32`, `m = 2`, **E-full ≈ 16.5× E-settled**. The
two policies cross between `K = 1` and `K = 2`: at `K = 1` E-full is cheaper
(24,163 vs 37,101 ns); from `K = 2` onward E-settled wins and the gap widens
linearly.

## 3. The four remaining author decisions

### Decision A — Study shape

Topology and node/edge structure, shock family, reserve-regime
implementation.

| | |
|---|---|
| **Options** | **A1 minimal shared-endpoint** · **A2 hub-and-periphery (heterogeneous out-degree)** · **A3 shared-destination structure** |
| **Enables** | Whether repeated exact-EBU decisions preserve reserves and service under genuine contention; A3 opens the destination-side interaction channel, which no completed study has exercised |
| **Cannot claim** | External validity beyond the declared family; nothing about allocation or O3; A1 cannot speak to contention, A2 confounds degree with horizon effects unless degree is a declared factor |
| **Exact-EBU / homeostasis** | R-b reserve-binding is already selected, so P1C screening is exercised and the source potential stays live, making `double_count` capable of being non-zero. Gate 1D-C's near-zero interaction was an artifact of flat-band sources plus distinct destinations and must not be assumed here |
| **D5 multiplier used** | Sets `Σ d_out(s)`, hence `K = F × Σ d_out(s)`, hence which row of the per-record table applies |
| **Unmeasured on AWS** | Whether per-record byte and retained-byte coefficients hold beyond the measured record shape; menu growth was measured only to `K = 32` |

### Decision B — Scientific horizon

Ticks `T`, worlds, arms, timesteps, deterministic parameter variants.

| | |
|---|---|
| **Options** | **B1 one relaxation time** (single recovery) · **B2 several relaxation times** (recovery repeatability) · **B3 ≫ relaxation time** (drift, ratchet, slow reserve erosion) |
| **Enables** | The registered long-run question — whether repetition preserves homeostasis, reserves, service, recovery and robustness over a declared horizon |
| **Cannot claim** | B1 cannot show repeatability; B2 cannot show slow drift; none can claim anything outside the declared family or beyond the certified timesteps |
| **Exact-EBU / homeostasis** | `T` must be justified by a relaxation-timescale sufficiency argument derived statically from the world parameters — never by a compute budget. The V3 implementation is deterministic with no seed, so "replicates" can only be declared parameter or initial-condition variants; stochastic replicates would introduce noise semantics V3 does not have |
| **D5 multiplier used** | Sets `records = R × T`, the multiplier on every per-record constant |
| **Unmeasured on AWS** | Sustained throughput over a long run. D5 measured ~18,000 operations per cell in short bursts; thermal behaviour, GC pressure and allocator drift over hours are unmeasured anywhere |

### Decision C — Decision and evidence shape

Fraction ladder `F`, matched comparator-arm requirements, E-full versus
E-settled.

| | |
|---|---|
| **Options** | `F` **C1 coarse** · **C2 medium** · **C3 fine**; evidence **E-full** (commit every candidate) or **E-settled** (commit settled actions plus the required triple) |
| **Enables** | `F` sets decision resolution — whether the exact-EBU rule can express its preference or is forced into artificial ties. The evidence choice sets what is independently re-verifiable after the fact |
| **Cannot claim** | A coarse ladder cannot support near-threshold claims. E-settled cannot later prove which non-selected candidates were considered; that evidence is simply not retained |
| **Exact-EBU / homeostasis** | `Δe(q)` is exact at every `q`; resolution affects only which quantities are *offered*, never the accuracy of the value. There is no quadrature parameter. Evidence granularity is evidentiary and must be registered before execution, never tuned after |
| **D5 multiplier used** | **The single largest measured lever.** Linear in `F` through `K`; then E-full costs ~22,303 ns and ~161 B per candidate, E-settled ~199 ns and ~94 B. At `K = 32` that is the 16.5× gap |
| **Unmeasured on AWS** | Write throughput for a large JSONL evidence stream on network-backed storage. D5 wrote 226 KB locally; nothing about sustained evidence I/O at study scale has been measured |

### Decision D — Durability

Checkpoint/restart, or an explicitly accepted all-or-nothing limitation.

| | |
|---|---|
| **Options** | **D1 checkpoint at interval χ with restart** · **D2 accept all-or-nothing and register it as a limitation** |
| **Enables** | Bounded rework after failure, and a memory ceiling that does not grow with the whole study |
| **Cannot claim** | Neither option changes any scientific claim. Choosing D2 means a failure near the end loses the entire run |
| **Exact-EBU / homeostasis** | A restart must not become a rerun: a resumed run must be provably the same attempt, or the single-attempt discipline that governs registered studies is compromised. That is a protocol design problem, not an engineering detail |
| **D5 multiplier used** | Retained bytes per record — 2,489 B at `K = 1` rising to 11,124 B at `K = 32` under E-settled. With no checkpoint, memory scales as `records × retained`, since the reference implementation materialises everything before writing |
| **Unmeasured on AWS** | Checkpoint write cost and restart overhead. No checkpoint mechanism exists, so nothing about it has been measured anywhere |

## 4. Parametric cost worksheet

Let `R` = runs (worlds × arms × timesteps × declared variants), `T` = ticks per
run, `K = F × Σ d_out(s) ≤ F × E`, and `m = 2` (selected).

```
records            = R × T

t_record(K, full)  ≈ 24,163 ns + 22,303 ns × (K − 1)
t_record(K, settl) ≈ 37,101 ns +    199 ns × (K − 1)

b_record(K, full)  ≈    964 B  +  160.7 B × (K − 1)
b_record(K, settl) ≈  1,114 B  +   93.7 B × (K − 1)

mem_record(K,full) ≈  2,522 B  +  390.8 B × (K − 1)
mem_record(K,settl)≈  2,489 B  +  278.5 B × (K − 1)

local_cpu_seconds  = records × t_record / 1e9
logical_bytes      = records × b_record
peak_memory_bytes  = records_held × mem_record      (records_held = records
                                                     unless Decision D adds
                                                     checkpointing)
wall_clock_floor   = T × t_record                   (one trajectory is
                                                     irreducibly sequential;
                                                     parallelism only across
                                                     the R runs)
```

Every coefficient above is a **local** measurement on one Apple M4 Pro under
`normal-shell`. No node count, horizon, run count, AWS throughput, instance
type, price, or dollar figure is supplied or implied. Transfer to any other
host requires its own measurement.

## 5. What a credible AWS dollar estimate requires

Exactly two things, and nothing else:

1. **One completed author selection from each of the four groups above** — A,
   B, C and D. Those fix `K`, `records = R × T`, the applicable per-record
   coefficients, and whether memory is bounded.
2. **One separately authorized AWS-host micro-benchmark** for cross-host
   transfer, of the same non-scientific kind already committed: same kernel,
   same synthetic inputs, same boundaries, a new run identifier, run on the
   candidate host.

With those, `records × t_record` and `records × b_record` become concrete, the
host's own throughput replaces the local constant, and a price can be applied.
Without both, any figure would be invented.

### Recommended low-complexity first path — a recommendation, not a selection

**A1 · B2 · C2 with E-settled · D1.**

Rationale, briefly: **A1** is the smallest structure in which a joint
transition exists at all, so Option B has content without confounding degree
effects. **B2** is the shortest horizon that can speak to recovery
*repeatability*, which B1 cannot. **E-settled** is the measured cheap side of
the 16.5× lever and still retains the full `group_quote` / `naive_sum` /
`double_count` triple that Option B exists to measure; the evidence it gives
up is the set of non-selected candidates. **D1** is recommended because with
no checkpoint a long run is all-or-nothing, and the reference implementation
materialises every record before writing.

This path is offered to make the first estimate cheap and interpretable. It is
**not** a scientific recommendation about what the study should test, and the
author should override it wherever the science requires.
