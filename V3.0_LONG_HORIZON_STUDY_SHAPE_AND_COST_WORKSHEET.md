### 5.1 What each family can and cannot claim

**T1 — shared source.** Can test whether repeated exact-EBU decisions preserve
reserves and service under **source-budget contention**: two actions draw on one
source's P1C budget, and under R-b reserve-binding the source potential stays
live, so `double_count` is capable of being non-zero. Cannot test the
destination-side interaction channel at all, and cannot claim anything about
contention at a shared destination.

**T2 — shared destination.** Can test the destination-side interaction channel,
which no completed V3 study has exercised — every prior world shared only a
source. Cannot test source-budget contention: each source carries its own P1C
budget, so a two-action tick here is two independent single-action decisions
coupled only through the destination potential.

**T3 — both channels.** Can test both channels and whether they compound.
Cannot separate them: source-side and destination-side interaction are
confounded unless the declared variants are designed to isolate them, which is
itself an unresolved design choice.

None of the three can claim allocation of joint EBU, O3 settlement, causal
attribution, external validity beyond the declared family, or anything about
latency or uncertainty (Gate 1E).

### 5.3 Horizon: a destination-side lower-bound estimate only

From the committed law (`d0_v29.marginal`, `d0_v29.edge_flux`), holding the
source marginal at zero in its flat band and retaining only the destination's
α-branch below `L`:

```
f_e            = 2ηα(L − x)
delivered rate = ηJ = 2η²Mα(L − x) − ηMθ
⇒ dx/dt        = −λx + const,   λ = 2η²Mα
⇒ τ_ticks      = 1 / (2η²Mα·dt)
```

**This is a destination-side lower-bound estimate, not a complete-horizon
derivation.** Both simplifications fail under the selected regime: R-b
reserve-binding keeps the source potential live — that is the point of
reserve-binding — so `mu_i ≠ 0`, and the destination's χ reserve-branch may also
be active. The coupled two-sided system is not a single exponential, and this
argument establishes neither the sign nor the size of the correction. It
therefore yields a **necessary condition** on `T`, never a sufficient one:

```
T ≥ burn_in + n_s · k · τ_ticks        (necessary, not sufficient)
```

with `n_s ≥ 2` recovery episodes, because B2 tests *repeatability*, which one
episode cannot show; and `k ≥ 3` relaxation times per episode, since
`e⁻³ ≈ 0.05` is roughly 95 percent recovery. `burn_in`, `n_s`, `k`, `dt` and the
world parameters `(α, η, M, χ, R)` are all unresolved author choices. `T` is
therefore **UNRESOLVED** for every family, and any `T` obtained from this
estimate must be confirmed against the chosen parameters before it can be
registered. `T` must never be set by a compute budget.

B2 additionally implies a **repeated-shock family**, since recovery
repeatability cannot be observed without at least two shock-recovery episodes.
The shock family itself remains **UNRESOLVED**.

### 5.6 Study type, and a correction to how stress relates to this algebra

**This study is a normalized mechanism study.** No parameter used with the
algebra above is empirically calibrated, and none describes any real external
system; parameters declare synthetic worlds only. Structural parameter
reduction, empirical parameter identification and a future calibration study
are three different things, and only the first is done anywhere in this
repository.

Concrete normalized world families implementing A1 / B2 / C2 / E-settled / D1
are **proposed, not adopted**, in
`V3.0_LONG_HORIZON_NORMALIZED_MECHANISM_CANDIDATE.md`. Nothing in that file is
selected, and nothing here adopts it.

**Correction — reserve stress is not controlled by the edge capacity.** It is
tempting to read §4 as implying that a target stress `sigma = J_tot / Q_max` can
be reached by raising the transport capacity `M`. That is wrong whenever the
timestep is tied to its certificate. Both certificates scale as `1/M`, so
`Q_max ~ h/dt` grows with `M` exactly as fast as `J_tot` does, and `M` cancels:

```
sigma  ->  4*(f - theta)*Pi_tau / ( h * L_V * (1 + eta^2 + overlap) )
```

Reserve stress is therefore governed by the **headroom** `h = x - R_eff`, the
driving force above the deadband, the total curvature `L_V`, and the timestep
safety fraction — not by `M`. One consequence is counter-intuitive and worth
recording: raising the reserve stiffness `chi` raises `L_V`, tightens the
certificate, shrinks `dt`, and therefore **lowers** the stress it was meant to
sharpen.

A second exact relation bounds usable resolution. Because
`q_acc = min(q_req, budget)`, every rung above the budget collapses to the same
accepted quantity, so the number of distinguishable quantities is
`F_eff = #{phi_i : phi_i < 1/sigma} + 1`. Binding requires `sigma >= 1` and two
distinguishable quantities require `sigma < F`, giving the feasibility window
**`1 <= sigma < F`**. The ladder `F` and the stress level cannot be chosen
independently.

## 6. What is required, at two different levels

These are two different questions and must not be conflated.

### 6a. A preliminary compute and storage estimate

Needs exactly two things:

1. **One completed author selection from each of the four groups above** — A,
   B, C and D. Those fix `K`, `records = R × T`, the applicable per-record
   coefficients, and whether memory is bounded.
2. **One separately authorized AWS-host micro-benchmark** for cross-host
   transfer, of the same non-scientific kind already committed: same kernel,
   same synthetic inputs, same boundaries, a new run identifier, run on the
   candidate host.

With those, `records × t_record` and `records × b_record` become concrete, the
host's own throughput replaces the local constant, and a price can be applied
to compute and storage. Without both, any figure would be invented.

A preliminary estimate of this kind is **not** a launch decision. It sizes the
job; it does not establish that the job can be run correctly or safely.

### 6b. A launch-safe budget

Everything in 5a, **plus two pieces of software that do not exist yet**:

3. **A matched multi-action non-EBU comparator selector.** The selected
   `m = 2` requires the non-EBU baseline to select up to two actions per tick
   under one shared P1C budget, with deterministic tie-breaking and the
   request-shaping identity holding for both actions. No such selector exists.
   Without it the primary comparison is unmatched in capability and the study
   cannot answer its own question, however accurate the cost estimate is.
4. **A checkpoint and restart mechanism** (Decision D1). None exists today,
   and the reference implementation materialises every record before writing.
   Until it exists, peak memory scales with the whole study and a failure near
   the end loses the entire run — so a budget computed without it understates
   the true expected cost by an unknown rework factor.

Both are implementation work under their own separate authorization. Neither
is a cost question, and neither can be substituted by a larger budget.

### Rationale for the selected direction set

**A1 · B2 · C2 with E-settled · D1** are the selected directions (§1).

Rationale, briefly: **A1** is the smallest structure in which a joint
transition exists at all, so Option B has content without confounding degree
effects. **B2** is the shortest horizon that can speak to recovery
*repeatability*, which B1 cannot. **E-settled** is the measured cheap side of
the 16.5× lever and still retains the full `group_quote` / `naive_sum` /
`double_count` triple that Option B exists to measure; the evidence it gives
up is the set of non-selected candidates. **D1** is required because with
no checkpoint a long run is all-or-nothing, and the reference implementation
materialises every record before writing.

Selecting these directions fixed **no numerical value**. `F`, the arm count,
the timestep count, the deterministic variant count, `R`, `T` and `χ` all remain
unresolved, as do the shock family and the comparator-arm set. Nothing in §2 or
