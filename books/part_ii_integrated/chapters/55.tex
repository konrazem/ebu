\chapter{Tests that can genuinely detect being wrong}\label{ch:testing}
A useful test is designed so that a plausible defect makes it fail. A
suite that merely confirms its own assumptions can stay green while the
scientific meaning has changed. The goal is not a large number of checks;
it is coverage of the ways the implementation could compute the wrong object.

\section{Execution classes must be named honestly}
Static inspection covers source, schema, hashes and declarations. Pure
arithmetic evaluates a fixed mathematical expression without advancing
model state. A transition test executes a physical update, even if there
is only one synthetic tick. A scientific study executes its registered
process and interprets outcomes under a frozen protocol.

These classes have different authorization boundaries. A test's filename
or speed does not determine its class. Importing a module can itself have
side effects, so calling a test static requires inspection of what it actually
does. A source scan that sees no direct transition call cannot prove that
an imported helper never transitions.

\section{Arithmetic checks for the new family}
The future Gaussian foundation should compare finite endpoint evaluation
with the exact expansion, local with global differences, path sums with
group value, and rate/quantity conversions at non-unit durations. It should
include reference states, overshooting quantities, cancelling groups and
unequal scales, not only beneficial transfers.

An especially useful defect injection is replacing exact finite value by
the initial tangent. The quantity-four example changes from twelve to
sixteen. Another is summing two same-baseline singleton values: the shared
group changes from twelve to fourteen. A negative control should detect
those substitutions, not merely run them and count a pass.

\section{Physical checks are independent}
Conservation, nonnegative stock, allowed support and joint capacity must be
tested independently of the potential. A negative source and positive
destination can preserve total mass. A changed sink can preserve one
aggregate residual while violating its declared physical update. Passing
one scalar identity is therefore not a complete physical validator.

At the lossless first-domain boundary, any loss coordinate should remain
inert under its declared rule. A future loss-aware extension needs its own
carrier-by-carrier checks; the success of the lossless suite cannot be
reported as certification of that extension.

\section{Information and account controls}
Required prospective controls include forbidden remote reads, future draw
access, stale epochs, duplicate settlement, post-selection quantity changes,
missing owners, wrong parameter versions and cross-owner pooling. Each
should specify the expected refusal and the state that must remain unchanged.

A refused campaign entry is not proven by any nonzero process exit. A syntax
error also exits unsuccessfully. The check must verify the intended refusal
class and message, and where relevant that no model state changed before it.
Refusal is a behavior with a contract, not the absence of a successful printout.

\section{What green checks do not establish}
Even complete conformance to a specification does not prove the specification
is scientifically useful. A correctly implemented process can cycle, ration,
refuse, or fail to improve its declared metric. Those are possible scientific
outcomes, not automatic reasons to weaken tests or alter the world.

This book's worked arithmetic is checked independently as teaching material.
Those checks are not reported as implementation acceptance counts. Historical
Q-test and D-test counts in the historical readings remain attached to their own code
and configurations; none is inherited by an unbuilt Gaussian runtime.

\section*{Chapter recap}
Test the equation, the physical transformation, information boundaries,
accounting semantics and execution guards separately. Then keep conformance
distinct from scientific success.
