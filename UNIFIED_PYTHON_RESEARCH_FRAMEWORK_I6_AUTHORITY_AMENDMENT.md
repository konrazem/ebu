## 4. Group and boundary law

A dependency edge exists only when two child actions have declared effective-interval overlap and at least one declared condition in this closed domain: `SHARED_WRITE_SUPPORT`, `SHARED_CONSTRAINT`, `CROSS_ACTION_DEPENDENCY`, `NONSEPARABLE_DISTORTION`, `COMMON_ENDPOINT_ONLY_OBSERVATION`. A joint-transition group is exactly a connected component of that supplied relation, including required transitive closure. A chain may form one component without a global n-way intersection. Every child identity is preserved.

One group has one common before state, boundary, distortion model, horizon, joint write support, joint constraint set, and source-budget account. Grouping occurs after admission and before transition. Domain/model authority supplies dependency and grouping declarations; EBU validates them and their closure but makes no automatic-discovery claim.

M1 is deliberately not coerced into a group. Its aggregate arithmetic is a static separate-transition witness, `classify_joint_groups_fixture` returns an empty group tuple, and no physical `GroupReceipt` is fabricated.

## 5. Five non-interchangeable records

Bridge v0.2 places same-baseline nonadditivity beside four operational categories. Accordingly, the adapter keeps these five record categories distinct:

1. Physical group measurement: `EBU_G = D(X_0) - D(X_G)`, measured once on the complete finite group transition.
2. Same-baseline nonadditivity: `N_G = EBU_G - sum_i EBU_i^(0)` when every standalone child exists.
3. Comparator-relative interaction: `I_(G|pi) = EBU_G - EBU_(seq,pi) = D(X_pi) - D(X_G)` for a named admissible comparator.
4. Optional causal child contributions `C_i`, only under a separately accepted causal-identification protocol.
5. Optional institutional shares `S_i` and explicit residual `R_G`, with `sum_i S_i + R_G = EBU_G`.

The accepted I-3C repair is preserved: an authorized institutional share with mandatory `rule_ref`, compatible units, exact closure, and explicit residual is not thereby a causal claim. All group rows M2–M9 are `UNIDENTIFIED` for causality because the matrix supplies no identification protocol. All M1–M9 settlement records are `NOT_APPLICABLE` because the matrix chooses no rule.

Receipt batching is separate bookkeeping: `K_separate - K_group = (n-1)K_0 - K_G`. No `K` term enters physical EBU, nonadditivity, interaction, causality, or settlement.

## 6. Comparator law and decision table

Accepted `scheduling.ComparatorKind` remains exactly `OPEN_LOOP_REFERENCE`, `SEQUENTIAL_ORDER`, and `DECLARED_ALTERNATIVE`. Quantity-fixed versus rule-replayed is an orthogonal bridge-owned closed literal domain: `QUANTITY_FIXED`, `RULE_REPLAYED`.

Every comparator has the exact same baseline and a compatible boundary, horizon, distortion contract, and endpoint obligation. Order is explicit. State equivalence and EBU equivalence are separate. Sequential telescoping must close exactly:

`sum_(k=1)^n [D(X_(k-1)) - D(X_k)] = D(X_0) - D(X_n)`.

| Condition | Closed selection kind | Mandatory report |
|---|---|---|
| Every admissible order reaches the same represented endpoint | `ORDER_INVARIANT_IDENTIFIER` | Use a preregistered identifier order; report one interaction and retain exact endpoint/order-invariance evidence |
| Endpoints differ and one physical or contractual precedence is mandatory | `MANDATORY_PRECEDENCE` | Use and name that mandatory order with precedence provenance |
| Reservation order or actual start order is the scientific object | `FROZEN_OBSERVED_ORDER` | Use the frozen observed order without outcome-dependent substitution and state its scientific relevance |
| Several noncommuting orders are feasible and none is privileged | `ALL_FEASIBLE_OR_EXACT_EXTREMA` | Evaluate every preregistered feasible order or a preregistered exact-extremum procedure; report vector/range plus endpoints |
| An accepted policy requires one canonical order despite several feasible orders | `POLICY_CANONICAL_WITH_SENSITIVITY` | Freeze policy order before results; report canonical value and sensitivity to every other registered order; never call it unique physics |
| Large n makes all permutations impractical | `PREREGISTERED_LARGE_N_COVERAGE` | Freeze schedule family, sampling rule, or exact optimization before execution; report coverage, omitted schedules, and uncertainty; no post-result search |
| No feasible sequential schedule preserves the declared children and constraints | `NONSERIALIZABLE` | Report group EBU and NonserializableGroup; numeric interaction is Applicability.NOT_APPLICABLE |

When no admissible comparator exists, interaction is undefined and nonserializable. It is never silently zero. M9 invents neither a comparator nor a causal value.
