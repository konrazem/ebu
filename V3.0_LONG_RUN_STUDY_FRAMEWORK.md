## 1. The question this architecture must eventually be able to ask

> Do physically permissible, EBU-guided actions preserve homeostasis under
> regeneration, demand, disturbance and reserve constraints?

The architecture must be *capable* of posing that question. It does not pose it
here, and nothing below may be read as a hypothesis about the answer.

Three words in that question are load-bearing and are **not** interchangeable:

- **physically permissible** — admissibility and reserve screening decide this,
  and they decide it *before* any EBU value is computed;
- **EBU-guided** — a value may order the admissible candidates; it may never
  enlarge the admissible set;
- **preserve homeostasis** — a property of the *world's* trajectory, never a
  property of the decision rule that is assumed rather than measured.

---

## 2. Decision order — fixed, and not a slot

This is the one thing the architecture fixes, because committed sources already
fix it and reversing it would be a scientific error, not a design choice.

```
1. admissibility and reserve screening   (physical; may refuse everything)
2. exact finite EBU evaluation           (only on the surviving candidates)
3. the declared arm's selection rule     (ordering only)
4. joint capacity resolution             (the accepted vector)
5. record                                (settlement-free)
```

Consequences, each of which the implementation must enforce rather than assume:

- an action that violates a homeostatic or reserve constraint **is not made
  admissible by a favourable EBU value**;
- a first-order or linear term is a **diagnostic** and never a settlement or
  ranking value (`v30_o14_multi_edge_plan.json`: the linear diagnostic "is
  NEVER used for settlement or ranking");
- the value that is ranked must be the value of the vector that **executes** —
  i.e. evaluated on the accepted quantities after step 4, not on the requested
  ones;
- step 5 records; it does not settle. `O3` and `O8` are open.

## 3. Atomic linked transformations — chains are not mega-actions

**Rule A-1 (no hidden chains).** Where a modelled physical consequence has its
own state transition, it is represented as **its own atomic action with its own
receipt**, linked to its neighbours. It is not folded into a predecessor's
receipt.

Illustrative shape only — no such world is adopted here:

```
fuel transformation -> generation -> delivery/use -> transfer
     (atom, receipt)  (atom, receipt) (atom, receipt) (atom, receipt)
```

**Rule A-2 (no automatic expansion).** Conversely, one declared action is **not**
automatically expanded into its entire causal supply chain. The boundary of
what is represented is a declaration, and it must be stated.

**Rule A-3 (encapsulation is a claim, not a convenience).** Collapsing a chain
into a single coarse action is exactly the substitution the atomic package's
**F10 exact history-wide boundary equivalence** governs: a detailed subsystem
and a parent representation are boundary-equivalent only when, for every
admitted request/observation history, they agree on accept/reject/permission
behaviour, typed flows and losses, timing, completion and pending commitments,
receipts and residuals, and settlement-visible records. Encapsulation therefore
requires a proof obligation; **linked atoms are the cheaper and honest default.**

> F10 is **CANDIDATE and off-branch** (`framework/atomic-generator-foundation-`
> `authority`, `d0d1edd`; F1-F16 "remain candidate decisions"). It is used here
> as a **design discipline**, never as authority. Any claim that rests on it is
> blocked by escalation **E4**.

**Rule A-4 (conservation is declared, not assumed).** Each transformation
carries a declared conservation profile in the sense of
`CONSERVATION_AND_BOUNDARY_ACCOUNTING_FOUNDATION.md`: internal conservation is
the left-nullspace condition `c_q^T S~ = 0`, and anything not conserved
internally must either appear in another explicit coordinate or cross the
declared boundary as `B phi`. Physical quantity may not silently disappear, and
the account level (1 reduced / 2 open control-volume / 3 isolated) must be
stated. **The potential `V` is not a conserved physical quantity** and is never
placed in the same ledger as one.

## 4. Process burden `C` — residual only

**Rule C-1.** `C_a` prices **only** declared action-process burden **not already
represented** by the state transition or the `V_loc` difference. This is the
adopted Gate 1A.1 normative constraint (Def 6.4) and it is already enforced
fail-closed in `ebu_quote_v30.py:56-66`, which refuses the categories
`state_carried_burden`, `monetary_cost`, `labour_cost`, `audit_penalty` and
`fraud_penalty`.

**Rule C-2 (no double count through the chain).** Under Rule A-1 a downstream
physical consequence that is represented as its own atomic action **must not
also** appear inside an upstream action's `C_a`. Representing electricity use as
its own transformation and *also* pricing it in the transfer's `C_a` is a double
count and must refuse.

**Rule C-3.** `C = 0` for a class of actions is **permitted by the type system
and still requires an explicit declaration.** It is never a default and is never
inferred from the absence of a declaration. A world whose modelled physical
transformations are all represented as atomic actions may legitimately declare
`C = 0` for ordinary transfers; that declaration is an author act.

*Slot S-C:* the `C_a` declaration per action class, with its category.

## 5. Simultaneous groups — representable, allocation diagnostic-only

The architecture **must** be able to represent a simultaneous group. It must
**not** assume a permanent one-action-per-micro-step restriction, and it must
not smuggle in an allocation rule.

**What is well defined at any group size.** The group's value: the registered
aggregate form evaluates the **accepted vector, once**.

**What is not.** The split of that value among the group's actions. The
telescoping identity `sum_n De_n = V(x0) - V(x^N) - sum_n C_n` is a **theorem at
`m = 1` only** — Theorem 8.2 holds under condition **(T3), one accepted action
per micro-step**. At `m >= 2` the record offers scheme 2 (proportional) as a
"candidate default" and scheme 4 (radial Aumann-Shapley) as a "registered
refinement, not required", with the general case open as **16.O3**.

**Rule G-1.** Every per-action quantity derived from a group's value carries an
explicit **role**. Permitted roles are `diagnostic`, `reconstruction_check` and
`audit_record`. The roles `settlement`, `wallet`, `causal_entitlement`,
`shapley_allocation`, `mobius_allocation`, `physical_path_claim` and
`responsibility_share` **refuse** at `m >= 2`. This is enforced by
`authority_coordinate.require_diagnostic_only`.

**Rule G-2.** `group_quote`, `naive_sum` and `double_count` are recorded for
every group decision and **nothing is allocated**. Recording the triple without
allocation is explicitly registered as non-settling.

**Rule G-3.** `double_count = naive_sum - group_quote` is the same object as the
bridge's same-baseline non-additivity `N_G := EBU_G - sum_i EBU_i^(0)` **with the
opposite sign**. Implementations must not cite one as the other without stating
the sign.

**Rule G-4 (escalation trigger).** If a scientific claim or a decision rule ever
*requires* a specific per-action split, work stops and escalation **E2** is
raised. Until then, group representation proceeds and allocation does not.

**Rule G-5 (Möbius).** Möbius/inverse-Möbius decomposition of a joint value is
**not** part of this framework. It is SD-06's object — the only stage that
licenses allocating a joint value among actions — and SD-06 is not begun. If it
is ever introduced, F13 requires a frozen subset-evaluation protocol and an
explicit domain decision: Boolean-lattice Möbius is **undefined and must refuse**
when a required subset is inadmissible, and a feasible-set poset "may not reuse
the Boolean alternating-sign rule without its own Möbius proof."

## 6. Long-duration actions and history

**Rule H-1.** An action completes within the tick of its quote. A longer
physical process is a **sequence** of per-tick accepted actions, each quoted on
its own frozen field. This is recorded as "a **protocol restriction, not a
theorem**" and must be labelled as such wherever it is relied upon.

**Rule H-2.** Later actions read the field state existing when they begin.
Quote epochs carry this: stale-epoch rejection is an **adopted** Gate 1A.1
normative constraint, and `ebu_quote_v30.py` already implements `stale_epoch`
and `expired_epoch` refusals. An action's initial field state is never assumed
valid indefinitely.

**Rule H-3 (missing physical memory).** When future evolution depends on history
that no coordinate carries, the missing memory **must become explicit state**
before the study can ask a question that depends on it. The one-tick stock
functional cannot price a persistent change to regenerative *capacity*; the
present field "has no coordinate that changes, so the quote is blind to it."
This is **Open problem 7.2**, and its proposed carrier — promoting certified
capacity to a slow local state coordinate `k_i` — is a **candidate design, not
adopted**.

*Slot S-H:* whether the study requires a capacity coordinate, and if so its
declaration. Unfilled, a study that depends on persistent restoration **must
refuse to run**.

## 8.1 Implemented architecture (safe pieces only)

The mechanisms below are built and validated; **none of them supplies a slot
value**, and every one refuses rather than defaults. They exist so that an
adopted protocol has correct machinery to be filled into.

| Piece | Where | Fail-closed behaviour |
|---|---|---|
| Physical conservation | `study_harness.ConservationProfile`, `Ledger`, `check_closure` | all 14 declared fields of `CONSERVATION_AND_BOUNDARY_ACCOUNTING_FOUNDATION.md` §14.2 required; an undeclared boundary channel refuses; an `exact` policy cannot carry a tolerance |
| Immutable state | `study_harness.State` | no `__setitem__`, no attribute set/delete; `evolve()` returns a new state and cannot introduce a field; mutable field values refused |
| Deterministic demand replay | `study_harness.DemandStream` | SHA-256 counter mode keyed by `(seed, stream_id, index)`; random-access, so a skipped or reordered draw cannot shift the stream |
| Controller information boundaries | `study_harness.InformationBoundary` | projection yields exactly the granted fields; an empty boundary refuses rather than meaning "everything"; a granted-but-absent field refuses rather than shortening the view |
| Receipts / audit | `study_harness.Receipt`, `receipt_chain` | hash-chained; reorder, drop and payload edits all break verification; a receipt is never re-sealed to agree |
| Event logs | `study_harness.EventLog` | append-only, in-memory, tamper-evident; no delete or update; storage cannot be reassigned |
| Negative controls | `study_harness.NegativeControl`, `run_negative_control` | a control that **passes** raises; a control that fails with the *wrong* exception also raises |
| Reproducibility | `study_harness.reproducibility_stamp` | one digest over inputs, code and declarations; reads no interpreter, platform or clock, so two identical runs stamp identically |
| Metrics | `study_harness.MetricSpec`, `evaluate_metrics` | units and direction required; duplicate ids refused; evaluated on **one** frozen state, never across a trajectory |
| Classifications | `study_harness.ClassificationScheme` | exhaustiveness and mutual exclusivity checked; zero matches and multiple matches both refuse — the first match is never taken |
| Preregistration support | `study_protocol_schema.py` | every slot of §7 is a refusal condition; `require_executable` has no success path while E2-E5 stand |

Validation: `test_study_harness.py` (10 groups, 120 checks) and
`test_study_protocol_schema.py` (6 groups, 68 checks), both static and
synthetic only. The synthetic states used are deliberately meaningless numbers;
no world, parameter, metric value, threshold or outcome interpretation appears
in either suite, and a test asserts that none may.
