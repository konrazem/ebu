## 3. Mathematical reconstruction of the safe-export budget

### 3.1 The exact one-tick preservation condition

Require `x_i^{n+1} ≥ R_i^eff`. From (0.1):

```
x_i^n + Δt(u_i^n + I_i^n − Q_i^n) ≥ R_i^eff
 ⟺  Q_i^n ≤ u_i^n + I_i^n + (x_i^n − R_i^eff)/Δt.                          (3.1)
```

Every term on the right is a **rate** (`(x−R)/Δt` is stock·t⁻¹). So the exact
per-tick cap on the **aggregate export rate** `Q_i^n` is (3.1). This is the
correct target the draft's `q_i^{1tick}` approximates.

### 3.2 Audit of the draft's `q_i^{1tick}`

The draft (its §4.1) proposes

```
q_i^{1tick} = g_i(x_i) + (s_i − d_i − λ_i − κ_i x_i) + (x_i − R_i^eff)/Δt
            = u_i^n + (x_i^n − R_i^eff)/Δt.                                (3.2)
```

Point-by-point, as the gate requires:

1. **Rate or per-tick quantity?** It is a **rate** (stock·t⁻¹). The physical
   amount withdrawn in one tick is `Δt · Q_i`. The draft's own §2 table lists
   `q` in stock·time⁻¹, so it is internally consistent, but the review states it
   explicitly because the `(x−R)/Δt` term invites a per-tick misreading.
2. **Correct for one edge?** With a single outgoing edge and `I_i = 0`, (3.2)
   equals (3.1) minus the `I_i` term — i.e. it is the **conservative** cap that
   ignores incoming flow. For one edge and no inflow it is exact.
3. **Correct for multiple simultaneous outgoing edges?** Only if it is applied to
   the **aggregate** `Q_i = Σ_e q_e`, **not** per edge. The draft's §4.3 min-form
   is written per edge; applied independently to `k` edges it permits total
   export `k·Q_max` (§7). **Correction required:** the bound governs the sum, not
   each edge.
4. **May incoming flows be counted?** Committed incoming (already-decided
   transfers into `i` computed from the same frozen state) may be counted, since
   they raise the successor. But this **couples** `i`'s budget to upstream
   sources' export decisions.
5. **Must uncommitted incoming be ignored?** **Yes.** If `i` inflates its budget
   by an *expected* inflow `I_i` that an upstream source later withholds (because
   that source is protecting its own reserve), `i` over-exports and breaches.
   The safe design **ignores `I_i` in the budget** (treats `I_i ≥ 0` as slack).
   The draft did not make this explicit; the review does (Theorem 4.1 uses
   `I_i ≥ 0` only as a one-sided helper).
6. **Already below reserve** (`x_i^n < R_i^eff`): (3.2) gives `(x−R)/Δt < 0`
   added to `u`; the clamp `max(0,·)` sets the budget to 0. But **zero export
   does not restore the source** — this is the *recovery-required* state (§5),
   not a preservation success.
7. **Natural decline alone crosses the reserve** (`x_i^n ≥ R_i^eff` but
   `x_i^n + Δt·u_i^n < R_i^eff`): then even `Q_i = 0` gives
   `x_i^{n+1} = x_i^n + Δt·u_i^n < R_i^eff`. The clamped budget is 0, yet the
   reserve is breached. **This is the central defect the clamp hides** (§3.4).
8. **`Δt = 0`:** (3.2) divides by zero — undefined. (0.1) gives
   `x^{n+1} = x^n` in the limit, so preservation is vacuous, but the budget
   formula is singular. `d0_step` requires `Δt > 0` (`d0_v29.py:346`); the
   certificate is defined only for `Δt > 0`.
9. **Measurement error / delayed field updates:** if the read state `x̂ ≥ x`
   (stale or over-estimated by `ε_x ≥ 0`) and drive `û` over-estimated by
   `ε_u ≥ 0`, then `Q_max(x̂, û) ≥ Q_max(x, u)` and the source over-exports.
   A tolerance-safe budget must subtract the margins **before** clamping
   (§3.5).

### 3.3 Corrected aggregate export budget

> **Candidate design 3.3 (corrected budget + feasibility).** Define the
> aggregate export-rate budget
> ```
> Q_{i,max}^n := [ x_i^n + Δt·u_i^n − R_i^eff ]_+ / Δt                       (3.3)
> ```
> together with the **separate feasibility condition**
> ```
> x_i^n + Δt·u_i^n ≥ R_i^eff.                                                (3.4)
> ```
> Note `Q_{i,max}^n = max(0, u_i^n + (x_i^n − R_i^eff)/Δt) =
> max(0, q_i^{1tick})` — i.e. **(3.3) is exactly the clamp of the draft's
> `q_i^{1tick}` with the incoming term dropped.** The candidate the gate offered
> and the draft's proposal coincide *as clamped budgets*; the substantive content
> is the **separation of (3.4)**.

### 3.4 Why clamping to zero does not preserve the reserve

If the no-export natural successor `x_i^n + Δt·u_i^n` already lies **below**
`R_i^eff`, then `[x_i^n + Δt·u_i^n − R_i^eff]_+ = 0`, so `Q_{i,max} = 0`; but
with `Q_i = 0`, (0.1) gives `x_i^{n+1} = x_i^n + Δt(u_i + I_i)`, and if
`I_i = 0` this is `x_i^n + Δt·u_i^n < R_i^eff`. **The clamp produces a zero cap
that is not a preservation guarantee** — it is a *signal of local infeasibility*.
Preservation therefore requires (3.4) as an *independent hypothesis*, not a
consequence of the clamp. This is the correction the draft's §4.1 gestured at
("can hold `x` at `R` … unsafe") but did not formalise.

### 3.5 Tolerance-safe budget (measurement/delay margin)

> **Candidate design 3.5.** With state tolerance `ε_x ≥ 0` and drive tolerance
> `ε_u ≥ 0` (worst-case over-estimates), the tolerance-safe budget and
> feasibility are
> ```
> Q_{i,max}^{safe} = [ (x_i^n − ε_x) + Δt(u_i^n − ε_u) − R_i^eff ]_+ / Δt,
> (x_i^n − ε_x) + Δt(u_i^n − ε_u) ≥ R_i^eff.                                 (3.5)
> ```
> These are the (3.3)/(3.4) objects with the reserve effectively raised by
> `ε_x + Δt·ε_u`. The draft's uncertainty margin `δ_i` should be identified with
> (and sized to dominate) `ε_x + Δt·ε_u` plus the discrete-overshoot margin of
> §6.

## 4. Candidate preservation theorem

### 4.1 Discrete one-step preservation — proved

> **Theorem 4.1 (one-step aggregate reserve preservation).**
> *Assumptions.*
> (A1) synchronous frozen-state proposals: all `u_i^n, Q_i^n, I_i^n` are computed
> from the single frozen state `xⁿ` and one update (0.1) is applied;
> (A2) `Δt > 0`, known;
> (A3) `R_i^eff` fixed during the tick;
> (A4) `Q_i^n` is the **aggregate** export rate `Σ_{e∈out(i)} J_e`, and there is
> no hidden withdrawal (all outflow is in `Q_i^n`);
> (A5) no clipping creates stock (projection can only *remove* stock at the upper
> bound; the lower bound is not enforced by clipping here — the theorem is about
> the *raw* successor);
> (A6) incoming usable flow `I_i^n ≥ 0` (efficiency `η_e ∈ [0,1]`, `J_e ≥ 0`);
> (A7) reserve state `x_i^n ≥ R_i^eff`;
> (A8) **feasibility** `x_i^n + Δt·u_i^n ≥ R_i^eff`;
> (A9) aggregate export respects the budget `0 ≤ Q_i^n ≤ Q_{i,max}^n` with
> `Q_{i,max}^n` from (3.3).
>
> *Conclusion.* `x_i^{n+1} ≥ R_i^eff`.

*Proof (full algebra).* By (A8), `x_i^n + Δt·u_i^n − R_i^eff ≥ 0`, so the
positive part is inactive as a truncation:
```
[ x_i^n + Δt·u_i^n − R_i^eff ]_+ = x_i^n + Δt·u_i^n − R_i^eff,
```
hence by (3.3)
```
Δt · Q_{i,max}^n = x_i^n + Δt·u_i^n − R_i^eff.                             (4.1a)
```
From the update (0.1) and (A6) `I_i^n ≥ 0`:
```
x_i^{n+1} = x_i^n + Δt·u_i^n + Δt·I_i^n − Δt·Q_i^n
          ≥ x_i^n + Δt·u_i^n − Δt·Q_i^n                 (drop Δt·I_i^n ≥ 0)
          ≥ x_i^n + Δt·u_i^n − Δt·Q_{i,max}^n           (by (A9), Q_i^n ≤ Q_{i,max}^n)
          = x_i^n + Δt·u_i^n − (x_i^n + Δt·u_i^n − R_i^eff)   (by (4.1a))
          = R_i^eff.                                                       ∎
```

The theorem is **valid**; label: **Theorem**. Three features are essential and
were the corrections of §3:

- **(A8) is indispensable.** Without it, `Q_{i,max}^n = 0` (clamp) but
  `x_i^n + Δt·u_i^n < R_i^eff`, so `x_i^{n+1} < R_i^eff`: the conclusion fails
  (see the counterexample 4.2). The draft's `q_i^{1tick}` alone does **not**
  carry (A8) and is therefore an incomplete certificate.
- **Aggregate (A4).** With per-edge caps the sum can exceed `Q_{i,max}` (§7),
  and the step `Δt·Q_{i,max}` is replaced by `Δt·Σ q_e > Δt·Q_{i,max}`, breaking
  the last inequality.
- **Ignore uncommitted incoming.** The proof uses `I_i ≥ 0` only as a one-sided
  slack, so counting `I_i` in the budget is unnecessary and (if uncommitted)
  unsafe; the theorem holds with `I_i` set to 0 in (3.3).

### 4.2 Counterexample for the clamp-without-feasibility reading

> **Observation 4.2 (clamp ≠ preservation).** Take one finite source, `g ≡ 0`,
> `s = 0`, constant demand/leak giving `u = −δ` with `δ > 0`, `R^eff = 5`,
> `x^n = 5` (so (A7) holds with equality), `Δt = 1`. Then the no-export successor
> is `x^n + Δt·u = 5 − δ < 5 = R^eff`: **(A8) fails.** The draft's clamped budget
> is `Q_{max} = [5 − δ − 5]_+ = 0`, and with `Q = 0` the actual successor is
> `5 − δ < R^eff`. Preservation fails despite zero export. This is the
> *locally infeasible* state (§5). It shows the clamp cannot be read as a
> guarantee and that Theorem 4.1 genuinely needs (A8).

### 4.3 Feasibility condition (isolated statement)

> **Definition 4.3 (one-tick feasibility).** A source in reserve
> (`x_i^n ≥ R_i^eff`) is **one-tick-preservable** iff its no-export natural
> successor stays in reserve:
> ```
> x_i^n + Δt · u_i^n ≥ R_i^eff.                                            (4.3)
> ```
> Equivalently `u_i^n ≥ (R_i^eff − x_i^n)/Δt`. When (4.3) holds, some admissible
> export (at least `Q = 0`, at most `Q_{i,max}`) preserves the reserve; when it
> fails, **no** admissible export does.

### 4.4 Continuous-time control-barrier interpretation

Let `h_i(x) = x_i − R_i^eff`. In continuous time (Model C, V2.7 (C.1)),
`ḣ_i = ẋ_i = u_i + I_i − Q_i`. A zeroing control-barrier condition
`ḣ_i ≥ −α(h_i)` with `α` a class-`K` function and export `Q_i ∈ [0, Q̄]` is
satisfiable at the boundary `h_i = 0` iff `sup_{Q_i ≥ 0}(u_i + I_i − Q_i) =
u_i + I_i ≥ 0` — the continuous analogue of feasibility (4.3). So:

> **Observation 4.4.** In continuous time, `h_i ≥ 0` is maintainable exactly when
> the boundary inflow rate `u_i + I_i ≥ 0`. This is a **CBF/Nagumo tangency**
> statement and is **necessary intuition, not a discrete guarantee**: a
> finite-`Δt` explicit-Euler step can jump across the barrier even when the CBF
> condition holds pointwise. The discrete guarantee is Theorem 4.1 with its
> feasibility hypothesis and budget; the continuous result does **not** transfer
> automatically (this is exactly the V2.8 §11 / V2.7 §7 discretisation gap).

## 5. Controlled invariance and infeasibility

The three states the gate demands, made precise for the reserve boundary:

> **Definition 5.1.**
> 1. **Preservable** (state 1): `x_i^n ≥ R_i^eff` **and** feasibility (4.3)
>    holds. Some admissible `Q_i ∈ [0, Q_{i,max}]` keeps `x_i^{n+1} ≥ R_i^eff`
>    (Theorem 4.1).
> 2. **Recovery-required** (state 2): `x_i^n < R_i^eff`. Export must stop
>    (`Q_i = 0`); the reserve can be restored only by natural drive `u_i > 0` or
>    certified inflow `I_i > 0`. Zero export is **not** a preservation success
>    here — it is the correct *do-no-further-harm* action while recovery is
>    sought.
> 3. **Locally infeasible** (state 3): `x_i^n ≥ R_i^eff` but feasibility (4.3)
>    fails (`x_i^n + Δt·u_i^n < R_i^eff`). Even `Q_i = 0` breaches next tick; the
>    breach is locally unavoidable. This must be **reported as infeasibility**,
>    never labelled preservation.

### 5.1 Status of the safe set — the correct term

Let `S = {x : x_i ≥ R_i^eff for every critical non-substitutable i}`.

> **Observation 5.2 (S is NOT forward-invariant; it is controlled-invariant only
> on a sub-region).**
> - **Not forward-invariant:** the uncontrolled/autonomous flow (fixed export
>   policy, e.g. demand-driven `Q`) can leave `S` — a state-3 point breaches with
>   any policy including `Q = 0`. So `S` is not forward-invariant.
> - **Controlled-invariant only on the feasibility kernel.** Define the one-step
>   **controlled-invariant kernel** (ignoring uncommitted inflow, `I_i = 0`)
>   ```
>   K₁ = { x ∈ S : x_i + Δt·u_i(x) ≥ R_i^eff for every critical i }.        (5.1)
>   ```
>   By Theorem 4.1, from any `x ∈ K₁` there exists an admissible export
>   (`Q ∈ [0, Q_max]`) with `x^{n+1} ∈ S`. On `S \ K₁` (state 3) no admissible
>   export keeps `x` in `S`. Hence **`S` is controlled-invariant on `K₁`, not on
>   all of `S`.**
> - Full (infinite-horizon) controlled invariance requires the **largest
>   controlled-invariant subset** `K∞ ⊆ K₁` (the viability kernel), obtained by
>   iterating the one-step operator until fixed point. Computing `K∞` needs the
>   drive/inflow envelope and is an **Open problem** (§6.3); `K₁` is the
>   one-step conservative inner estimate.
>
> **Correct terminology:** `S` is **conditionally / controlled-invariant on its
> feasibility kernel `K₁`**, and **not invariant** elsewhere. Calling a zero
> export cap on `S \ K₁` a "preservation guarantee" is a category error.

## 6. Source-type audit

### 6.1 External renewable flows (sunlight, wind)

The resource is a **flow** `s_i`, not a stock. The binding safe condition is a
**flow cap** `Q_i ≤ s_i` (+ any buffer term), not a stock reserve. If a buffer
stock exists, (3.3)/(3.4) apply to the buffer; but sustainable *export* cannot
exceed arriving flow, and over-draw depletes the buffer = debt (§9), not a
reserve crossing. `S` as a stock set is the wrong object for a pure flow.

### 6.2 Logistic regenerative stocks — MSY is an equilibrium, not a safe action

`q^{long} = (1−m)ρK/4`. Audit:

- `ρK/4 = g_max` is the **maximum sustainable yield**, attained only *at the
  equilibrium* `x = K/2`. It is an **equilibrium** property (V2.7 Thm 3.1: the
  fold at `h = ρK/4`, `x_− = x_+ = K/2`), **not** a safe action from arbitrary
  stock.
- Harvesting at `g_max` sits exactly at the fold (marginally stable); any
  perturbation or discrete overshoot tips to collapse. Hence the strict margin
  `m > 0`.
- **Required assumptions for `q^{long}` to be safe** (V2.7 Cor 3.3): (i) basin —
  `x^n > x_−(q)`; (ii) flip stability — `ρ√D < 2`, `D = 1 − 4q/(ρK)`; (iii) the
  one-tick budget also holds — `q ≤ Q_{i,max}^n`. So the realised safe export is
  `min(Q_{i,max}^{1tick}, q^{long})`, and even this does not guarantee
  multi-tick basin retention without (i)–(ii).

> **Observation 6.1.** `q^{long}` is **necessary, not sufficient**, and is only
> an *equilibrium* bound. From below `x_−` it is actively harmful (collapse
> basin). It is a *design-time ceiling*, combined at action-time with the
> one-tick budget (3.3); neither alone certifies long-run sustainability.

### 6.3 Allee sources — driven root, discrete overshoot, design-time certification

Reconstruct the driven persistence boundary (V2.7 Thm 4.2): the **unstable middle
root** `x_r` of
```
G_i(x) = ρ_i x(1 − x/K_i)(x/A_i − 1) + s_i − d_i − λ_i − κ_i x − h_i = 0,   (6.1)
```
with `G'(x_r) > 0` and (V2.7 (4.2)) `∂x_r/∂h = ∂x_r/∂d = ∂x_r/∂λ = 1/G'(x_r) > 0`,
`∂x_r/∂κ = x_r/G'(x_r) > 0`, `∂x_r/∂s = −1/G'(x_r) < 0`. Export (harvest/transport-
out) **raises** `x_r`; supply lowers it. Undriven `x_r = A` (V2.7 Thm 4.1).

Is `R_i^eff ≥ x_r + δ_i` sufficient? Analysis:

- **Continuous, fixed drive:** `x_r` is the separatrix; staying above it keeps the
  source in the recovery basin. `R^eff ≥ x_r` with margin `δ` is the correct
  *continuous* target.
- **Discrete overshoot:** an explicit-Euler step of size `Δt·(u − Q)` can jump
  from above `x_r` to below it in one tick even if the continuous flow would not.
  `δ_i` must therefore dominate the worst one-step decrement below the crossing,
  which is bounded via the step and the local drive/export (an overshoot margin,
  akin to V2.8 §5 step bounds). So `δ_i ≥ (x_r − A_i)` (drift, V2.7 C-2) **plus**
  a discrete-overshoot term.
- **Varying drive:** `x_r` moves with `(s,d,λ,κ,h)`. The safe reserve must
  dominate the **supremum** of `x_r` over the declared operating envelope:
  `R_i^eff ≥ sup_{drive∈env} x_r(drive) + δ_i`.

> **Observation 6.2 (design-time non-local certification vs action-time local
> decision).** `sup_{drive∈env} x_r` is a root computation over a declared
> parameter envelope — a **non-local, design-time** calculation done once at
> configuration. Its *result* is stored as the **local constant** `R_i^eff`. At
> **action time** the actor reads only `R_i^eff`, `x_i^n`, local params and `Δt`
> (Theorem 4.1). This cleanly separates a one-off non-local certification from
> per-action local decisions — and is exactly what the intended architecture
> ("future consequences encoded in present local field properties") requires. It
> is **Conjecture C-2** of V2.7 that a constant `R_i^eff` so chosen dominates the
> driven root over the envelope; that conjecture remains **unproved**.

### 6.4 Finite / non-regenerating stocks (`g ≡ 0`)

`x^{n+1} = x^n + Δt(u^{no-g} − Q)`. With `g ≡ 0` there is **no sustainable
positive export**: `q^{long} = 0`. Theorem 4.1 still preserves `R^eff` for a
finite number of ticks (the buffer `x^n − R^eff` funds `Δt·Q` withdrawals), but
holding at `R^eff` forever requires `Q = 0` and `u^{no-g} ≥ 0`. Any `Q > 0`
draws down a non-renewable buffer and is **depletion → debt** (§9), even while
`x > R^eff`.

> **Definition 6.3.** For `g ≡ 0`, "safe stock level" is **not** a sustainability
> concept: the honest local object is a depletion/debt rate, not a positive safe
> rate.

### 6.5 Irreversible ecological capacity

`R_i^eff` is set at (or above) current stock; safe export is **0**; any net use
is irreversible debt `D_r^irr` (§9). No price (G1) or transfer (G2) alters this.

### 6.6 Universal local safe rate — impossibility

> **Impossibility 6.4.** No single local action-time rate `q_i^safe > 0`
> certifies long-run sustainability across **all** source types under the current
> assumptions: finite/irreversible sources admit no positive safe rate (§6.4–6.5),
> and the Allee long-run boundary is the drive-dependent root `x_r` that is not a
> closed-form local function of the frozen state (§6.3). The **one-tick reserve
> budget** (3.3) *is* local and universal; **long-run** sustainability is not
> locally certifiable without design-time `R_i^eff` certification (Observation
> 6.2). The draft's Impossibility note 4.5 is confirmed and sharpened.

## 7. Multiple actors and source allocation

### 7.1 Why independent per-edge use of the full budget overdraws

Suppose `k` outgoing edges each read the same frozen state, each compute
`Q_{i,max}^n`, and each withdraw up to it. Aggregate export is
`Σ_{e=1}^{k} q_e` which can reach `k · Q_{i,max}^n`. Substituting into (0.1):
`x^{n+1} = x^n + Δt(u + I − Σ q_e) ≤ x^n + Δt·u − Δt·(k Q_{i,max})
= R^eff − (k−1)(x^n + Δt·u − R^eff) < R^eff` for `k ≥ 2` (under feasibility). The
reserve is breached by exactly the `(k−1)` surplus copies of the budget. So the
**aggregate constraint `Σ_{e∈out(i)} q_e ≤ Q_{i,max}` is mandatory**; independent
per-edge caps are unsound.

### 7.2 Minimal local coordination — allocator comparison

The allocator must enforce `Σ_e q_e ≤ Q_{i,max}` while preserving four
properties: **(P-agg)** the aggregate bound, **(P-sim)** simultaneous frozen-state
semantics, **(P-ord)** order invariance, **(P-loc)** locality (only source `i`
and its outgoing edges' local data). Reviewing the four schemes *only enough to
classify* (no implementation):

| Allocator | P-agg | P-sim | P-ord | P-loc | verdict |
|---|---|---|---|---|---|
| **Proportional scaling** (desired `q̃_e`; if `Σ q̃_e > Q_max` scale all by `Q_max/Σ q̃_e`) | ✓ | ✓ | ✓ (symmetric in edges) | ✓ (source-local aggregation of its own out-edges) | **preserves all four** |
| **Priority** (fill highest-priority edges first) | ✓ | ✓ | ✗ (result depends on priority order) | ✓ | breaks P-ord |
| **Auction** (edges bid) | ✓ | ✗ (needs iteration/price discovery) | depends | ✗ (bids ≈ nonlocal signal) | breaks P-sim/P-loc |
| **Sequential live-state** (apply edges one-by-one against updated stock) | ✓ | ✗ | ✗ | ✓ | breaks P-sim/P-ord; **also** breaks one-tick locality (V2.8 Obs 9.2) |

> **Observation 7.1 (minimal mechanism).** **Frozen-state proportional source
> scaling** is the minimal local coordination that preserves the aggregate bound,
> simultaneity, order invariance, and locality. It is exactly the mechanism
> registered — but not implemented — as **P1C** (V2.9 Amendment 1 §17.1,
> Amendment 2 §18.2). It is **outside** the V2.8 D0 theorem (it is a constrained,
> non-smooth allocation), so its guarantees need separate proof; Theorem 4.1
> covers the aggregate `Q_i`, and proportional scaling is the way to *realise* an
> admissible `Q_i ≤ Q_{i,max}` across edges without order dependence.

## 8. Relation to V2.8

### 8.1 What V2.8 contributes (proved, at its stated scope)

Local state functional `V(x)=Σv_i` (Def 2.1); local marginal `μ_i=v_i'`; loss-
aware force `f_e=μ_i−η_e μ_j` (Def 2.3); synchronous D0 update (Def 3.2);
dissipation identity `f_e J_e = J_e²/M_e+θ_e J_e` (Lemma 4.2); finite-step
remainder `R_n=(L_V Δt²/2)‖u+SJ‖²` (Thm 4.4); sufficient timestep bounds (Thm
5.1/5.2/5.5/5.6, Rmk 5.4); stock/loss ledger `1ᵀΔx=Δt[1ᵀu−Σ(1−η)J]` (Thm 8.1);
one-tick locality (Thm 9.1).

### 8.2 What the preservation theorem adds

Theorem 4.1 is a **reserve-preservation** statement: a per-cell lower-bound
invariance under an **aggregate export budget** and a **feasibility hypothesis**.
V2.8 proves none of this. In particular:

- V2.8's descent theorem is about the **potential `V`** decreasing; Theorem 4.1
  is about the **state coordinate `x_i`** staying above `R_i^eff`. These are
  different objects (V2.8 Remark 8.3 already warns `V` is not a stock).
- V2.8 is **unconstrained** (Def 3.2, §11 excludes clipping/projection). Theorem
  4.1 imposes a **constraint** `Q_i ≤ Q_{i,max}` — outside the D0 law.

### 8.3 What kind of law the hard cap is, and the new proof obligation

> **Observation 8.1.** The hard-cap preservation law is best understood as a
> **barrier-certified constrained allocation**: a projected/constrained D0 step
> in which the *aggregate* outgoing flux is capped by the reserve budget (3.3)
> and distributed by proportional scaling (§7). It is neither the free D0 flow
> nor plain `[0,K]` clipping (P1K); it is a **new law** in the same *class* as
> P1K/P1C — outside V2.8 (V2.8 §11 lists projection among the excluded
> mechanisms).
>
> **The V2.8 descent theorem does not transfer** because (i) it assumes the
> unconstrained update, and capping `Q_i` changes the flux, so the descent
> algebra (Lemma 4.1/4.2) no longer applies verbatim; (ii) capping can leave the
> potential non-monotone. **New proof obligation:** show that the constrained/
> projected law (a) still satisfies a (possibly weaker) dissipation/descent
> inequality, **and** (b) satisfies Theorem 4.1's invariance jointly across all
> sources and edges under proportional allocation. Neither is proved here or in
> V2.8. **V2.8 does not prove hard reserve preservation.**

## 9. Ecological-debt audit

Audit of `D_r^{n+1} = max(0, D_r^n + O_r^n + Λ_r^n − Ĉ_r^n)`.

### 9.1 Per-term definition

| term | physical meaning | units | measurement time | reversibility | stock/rate/accum |
|---|---|---|---|---|---|
| `D_r` | ecological debt in account `r` | resource-`r` units | end of tick | see split (9.2) | **accumulated** stock of debt |
| `O_r^n` | certified overdraw: `∫_tick (Q_i − Q_{i,max})_+` mapped to account `r` | resource-`r` units | during tick, post-certification | contributes to rev or irr per source type | accumulated over tick (rate·Δt) |
| `Λ_r^n` | attributable additional damage (spill, habitat loss) | resource-`r` units | at event | often irreversible | accumulated over tick |
| `Ĉ_r^n` | **verified** net restoration credited to account `r` | resource-`r` units | after persistence horizon (§10) | reduces only `D_r^rev` | accumulated over tick |

Dimensional consistency: all terms in resource-`r` units; `max(0,·)` keeps the
accumulated debt non-negative. ✓ The overdraw uses the **corrected** budget
`Q_{i,max}` of §3, tying the debt layer to the preservation certificate.

### 9.2 Reversible / irreversible split

> **Definition 9.1.** `D_r = D_r^rev + D_r^irr`, with `D_r^irr` **monotone
> non-decreasing**: `Ĉ_r` may reduce `D_r^rev` but **never** `D_r^irr`
> (`D_r^{irr,n+1} = D_r^{irr,n} + O_r^{irr} + Λ_r^{irr}`, no `−Ĉ` term).
> Finite-stock depletion (§6.4), collapse-basin entry (§6.3), and extinction feed
> `D_r^irr`.

### 9.3 What "paying debt" means for irreversible loss

For `D_r^irr`, "paying" is **impossible** in kind: no quantity of EBU, tokens, or
labour reduces `D_r^irr`. An external layer may assign *responsibility* (Store C,
draft §9) and demand compensating restoration *in a different, substitutable
account*, but that does **not** reduce `D_r^irr` — it opens a (declared,
physically justified) offset in another account, which the non-substitutability
rule (Def 6.1) forbids unless such a law exists. Honest statement: **irreversible
debt is permanent**; the ledger records it forever.

### 9.4 Guardrails confirmed

- Wallet transfers, market exchange, labour, and payment **do not appear** in the
  debt update (no `w_a` term). Therefore they **cannot reduce physical debt**
  (G2). ✓ Confirmed structurally.
- Debt is **resource-specific**; no cross-account netting (Def 6.1). ✓
- Uncertainty recorded at the conservative (larger-debt) end. ✓ (draft §6.3).

> **Verdict 9.2.** The debt structure is **coherent as a vector accounting law**
> with the irreversibility split. Two items are **Open problems**: (i) the exact
> attribution map from a physical overdraw to `(O_r, Λ_r)` across accounts
> (measurement/provenance), and (ii) the operational definition of "verified"
> for `Ĉ_r` (§10).

## 10. One-to-one restoration credit audit

Proposed: `1` unit verified net reduction in `D_r ↔ 1` EBU credit in account `r`.

### 10.1 Dimensional analysis — the decisive point

`D_r` is in **resource-`r` units**; an "EBU credit in account `r`" is therefore
denominated in resource-`r` units (or a fixed per-account reference). The
one-to-one rule is an **account-scoped identity**, which means:

> **Observation 10.1 (EBU must start as a vector).** A scientifically honest
> first implementation uses a **vector of resource-specific EBU accounts**
> `(EBU_carbon, EBU_water, …)`, each in its account's units, **not** a single
> immediately fungible scalar token. Collapsing to a scalar requires **conversion
> weights / normalisation / an energy-equivalent reference** between
> non-substitutable accounts — an **unresolved design choice** that must not be
> introduced silently (it would be exactly the cross-resource laundering the
> guardrails forbid). Therefore **scalar EBU is not currently justified.**

### 10.2 Checklist audit of the credit rule

| requirement | verdict |
|---|---|
| **dimensional consistency** | ✓ only within an account; cross-account scalarisation unresolved (10.1) |
| **no-action counterfactual** | required: credit = `ΔD_r^{no-action} − ΔD_r^{observed}`, attributable — **candidate**, not proved sufficient |
| **action-burden subtraction** | required: net of the restorative act's own burden (V2.5 debits `λ_L·loss + λ_F·F_a` are the existing analogue) |
| **persistence horizon `H`** | required: credit vests only after restoration persists `H` ticks — guards transient gains |
| **telescoping** | V2.5 live-state telescoping is the correct mechanism (`ebu_v25.py:78`) |
| **no double-credit** | each unit of `D_r` reduction creditable once — telescoping enforces |
| **damage-then-repair ≤ 0** | must require ending **above** pre-damage baseline for positive net credit |
| **split-action invariance** | live-state telescoping makes splitting neutral (V2.5 closes the splitting attack) |
| **delayed restoration** | horizon `H` + provenance timestamps (Store B) |
| **natural-regeneration claims** | must be **excluded**: the source's own `g_i` is not the actor's restoration — the V2.0 counterfactual test (`energy_balance`: natural inflow/regen not credited, impact = 0) is the physics-layer precedent |
| **multi-actor attribution** | `Σ_a Ĉ_{r,a} ≤` total verified reduction — needs an attribution rule (Shapley/proportional): **Open problem** |
| **collusion** | V2.6 found a **confirmed guarded exploit on 1/12 layouts** (+260 EBU while all sources die); so the *existing* guarded ledger is **not** collusion-proof and the new credit rule inherits this risk until re-audited |
| **cross-resource laundering** | prevented **only** by account-scoping (10.1); scalarisation reopens it |

> **Verdict 10.2.** The one-to-one credit is a **coherent candidate** *within an
> account*, reusing V2.5's telescoping/burden-debit machinery, but it is **not
> proved** and **not** already delivered by V2.5/V2.6 (which lack counterfactual,
> persistence, irreversibility, and resource-specificity, and are known
> exploitable, V2.6). Multi-actor attribution and the "verified" predicate are
> **Open problems**.

## 11. Information-boundary audit

The intended architecture — "future consequences are encoded in present local
field properties" — is realisable **iff** every action-time decision reads only
local field data and the future-dependence is pre-compiled into local constants
(chiefly `R_i^eff`, Observation 6.2).

**A local actor at source `i` / edge `(i→j)` MAY read** (all present, local):
current stock `x_i^n`; local source type and regeneration parameters
(`ρ_i,K_i,A_i,g_i`); local losses/declared demand (`λ_i,κ_i,d_i,s_i`); reserve
`R_i^eff`; the **remaining aggregate export budget for the tick**
`Q_{i,max}^n − Σ_{already-allocated} q_e` (a source-local scalar, §7); and the
adjacent destination data its flow rule needs (`x_j^n` and `j`'s declared
params + edge constants `η,M,θ`) — exactly the V2.9 §4 / `d0_v29.LocalView`
boundary, enforced by `test_v29.py` group 9.

**It MAY NOT read:** global `V`; global ecological debt `D_r`; future
trajectories / rollouts; whole-world state; global viability; any evaluation-only
metric (V2.9 §4.2, Def 4.2.1).

**Certifying/updating `R_i^eff` without a per-action global solve** — three
clearly separated timescales:

1. **Design-time ecological certification** (non-local, once): compute
   `sup_{drive∈env} x_r` (§6.3) and any MSY/basin margins over the declared
   operating envelope; store the result as the local constant `R_i^eff`. This is
   the only non-local step and it happens **off the action path**.
2. **Slow monitoring updates** (rare, out-of-band): revise `R_i^eff`, `ρ,K,A`,
   tolerances `ε_x,ε_u` as ecological monitoring improves — a governance/Store-B
   write, not an actor decision.
3. **Action-time local decision** (every tick, local): read `R_i^eff` + local
   field, apply Theorem 4.1's budget and the proportional allocator. No global
   optimisation, no rollout.

> **Observation 11.1 (causal/information honesty).** The architecture is
> information-consistent **only** under the assumption that `R_i^eff` correctly
> pre-encodes the future boundary over the *actual* operating envelope (V2.7
> Conjecture C-2). If drive leaves the declared envelope, the stored `R_i^eff`
> may under-protect and the local decision is silently wrong — a real causal
> assumption that must be stated, monitored (timescale 2), and never hidden. With
> that caveat, "future encoded in present local field properties" is **sound**;
> without design-time certification it is **not** achievable locally
> (Impossibility 6.4).

## 12. D9 and D10 readiness

### 12.1 D9 — must actually reach the driven reserve (fix the D5 defect)

The frozen Gate-2 D5 was **non-discriminating**: the Allee source started at
`x₀ = 6.5` (already below `R = 8`, so no downward `R`-crossing was possible) and
**rose monotonically** to `19.33` (source-min `6.697`), never nearing `A = 5`, so
`χ` was never exercised (confirmed from the trace). A discriminating D9 must
satisfy **analytically-derivable** conditions:

> **Candidate design 12.1 (D9 conditions).**
> 1. **Start strictly in the recovery basin, above the effective reserve:**
>    `x₀ > R^eff > x_r`, but only *modestly* above, so the arms can separate.
> 2. **Drive the source toward the driven unstable root:** choose demand/export so
>    the reserve-**blind** operating point (root of `G(x)=0`, (6.1)) satisfies
>    `x_r > A` and lies **below** `x₀` — i.e. the pull actively lowers the source
>    into the reserve band the penalty must resist. Concretely, pick
>    `(d, η, θ, M)` so that the steady export exceeds the Allee regeneration
>    available near `R^eff`: `η·J_e(R^eff) > g_Allee(R^eff)` at the frozen state.
> 3. **Make the arms genuinely differ:** three configurations — reserve-blind
>    `χ = 0`, reserve-aware soft `χ > 0`, and **hard-cap** (`Q ≤ Q_{i,max}`, §3).
>    Because the quadratic `χ` penalty is **soft** (its marginal `−2χ(R−x)₊`
>    vanishes at `x = R` — draft Observation 5.1), the *discriminating* prediction
>    is that **only the hard cap** holds the source above `R^eff`, while `χ > 0`
>    merely delays the crossing. D9 must be able to show that separation.
> 4. **Certified `Δt`** below the Gershgorin bound (V2.8 Rmk 5.4), as Gate 2.
> 5. **Registered discriminator:** downward `R`/`A` crossings and source survival
>    must differ across the three arms; if they do not, D9 is (like D5)
>    non-discriminating — and that null result must be **reportable**, not tuned.
>
> All of (1)–(4) are fixable **analytically** from `G(x)=0` and the flux at
> `R^eff` **before any simulation**; exact `(ρ,K,A,δ,d,η,θ,χ,Δt)` are left
> **unresolved** for a future preregistration (no exploratory search here).

### 12.2 D10 — service-vs-preservation map

> **Candidate design 12.2 (D10 axes and boundaries).** Deterministic grid (no
> seeds) over analytically-motivated axes:
> - **`d / g_max = d/(ρK/4)`** — primary axis; crosses `1` at the feasibility
>   fold (V2.7 Thm 3.1). Boundaries: `<1` potentially serviceable, `=1` fold,
>   `>1` demand exceeds sustainable yield.
> - **`η`** (loss / loss-aware force), **`θ`** (activation gate), **`δ` or `χ`**
>   (soft-vs-hard preservation strength), **`ρ`** (flip axis, `ρ√D<2`), **`Δt/r_dt`**
>   (below vs at certified bound).
>
> **Classification boundaries** (using §5 states and the debt layer):
> - **safe service** — feasibility (4.3) holds every tick, demand met, `O_r ≡ 0`;
> - **safe rationing** — feasibility holds, `O_r ≡ 0`, but served < demand
>   (export capped by `Q_{i,max}`);
> - **debt-incurring service** — demand met but `O_r > 0` (export exceeded
>   `Q_{i,max}`), debt recorded;
> - **infeasible demand** — no admissible export meets demand within `S`
>   (state 3 reachable);
> - **ecological collapse** — source crosses into the collapse basin
>   (`x < x_r`), `D_r^irr` increases.
>
> Candidate ranges (illustrative, **unresolved**): `d/g_max ∈ {0.25,0.5,0.9,1.0,
> 1.1}`, `η ∈ {0.5,0.7,0.9,1.0}`, `δ` spanning `x_r − A` from below to above.
> Final numbers derived at preregistration from fold/flip/root conditions,
> **never** by exploratory runs.

## 13. Verdict

> **Overall: PASS WITH CORRECTIONS.** The proposed architecture — locally encoded
> reserve, safe-export budget, resource-specific ecological-debt vector, and
> verified one-to-one restoration credit — is mathematically **coherent and
> compatible** with the Energy Balance Project's original objective, and it
> **can** support the intended principle (local actors avoiding regenerative
> exploitation from present local field information, without global evaluation or
> per-action rollout) — **provided** the named corrections are adopted. It is
> **not** PASS-as-written (the draft's `q^{1tick}` omits the feasibility
> condition and the aggregate framing), and it is **not** FAIL (no fundamental
> contradiction was found; a valid one-step theorem exists).

Per-component assessment:

| Component | Verdict |
|---|---|
| **Local preservation** | **PASS WITH CORRECTIONS** — Theorem 4.1 holds with the **added feasibility hypothesis (4.3)** and **aggregate budget (3.3)**; the draft's clamp-only `q^{1tick}` is incomplete (Observation 4.2). |
| **Source-specific certification** | **PASS WITH CORRECTIONS** — one-tick budget is local & universal; long-run needs design-time `R^eff` (Obs 6.2); no universal positive local safe rate (Impossibility 6.4). |
| **Ecological debt** | **PASS** as a vector law with the irreversibility split (Def 9.1); attribution & "verified" predicate are Open problems. |
| **One-to-one restoration credit** | **PASS WITH CORRECTIONS** — coherent within an account; needs counterfactual/persistence/no-double-count; **not** already provided by V2.5/V2.6 (Open problem 7.3 / 10.2). |
| **Eventual fungible (scalar) EBU** | **NOT YET JUSTIFIED** — one-to-one credit forces a **vector** of resource-specific accounts; scalarisation needs conversion weights that must not be introduced silently (Observation 10.1). |
| **Compatibility with the original EBP objective** | **PASS** — the design is on the original path and is a *constraint added to* V2.8, not a claim that V2.8 already proves preservation (Observation 8.1). |
