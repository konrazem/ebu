# EBP V3.0 Gate 1D-B — O14 Multi-Out-Edge Capability Study: Analytical Design and Preregistration

**DESIGN-AND-PREREGISTRATION ONLY.** This gate creates exactly two files
(this protocol and `v30_o14_multi_edge_plan.json`) and executes nothing. No
behavioral trajectory of any length was run while producing it; every number
below comes from static algebra, root calculations and the released
certificate functions evaluated at declared frozen states. Implementation,
pre-execution testing and the single official execution each require
separate authorization. Passing future numerical tests will not prove
alignment, safety, or any theorem.

**Question under test.** When one source has several simultaneously
available outgoing choices, does maximizing the exact local total EBU quote
select actions that preserve the source and provide useful service, or can
it prefer a locally profitable but service-inferior destination or quantity?

**The candidate heuristic (a heuristic, NOT a theorem).** For each feasible
edge `e` of the acting source, with the exact committed quote schedule

```
Delta e_e(q) = V_local(z) - V_local(T_e(q) z) - C_e(q),   0 <= q <= q_e,max,
```

choose `q_e* = argmax_{0 <= q <= q_e,max} Delta e_e(q)` and then
`e* = argmax_e Delta e_e(q_e*)`; execute only if the maximum exact total
quote is strictly positive, otherwise rest. Ranking is by **exact total
quote**; EBU **per unit is forbidden** as a ranking key (falsifier F8).

## 2. Mathematical choice audit

### 2.A Single selected edge: the schedule and its exact maximization

For source `i`, destination `j`, edge `e` with efficiency `η_e`, frozen
no-action successor `z = x + Δt·u(x)` (drive computed with demand stripped,
per the Gate 1D semantics), the exact committed schedule on `[0, q_e,max]`
is (foundation eq. 6.1):

```
Delta e_e(q) = [v_i(z_i) + v_j(z_j)] - [v_i(z_i - Δt q) + v_j(z_j + Δt η_e q)] - C_a(q),
C_a(q)      = c0·1[q>0] + λ_L Δt (1-η_e) q ,   c0 = 0.0, λ_L = 0.1 (Gate-1 convention).
```

`q_e,max` is `min(frac_max · J_e, Q_max)` where `J_e = M_e[f_e - θ_e]_+` is
the released raw loss-aware request and `Q_max` is the **authoritative
source-local P1C budget** (`p1c_v29.robust_budget` for State-P regenerative
sources; zero for R/I/finite/irreversible; the flow rule for State F).

**Structure.** With the piecewise-quadratic family
`v(x) = α[L-x]_+² + β[x-U]_+² + χ[R-x]_+²`, the schedule is a piecewise
quadratic in `q` with breakpoints where `z_i - Δt q` or `z_j + Δt η_e q`
crosses a branch boundary (`L`, `U`, `R` of either endpoint). By Theorem 6.9
with `c0 = 0` and `C_a` linear (convex, anchored), the **full schedule is
concave on `[0, q_e,max]`** — the activation-branch caveat of Def 6.13a does
not arise at the registered cost constants.

**How `q_e*` is calculated (frozen decision).** Two objects are registered:

1. **Action selection uses exact enumeration over the registered finite
   menu** `{frac · J_e : frac ∈ (0.25, 0.5, 0.75, 1.0)}`, each capped at
   `Q_max`. Enumeration of a finite set of exact schedule evaluations is
   deterministic, uses only source and adjacent-destination state, handles
   `q = 0` exactly (rest is the exact zero branch, `Δe(0) = 0`), respects
   the (here inactive) activation discontinuity by never interpolating
   across `0`, never evaluates outside `q_e,max`, and uses **total** quote.
2. **The continuous vertex is recorded as a diagnostic only.** On each
   quadratic branch the unconstrained maximizer is closed-form; e.g. with
   the source penalty-inactive and the destination on its deficit branch
   with deficit `D_j = L_j - z_j`:
   `q_cont* = [2 α_j η_e D_j - 2 α_s S_i - λ_L(1-η_e)] / (2 Δt (α_j η_e² + α_s))`
   (with `S_i = [L_i - z_i]_+` the source's own deficit slack, `α_s` its
   deficit weight; branch-crossing cases resolve by evaluating the finite
   breakpoint set — exact for the quadratic family). This value is recorded
   per candidate to measure the menu-discretization gap. It never selects
   actions.

**Tie rule (frozen, no hidden physical objective):** exact-quote ties break
by lower edge index, then lower quantity-menu index — deterministic
identifiers only.

**Registered boundary-optimality lemma (analytic finding, falsifiable in
the study).** Under `r_dt ≤ 1`, the per-tick transfer `Δt η q` is bounded by
the certificate so strongly that, for a source with inactive penalty
branches at the frozen state and a destination on a single deficit branch,
the schedule is **strictly increasing on the entire feasible menu**, hence
`q_e* = q_e,max`. Sketch: increase requires
`2 Δt M (α_j η² + α_s) ≳ 1` at `q = J_e`; with the binding Gershgorin
certificate `Δt·M ≤ 1.8 / (L_V · [(1+η²) + (k-1)])` (k out-edges) and
`L_V ≥ 2 max(α)`, the left side is at most ≈ 0.86 at `r_dt = 0.9` (and
≈ 0.48 at `r_dt = 0.5`) for the α-balanced corner, i.e. the vertex
`q_cont*` sits at or beyond `q_e,max` throughout the registered worlds —
verified numerically for all 96 candidate evaluations of §4 (every
schedule strictly increasing across the menu). Consequences: (i) quantity
misalignment is **structurally excluded at the registered timesteps** in
these families — a genuinely interior optimum requires the parameter corner
`α_s ≈ α_j`, `χ_src = 0`, `η ≥ 0.9` **and** `r_dt` near 1, which is
registered as a possible future extension with its own certificate
analysis, not smuggled in here; (ii) any interior menu pick observed in the
study is itself a reportable surprise (it falsifies the lemma's premise
audit for that tick, not the study).

**Linear form ban.** The linear diagnostic
`Δt q (μ_i - η_e μ_j) - C_e(q)` over-quotes (Theorem 6.9; E1: 15.18 vs 7.94,
E2: −0.08 vs −5.52) and is **never** used for settlement or ranking; it is
recorded only as the analytical link to the V2.8 force.

### 2.B Joint fan-out transformation and the double-count audit

For one source `i` sending simultaneously over edges `e ∈ E_i` to
destinations `j(e)` with accepted rates `q_e`:

```
Delta e_group(q_vec) = v_i(z_i) + Σ_j v_j(z_j)
                     - v_i(z_i - Δt Σ_e q_e) - Σ_e v_j(e)(z_j(e) + Δt η_e q_e)
                     - C_group(q_vec),          C_group = Σ_e C_e(q_e).
```

By Lemma 6.6 (separability) this equals the global finite difference — the
affected set is the source plus its destinations, and locality is exact.

**Independently frozen per-edge quotes double-count the shared source
term.** The committed Counterexample 10.1 already witnesses this on a
shared endpoint (`η = 1, u ≡ 0, C ≡ 0`, source `x_i = 18` with `v = 4`,
destination `x_j = 0` with `v = 16`, two accepted `q·Δt = 2` actions:
independent quotes `2 × 16 = 32` versus true joint `+20` — **12 phantom
EBU**). The same algebra applies verbatim to one source with two out-edges:
take `v(x) = [5 - x]_+²` at the source (α = 1, L = 5), `z_i = 4`, two edges
with `Δt q_e = 2` each, destinations flat (`v_j ≡ 0` region) and `η = 1`,
`C = 0`. Each independent per-edge quote charges the source
`v(2) - v(4) = 9 - 1 = 8`, so the naive sum charges `16`; the true joint
withdrawal charges `v(0) - v(4) = 25 - 1 = 24`. Independent quotes
**under-charge the joint source drawdown by 8** — a per-source fan-out
over-issuance of exactly the convexity gap. **Proposition 10.2** proves the
general inequality: for convex `v`, the sum of independent same-baseline
quotes on a shared cell is ≥ the true joint quote on the credit side and ≤
on the damage side; strict whenever a shared endpoint's increments straddle
a strictly convex branch. **Independent per-edge credit is therefore NOT
conservative for fan-out; this is registered, not assumed away.**

### 2.C Aggregate attribution readiness — verdict: NOT ready; O3 stays open

Reviewed against the draft §10.2 requirements (V-cons conservativity,
V-split split-invariance, V-ord order-invariance, V-loc locality):

| Mechanism | Status | Blocking gap |
|---|---|---|
| independent per-edge quotes | rejected (Cex 10.1 / §2.B) | violates V-cons, V-split |
| proportional-to-`q_acc` sharing of the group quote | candidate default; conservative and split-invariant **at one-source-one-tick scope** (proved in draft §10.2) | multi-tick/multi-source split-invariance and the request-inflation incentive ("does inflating `q_req` to capture allocation share pay?") are **unproven — O3** |
| sequential marginal (live state) | rejected | order-dependent, leaks locality |
| Aumann–Shapley path allocation | registered refinement; conservative, split- and order-invariant at the same scope | branch-crossing case analysis unaudited; same incentive gap as above |
| source-group settlement (one wallet per source-group) | coherent but presupposes the actor/wallet layer | Gate 2 is paused; out of scope |

**Decision (frozen):** no scientifically defensible allocation is ready, so
the first O14 execution keeps **one selected outgoing action per source per
micro-step** in every EBU-bearing arm, and **no aggregate settling arm is
registered**. The study is not made larger by force. Instead, a
**settlement-free diagnostic** is registered: for every arm-A tick, record
`Delta e_group(q_acc_vec)` and the naive independent per-edge sum; their
difference is the measured double-count (expected `naive ≥ group` on the
credit side by Prop 10.2 — a violation fires F9). Worlds are additionally
designed so that in the restricted arms **no two simultaneous actions ever
share a cell** (exactly one configured source per world, distinct
destinations), so per-action exact quotes are trivially conservative there
and O3 contamination cannot enter the primary comparisons.

## 3. Capability-matched policy arms

| Arm | Selection rule | EBU |
|---|---|---|
| **A** — full multi-edge P1C | all raw out-edge requests, proportional σ-scaling by the aggregate robust budget (released `p1c_step` on the full world); bounded service | none (capability-**superset** benchmark; never the alignment comparator) |
| **B** — restricted matched non-EBU | one action per source per micro-step from the shared menu; released loss-aware force rule (largest `f_e`, tie larger `q_acc`, then lower edge index); no EBU input, no global score, no rollout | none (**primary comparator**) |
| **C** — B + observational quote | **identical selection to B**; executed action quoted and settled observationally; full candidate-menu schedules recorded | observational only; physics must be byte-identical to B |
| **D** — restricted exact-total-quote greedy | the §2.A heuristic on the same menu; rests when no strictly positive exact quote exists | evaluation variable |
| **S** — restricted local service priority (**registered**, not silent) | same menu; score `= η_e · q_acc · 1[declared demand rate of destination > 0]`, ties lower edge index then lower menu index | none |

Arm **E** (aggregate source-group quote) is **not registered for
execution** (§2.C). Arm S is registered because it cleanly separates
quote-*specific* service loss (D vs S) from restriction-*generic* loss
shared with B; its declared limitation — it ignores destination stock
buffers — is recorded, and it reads only the menu plus the adjacent
destination's declared demand rate.

**Capability-matching proofs from the plan (not from behavior):**

- B, C, D and S consume the **same registered menu function** (fractions ×
  raw flux, capped by the same authoritative budget), the same conflict
  rule, and the same per-world timestep — plan sections `quantity_menu`,
  `request_shaping`, `timestep`; asserted **per tick** by the future
  harness (any violation fires F2/F12).
- B and D differ **only** in the ranking heuristic (force vs exact total
  quote) — both consume identical candidate tuples.
- C cannot alter physics: its selection is B's selection by definition;
  quotes are computed after the action set is fixed (event order:
  permission → selection → quote → settle), and F1 fires on any deviation.
- A vs B measures exactly the one-action restriction: same world, same
  budget law, same bounded service; A's only extra freedom is retaining all
  accepted flows.
- B vs D measures quote-driven choice under matched capability; a
  capacity-caused service reduction can never be attributed to the quote
  because capacity is identical by construction.

**Executed = selected (request shaping, registered).** Gate 1D's harness
executed the full flux of the selected edge regardless of the ranked
fraction (the released `p1c_step` regenerates requests internally). O14
requires the selected quantity to be the executed quantity, so the
restricted arms present `p1c_step` with an active world whose single edge
carries mobility `M_sel = frac · M_e`; the released allocator then
generates `frac · J_e` itself and applies its own authoritative budget.
`p1c_v29.py` is not modified; the identity
`q_acc(executed) = min(frac·J_e, Q_max) = menu q_acc` is asserted per tick.

## 5. Timestep, boundary and service discipline

- Bounded service semantics of Gate 1D **verbatim** (registered 10-step
  order; `service ≤ available`, `service ≤ demand`; `unmet = demand −
  service` exactly; non-negativity corrections explicit; exact ledger
  closure `Σx' − Σx = dt·Σu − loss − Σservice + Σcorrections` with named
  losses/corrections; no clipping that creates phantom stock).
- Non-negative physical states; domain failures first-class.
- **One shared certified timestep for all five arms at each paired world**;
  conservative (r_dt = 0.5) and near-certificate (r_dt = 0.9) registered
  per world (§4 table, full precision in the plan); `r_dt ≤ 1` in every
  confirmatory run; the harness recomputes every certificate and fails
  closed on mismatch; post-hoc timestep change forbidden.
- Reserve diagnostics use the **Gate 1D-A corrected scale-aware tolerance**
